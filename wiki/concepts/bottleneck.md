# ボトルネック

## 現在の統合見解

武田さんが 2026-06-11 の ChatGPT 対話で確立した理解。

- **「全体の流れを制限している部分」**。工程・プロセス(流れがあるもの)の文脈で使う言葉。
- 苦手なもの全部がボトルネックではない。**成果・速度・完成度を一番強く制限しているものだけ**がボトルネック。
- 武田さん自身が組み立てた言い換えの階段:
  「一番足を引っ張っている部分」→「全体の流れを制限している部分」→「全体を詰まらせている原因」→「ボトルネック」
- [[issue-driven|イシュー]] との関係: **ボトルネック = 詰まりそのもの / イシュー = その詰まりについて答えるべき問い**。ボトルネックを見つけることはイシューを立てる前段階。

## 絵の工程への適用

(出典は ChatGPT の例示。武田さんの実工程での見極めはまだ行われていない)

- 工程: 企画 → ラフ → 線画 → 塗り → 仕上げ → 投稿
- 毎回どこで止まるか・どこが全体の完成数や質を決めているかを見る。塗りが苦手でも、実際に
  完成を阻んでいるのがラフの迷いなら、ボトルネックはラフ。
- 「クロッキー・解剖学は基礎だからやる」は一般論への追従であり、ボトルネックの見極めではない
  ([[llm-log-issue-hajimeyo]])。

## LLM運用への短い適用例

- 2026-07-09 の運用失敗では、「廉価モデルだから駄目」がボトルネックではなかった。
  本当の詰まりは、`配布済み` / `実機反映済み` / `運用開始可能` を分けないまま終端判定していたこと。
- もう1つの詰まりは、会話・wiki・配布物・実機・helper のどれを正本として読むかが固定されていなかったこと。
- 詳しい再発防止の正本は [[llm-cheap-model-execution-workflow]]。
