# Eagleレビュー表示改善とビュー専用プラグイン案

## 現在の結論

武田さんの現在の目的は、AI に創作成果物を作らせることではなく、Eagle を見返して自分の考えを整理しやすくすること。
そのため、改善の主軸は「AI が勝手に分析する」ではなく、「保存画像を見返すときに、作者・反応数・投稿本文・保存先・保存日時がすぐ読める」ことに置く。

実データ確認では、X 由来保存の Eagle 注釈にはすでに 作者、いいね、リポスト、返信、引用、表示、投稿本文、保存情報、投稿 URL、画像 URL、技術メモが入っている。
ただし通常の Eagle メモ欄では長く、保存先や日時が下に流れるため、視認性が弱い。

## 注釈形式の方針

今後の保存分は、Eagle メモ欄の先頭を次の二層に分けるのがよい。

- `【見る用】`: 武田さんが Eagle 画面で読むための短い表示。
- `【LLM用】`: Codex / Claude などの LLM が後から正確に読むためのキー付き情報。

`【見る用】` は、作者、主要反応数、投稿本文、保存先の末尾フォルダ名、保存対象、JST 表示の保存日時、保存理由を短く並べる。
`【LLM用】` は、`source`、`item_kind`、`author_id`、`post_id`、`post_url`、`captured_at`、`target`、`folder_path`、`image_url`、`metrics.*`、`post_text`、`save_reason` をキー付きで残す。

これにより、人間はメモ欄の上だけ読めば概要が分かり、LLM は下のキー付き情報から機械的に取り出せる。

## 今回実装した範囲

`tools/x-eagle-save-extension/eagle-save.js` と `tools/x-eagle-video-helper/server.js` の注釈生成を v0.5.14 として変更した。

対象は今後保存される画像・動画。既存 Eagle 項目の注釈は書き換えていない。

自動試験では、画像保存側と動画補助側の注釈が `【見る用】` → `【LLM用】` → `## 技術メモ` の順になることを確認した。
未署名 `.xpi` も v0.5.14 として生成済み。

## ビュー専用ウィンドウ案

ビュー専用は、Eagle 本体の表示状態を無理に操作するより、Window Plugin（クリックすると別画面を開く形式）で別画面を作るのが現実的。
Eagle 公式の Plugin API は、Window Plugin と Inspector（右側詳細欄に追加情報を表示する形式）を提供しており、ユーザー環境の Eagle 4.0.0 でも Web API V2 と通常 API が使える状態だった。

最初に作るなら、ビュー専用ウィンドウは「保存画像を横断して見返す机」にする。

- 左: 最近保存した X 由来画像の一覧。サムネイル、作者、いいね、表示、保存先を1行で見る。
- 上: 絞り込み。最近保存、いいね多い順、保存先フォルダ、作者、動画のみ、画像のみ、投稿本文あり。
- 中央: 選択中の画像を大きめに表示。
- 右: 注釈を読む用に整形。作者、反応数、本文、保存先、保存日時、投稿 URL を表示。
- 下: 操作。Eagle で開く、X を開く、同じ作者だけ表示、同じ保存先だけ表示、LLM へ渡す Markdown をコピー。

この画面の価値は、創作案を AI に出させることではなく、武田さんが「今どれが気になるか」を自分で選びやすくすること。
よって初期版では、AI 分析ボタンよりも、絞り込み・並べ替え・比較・コピーを優先する。

## 使用感のイメージ

1. Eagle のプラグインから `Xレビュー` を開く。
2. 最初は「最近保存」が新しい順で並ぶ。
3. 気になる保存先、たとえば `04_エスキース_カップル_01` を押すと、そのフォルダの X 由来保存だけになる。
4. 画像をクリックすると、右側に読みやすい注釈が出る。
5. 「同じ作者」を押すと、その作者の保存画像だけに切り替わる。
6. 何枚か選んで「LLM用コピー」を押すと、投稿 URL、作者、反応数、保存先、本文、Eagle item ID を Markdown としてクリップボードに入れる。

この流れなら、Eagle は画像現物を見る場所、ビュー専用ウィンドウは横断レビューの場所、LLM はユーザーが選んだ材料だけを壁打ちする場所になる。

## 優先順位

1. まずは今後保存分の注釈を読みやすくする。これは v0.5.14 で実装済み、自動試験済み、実機未確認。
2. 次に、既存 Eagle 項目の注釈を 5〜10 件だけパイロット変換するか判断する。全件書き換えはしない。
3. その後に、ビュー専用ウィンドウの最小版を作る。最小版は「最近保存一覧、保存先/作者/動画画像フィルタ、選択画像詳細、Markdown コピー」に絞る。
4. Inspector は、単体画像を選んだときの読みやすさには向くが、横断レビューには弱い。したがって最初の本命は Window Plugin。

## 未確認・注意

- v0.5.14 の新注釈は、コード上の自動試験と `.xpi` 生成までは確認済み。Eagle 画面上の見え方はまだ実機未確認。
- 既存 Eagle 項目の注釈を書き換える場合は、必ず小さなパイロットから始める。
- ビュー専用ウィンドウは新機能であり、作る前に完成条件と非対象を確認する必要がある。
- Eagle の右側 Inspector は、選択中の1枚を読む用途には合うが、最近保存や作者別を一覧する用途には Window Plugin の方が合う。
