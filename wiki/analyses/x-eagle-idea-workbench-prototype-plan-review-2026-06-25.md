# Xアイデア作業台プロトタイプ計画レビュー

## レビュー結論

`Xアイデア作業台` プロトタイプ計画は、武田さんの現在の目的におおむね合っている。

目的は、AI に創作成果物を作らせることではなく、X 由来の保存事実を Eagle 内で見返し、武田さん自身が組み合わせて「題材・文脈・周期性・見せ場・準備行動」を言語化しやすくすること。この点で、計画の `事実プール`、`組み合わせボード`、`仮説メモ` の 3 列構成は妥当である。

ただし、初回プロトタイプとしては絞り込み項目がやや多い。最初の完成条件は「事実カードを見て、数枚を束ね、5項目メモを書き、LLM用Markdownをコピーできる」までに絞る方が安全。

## 観点1: 3つの要望の意図を汲み取っているか

ここでの3つの要望は、会話経緯から次のように解釈する。

1. X から抽出した事実を材料にする。
2. AI ではなく武田さん自身が組み合わせてアイデアを作る。
3. Eagle の使用感を改善し、考えを整理しやすくする。

この解釈なら、計画はおおむね合っている。

`FactCard` は作者・本文・反応数・保存先・保存日時を扱うため、X由来の事実を材料化できる。`IdeaBundle` は複数カードを束ねるため、ユーザーが組み合わせる行為を中心に置いている。`MarkdownExport` は、AI に最初から結論を出させるのではなく、ユーザーが選んだ束だけを壁打ちへ渡す形になっている。

特に、右側の `仮説メモ` に「題材」「文脈」「周期性」「見せ場」「準備行動」を置く方針は、[[issue-framework-review-for-x-eagle-project-2026-06-23]] の成功条件と合っている。

## 観点2: 目的に対して不用意に膨張していないか

大枠では膨張していない。読み取り専用、既存Eagle項目を書き換えない、AI生成なし、タグ付けなし、自動分類なし、Wikiへの書き戻しなし、という非対象の切り方は適切である。

膨張気味なのは、初回から入れる絞り込みの数である。`最近保存`、`いいね順`、`表示順`、`保存先フォルダ`、`作者`、`画像/動画` は便利だが、最初の実機検証では多い。

初回の最小版は、次の4つでよい。

1. X由来候補の事実カード一覧。
2. カードをクリックして束に追加・削除。
3. 束ごとに5項目メモを書く。
4. LLM用Markdownをコピーする。

並べ替えや絞り込みは、実際にカード数が多くて困ったら追加する方が、目的から逸れにくい。

## 観点3: 実装に対して計画は妥当か

実装方針は妥当である。

Eagle Web API V2（同じMac上からEagle情報を読む入口）は現環境で応答しており、Eagle 4.0.0 / build 20260401 も確認済み。既存の X 保存拡張と動画補助処理は別ディレクトリ・別役割であり、新規 `tools/eagle-x-idea-workbench/` として分離するなら干渉は小さい。

注意点は3つある。

1. サムネイルは API 応答に直接含まれないため、注釈内の `image_url` 優先、無いものはプレースホルダー表示が現実的。
2. X由来判定を `x-` 検索だけにすると漏れや混入が出る可能性があるため、`url`、注釈、名前の複数条件で「候補」として拾うのがよい。
3. `localStorage` はプロトタイプ用の仮保存であり、長期保存先としては扱わない。消えて困る段階になったら、JSON書き出しやWiki書き戻しを別判断にする。

## 使用感の要点

### 1. Eagleを「保存場所」から「考える机」にする

保存されたX画像を眺めるだけでなく、反応数・作者・投稿文・保存先を同じ画面で読めるようにする。

### 2. 左で事実を見る

左列は材料棚。カードには画像、作者、投稿本文、いいね、表示数、保存先、保存日時が並ぶ。

### 3. 中央で組み合わせる

気になったカードを中央へ送る。ここでは、1枚の画像ではなく、複数の事実をひとまとまりの束として扱う。

### 4. 右で創作方向に変換する

右列では「題材」「文脈」「周期性」「見せ場」「準備行動」を書く。これにより、保存事実が「何を描くか」「いつ準備するか」「何を見せるか」に変わる。

### 5. AIには束だけ渡す

最後に `LLM用コピー` で、選んだ束だけを Markdown としてコピーする。AI は最初から答えを出す役ではなく、武田さんが選んだ材料への壁打ち相手になる。

## 現時点の判断

この計画は、プロトタイプとして進めてよい。ただし、初回は「3列UI」「カード束ね」「5項目メモ」「LLM用コピー」までを完成条件にし、絞り込み・並べ替え・長期保存は後回しにする。
