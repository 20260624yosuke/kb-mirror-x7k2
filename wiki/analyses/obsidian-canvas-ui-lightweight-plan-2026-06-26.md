# Obsidian Canvas のUI軽量化(描画/メモリ軸)— 調査と非破壊プラン

> 出典: `llm-uploads/20260626-105500-Obsidian-Canvas-UI軽量化-経緯と非破壊プラン-BrainBaseで誤実施分のKB3移送.md`
> (別セッションの調査を KB3 へ移送した引き継ぎ書)。
> この調査・計測は**別セッションが実施**したもので、KB3 では未再検証。下では
> **計測事実 / 提案 / 未検証の但し書き**を分けて記す。**プラン自体はまだ未実行**で、
> 着手には武田さんの方式決定と(raw/ を触るため)再承認が要る。

## この分析の位置づけ

- これは「重い参照 Canvas を開いたときの UI のカクつき」を軽くするための**原因調査と提案**。
- **決まっていること**: 原因の所在(下記の計測)と、非破壊で軽くする方針の候補。
- **決まっていないこと**: 方式(B/A)・軽量版の目標解像度・パイロット対象(下「未決定」)。

## 相談の軸(確定)

- 武田さんの論点は **(a) Canvas を開いたときの UI のカクつき = 描画/メモリの軸**。
  ディスク容量や同期の話**ではない**。
- 対象 Canvas: `raw/_MY_ART/2026_06/2026_06_02_アイドルxアスナx立ち絵_01/2026_05_30_アスナxアイドル衣装.canvas`。
  ※この Canvas は [[canvas-reference-tools]] の切り取り比率修正(2026-06-26)でも触れている同一ファイル。

## 実測した原因(計測事実 / 別セッション計測・KB3未再検証)

- ノード **485**(file 299 / text 181 / group 5)、エッジ **514**。
- Canvas 本体は 163KB と小さい。参照画像のディスク合計は約200MB。しかし
  **Obsidian(内部は Chromium)が展開するビットマップ合計は約3.3GB**(= 幅×高さ×4バイト)。
  **これがカクつきの主因**。表示の大小ではなく、画像の実ピクセル数が RAM/描画を食う。
- 画像が **表示の約5.1倍**に肥大: Canvas 表示の長辺 中央値 ~399px に対し、
  実画像の長辺 中央値 ~1920px(最大4096px)。
- 解像度バンド: 3500px↑ 27枚=1085MB / 2500–3499px 29枚=677MB /
  1500–2499px 132枚=1265MB / 800–1499px 87枚=285MB / 800px未満 18枚=25MB。
- 動画(mp4)ノード5本(各0.7–2.4MB・表示130–225pxと小)。同一ファイルの重複参照26件(299→ユニーク273)。
- ※参照画像が大きい遠因: 作画文化として大解像度で描き縮小する方針([[large-canvas-7000px]])があり、
  素材も大きいまま Canvas に載りやすい。

## 重要な訂正と教訓

- 調査の途中で「Vault全体80GB・動画78GB(ディスク使用量)がボトルネック」と飛躍したが、これは**誤り**。
  ディスクに置いてあるだけのファイルは CPU/RAM を消費せず、UI のカクつきとは**別軸**。外付けSSDも35%使用で圧迫なし。
- 教訓は harness memory `stay-on-asked-axis` に記録(`no-reactive-fixes` / `feedback-prefer-lean-interpretation` と同系)。
  要点: 性能・UI相談ではまず軸を確定し(①描画/メモリ ②ディスク容量 ③同期/ネット)、名指しされた軸に留まる。
  偶然見つけた巨大ファイル等を、作用機序を示せないまま「原因」に格上げしない。スコープを勝手に広げない。

## 非破壊ワークフローの要件(武田さん指定)

1. 非破壊で画像を縮小(原本を失わない)。
2. Obsidian 内で原寸表示に戻せる。
3. 外部へコピペするときは原寸で取れる。

## 設計案(提案 / 未実行)

### 方式B(推奨・追加のみ・リスク無し)

- 原本も元 Canvas も無改変。`_attachments_light/`(縮小コピー・同名)と、画像パスを書き換えた
  双子 `〇〇__light.canvas` を**足すだけ**。
- 切替 = 軽量 `__light` タブ / 原寸の元 Canvas タブ を**開き分ける**(バニラ機能のみ)。
- 外部原寸 = 原寸 Canvas か `_attachments`(原本)から取れば必ず原寸。
- 代償: Canvas が2枚 → レイアウト編集時はスクリプトで `__light` を再生成して同期(元 Canvas を正)。
  リファレンス board は編集頻度が低く実用上の問題は小さい。

### 方式A(1枚のまま切替・要検証)

- `_attachments` を symlink 化し、原寸/軽量を張り替える。1枚のまま切替できるが、
  (1) Obsidian が symlink を辿るか着手前に1枚で要検証、(2) 切替時に Canvas タブ再読込が必要(瞬時ではない)。
- ※KB3 既存の symlink 運用の前例 = harness memory `clipstudio-backup-external-symlink`(外付け+symlink)。

## 正直な但し書き(未検証 / 限界)

- Obsidian に「表示解像度トグル」の**ネイティブ機能は無い**(PureRef のそれは無い)。
  入っている3プラグイン(brat / local-rest-api / canvas-reference-tools)にも無く、プラグインのオン/オフでは軽くならない。
- ③外部原寸の確実な経路は**ファイルから取る**こと。Canvas ノードの Cmd+C が原寸ラスタを
  クリップボードに載せる保証はない(未検証・恐らく不可)。
- **完全サクサクにはならない**: 485ノード+514エッジの DOM 描画コストは残る(Electron の下限)。
  残れば Canvas 分割が二の矢。

## 効果見積り

- 展開3.3GB → 目標長辺1280px で約 **0.7〜1.0GB(1/3〜1/5)**(提案ベースの見積り)。

## パイロット実装(2026-06-28 実施)

- **方式**: B（追加のみ・非破壊）。
- **目標長辺**: 1280px。
- **スコープ**: パイロット対象 Canvas 配下の `_attachments/` だけ縮小。別フォルダ(`2026_05/_attachments/` 等)の画像は元パスのまま。
- **生成スクリプト**: `tools/canvas_light_gen.py`（新規作成）。
  - `--canvas <path>` `--max-edge 1280` `--pilot-prefix <prefix>` `--dry-run` 対応。
  - 画像を LANCZOS で縮小し `_attachments_light/` へ配置。Canvas JSON のパスを書き換えた `__light.canvas` を生成。
- **プラグイン拡張**: canvas-reference-tools v0.5.3。
  - `image-clipboard.ts` に `resolveOriginalPath()` を追加。`_attachments_light/` パスを検出して `_attachments/`（原寸）に差し替えてからクリップボードに書き込む。
  - テスト 4 件追加（素通り / 変換 / 二重パス / fallback）、全通過。
- **生成結果**: 対象198枚（縮小127 + 原寸コピー71）。119.9MB → 55.2MB（54%削減）。
  ビットマップ展開量の削減率はこれより大きい（長辺1920px→1280pxで面積比は約44%）。
- **実機確認(2026-06-28)**: 武田さんにより確認済み。軽量版で体感の違いあり（PureRef ほどではないが改善）。原寸コピーも動作確認済み。
- canvas-reference-tools v0.5.5: コマンドパレット（Cmd+P）と右クリックメニュー（コンテキストメニュー）から「このCanvasの軽量版を生成」を実行可能に。Python スクリプト不要、プラグイン内で完結。

## light版正本同期の実装(2026-06-28 v0.5.6)

- **運用方針**: 重くなった Canvas は `__light.canvas` を作り、以後は light版を作業正本にする。元 `.canvas` は light版から生成される原寸ミラーとして扱う。
- **新コマンド**: `このlight Canvasを原寸同期して軽量化`。
  - light版に混ざった `_attachments/` 原寸画像を `_attachments_light/` へ長辺1280pxで縮小し、light版の参照を軽量画像へ差し替える。
  - light版の配置・メモ・グループ・エッジ・クロップ・回転・反転を正として、元 `.canvas` を `_attachments/` 参照の原寸ミラーへ更新する。
  - 上書き前に `.before-light-sync-<timestamp>.canvas` バックアップを同フォルダに作る。
- **初回移行**: 既存 light ペアで、light側だけの追加がなく元Canvasの方が新しい場合に限り、元Canvas側だけの追加や既存ノード差分を light版へ取り込む。`アイドルアスナ衣装` は読み取り検査でこの条件に該当（元Canvas側 15ノード/16エッジ追加、light側だけの追加なし）。
- **検査**: `light Canvas同期状態を検査` で `raw/_MY_ART` 配下の `__light.canvas` ペアを走査し、差分数を開発者コンソールへ一覧出力する。
- **検証状態**: 実装済み・自動試験済み。実Canvasに対する同期コマンド実行と Obsidian 実機確認は未実施（武田さん検証待ち）。

## 使い方

1. Obsidian で重い Canvas を開く。
2. コマンドパレット（Cmd+P）→「このCanvasの軽量版を生成」を実行。
3. 処理が終わると同じフォルダに `〇〇__light.canvas` と `_attachments_light/` が作られる。
4. `__light.canvas` を開けば軽い版。画像をコピーすると原寸が貼れる。
5. 以後は `__light.canvas` を作業正本として資料追加・配置・メモを行う。
6. 作業の区切りで「このlight Canvasを原寸同期して軽量化」を実行すると、light版は軽量表示に揃い、元 `.canvas` は原寸ミラーとして更新される。
