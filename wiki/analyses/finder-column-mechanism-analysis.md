# Finder カラム構造解析(Miller Columns 完全化のための事前調査)

[[obsidian-miller-columns]] を「見る専用」から「Finder 相当」へ育てる前に、
武田さんの指示(2026-08-26「予想で作るんじゃなくて、finder をスワップしろ。できないなら限りなく
構造を解析しろ」)により実施した事前解析。実装はこの判定のあとで行う。

## 要約

- **真のスワップ(Finder 部品の流用)は不可能。ただし「脆くはあるが技術的には可能」な
  ネイティブ埋め込み路線も存在する**。両方とも非推奨と判定し、JS 実装で Finder 仕様を
  移植するのが正攻法(Path Finder など先行例も全部この路線)
- **psd のサムネイル生成は実測で成功**(macOS 標準 `qlmanage`)。**clip は QuickLook
  プロバイダが無くタイムアウト(実測)** → サムネ対象は画像・動画・psd、clip は除外が現実解
- 現プラグイン(v0.2.1)は**シングルクリックでファイルを開く**が、**Finder カラムは
  シングルクリックでは開かず選択だけ**(ダブルクリックで開く)。ここが操作感の根本的な違いの1つ

## 調査 1: 真のスワップ可否の判定

| 方式 | 判定 | 根拠 |
|---|---|---|
| Finder のカラム部品をそのまま流用 | **不可能** | Finder は非公開アプリで、カラムビューを外部から組み込む API は存在しない |
| Apple 純正の列ブラウザ部品(NSBrowser)を Electron へ埋め込み | **可能だが脆い・非推奨** | Electron 公式が AppKit ネイティブアドオンを文書化(developer.apple.com NSBrowser / electronjs.org チュートリアル実在確認済み)。ただし既存ウィンドウへの NSView 埋め込みは子ウィンドウ重ね合わせ等のハックが要り、Obsidian 更新で壊れるリスク・ネイティブビルド/署名の負担・純 JS プラグインという配布形態からの逸脱がある |
| AppleScript で Finder 実窓を連動 | **非推奨** | 埋め込みではなく別窓になる。多窓環境での位置制御が破綻しやすい |
| **JS 実装で Finder 仕様を移植** | **推奨** | Path Finder(シェアウェア)や OSS クローンが全てこの路線。Obsidian プラグイン API の範囲で実装可能 |

NSBrowser の仕様は移植時の仕様参照として有用: 列ごとの幅(`setWidth(_:ofColumn:)`)と
その永続化(`columnsAutosaveName`)、ドラッグ&ドロップ(`DropOperation`、validateDrop)、
ダブルクリックアクション(doubleAction)、インライン編集(editItem)、キーボードタイプ選択
(allowsTypeSelect)を公式が提供しており、「列ブラウザにあるべき機能群」の網羅チェックリスト
として使える。

## 調査 2: Finder カラムの挙動仕様(移植仕様草案)

出典の区分: 〔知識〕=一般知識・Apple HIG 由来(未実測) / 〔実測〕=本日確認。

| 操作 | Finder カラムの挙動 | 出典 |
|---|---|---|
| シングルクリック(フォルダ) | 選択+右隣に子の列を展開。より深い列は破棄 | 〔知識〕現プラグインと同一 |
| シングルクリック(ファイル) | **選択のみ。開かない**。プレビュー列の中身が更新される | 〔知識〕**現プラグインはここが違う(開く)** |
| ダブルクリック(ファイル) | 既定アプリで開く(md 等の対応形式は Finder でも既定アプリ) | 〔知識〕 |
| ダブルクリック(フォルダ) | シングルと同じ(階層移動のみ) | 〔知識・未実測〕 |
| リネーム | Return キーまたは右クリックメニューでインライン編集。Cmd+O / Cmd+↓ で開く | 〔知識〕 |
| クイックルック | Space キー。プレビュー列の右端にサムネ+メタデータ | 〔知識〕 |
| 削除 | Cmd+Delete でゴミ箱。右クリックメニューにも有り | 〔知識〕 |
| ドラッグ&ドロップ | 列間・フォルダ間で移動。フォルダ上に 1 秒ほど重ねると自動展開(spring loading)。移動先のハイライト表示 | 〔知識〕 |
| 列幅 | 境界ドラッグ。**列ごとに独立した幅**で、設定は永続化される(NSBrowser にも columnsAutosaveName あり) | 〔知識〕 |
| スクロール | 各列が独立した縦スクロール+全体横スクロール。深掘りすると右端へ自動追従 | 〔知識〕現プラグインと同一方向 |
| キーボード | ↑↓=列内移動、←→=階層移動、タイプ選択(名前入力でジャンプ) | 〔知識〕 |
| ソート | 名前順が基本。フォルダをまとめるかは表示オプション依存 | 〔知識・未実測〕 |

**移植時に武田さんへ確認したい分岐点**: 現プラグインの「シングルクリック=開く」を
Finder 流の「シングル=選択/ダブル=開く」に寄せるか。(寄せると Obsidian ノートを
1 クリックで開けなくなる代わりに、誤爆開封が消える)

## 調査 3: 先行クローンの採用方式

- **Path Finder**(cocoatech、シェアウェア): Miller column view を搭載する代表的サード
  パーティ(Wikipedia「Miller columns」記載を確認)。クローズドソース
- **SpanFinder**(LumiBearStudio、GitHub): Finder 風 Miller Columns を謳う OSS。
  ネイティブ(Swift)実装。4 表示モード持ち
- GitHub topic `miller-columns`: Web/Electron 向け JS 実装が複数(インタラクション参考)
- **ネイティブ部品を他アプリへ埋め込んだ先行例は確認できなかった** → 調査 1 の判定を裏付け

## 調査 4: psd/clip サムネイル生成の実測テスト

macOS 標準の `qlmanage -t`(QuickLook 経由で縮小画像 PNG を作る CLI)を実在ファイルで実施。

| 形式 | 結果 | 証跡 |
|---|---|---|
| **psd** | **成功**。512px PNG(約 50KB)が即時(25 秒待機以内)に生成された | `/var/folders/mx/.../qltest/c02_講座教材.psd.png`(2026-08-26 実測) |
| **clip**(クリスタ) | **失敗**。120 秒以上応答が返らず出力ゼロ。QuickLook プロバイダがこの環境に無い(~/Library/QuickLook・/Library/QuickLook とも空を確認) | 2026-08-26 実測 |
| jpg/png/webp/mp4 | アプリ内(`<img>`/`<video>`)でプレビュー可能。qlmanage 不要 | 知識 |

**判定**: プレビュー列のサムネ対象は **jpg/png/webp/mp4(アプリ内描画)+ psd(qlmanage、
初回生成をディスクキャッシュ)** まで。clip はサムネなし(汎用アイコン)で妥協するか、
将来クリスタ連携として別途検討。

## 結論(実装方式の判定)

1. **JS 実装で Finder 仕様を移植する**(真のスワップ・ネイティブ埋め込みは非推奨)
2. 移植仕様は「調査 2」の表を正本とし、〔未実測〕項目は実装後に武田さんの実機比較で確定する
3. プレビュー列は psd まで。clip は対象外
4. 現仕様との分岐点(シングルクリック挙動)はユーザー判断を経てから実装計画に入れる
5. 実装開始時に quality-gate.json を置き、完成報告の前に `complete` ゲートを通す
   (原作=Finder がある再現・操作感が自動試験不能なため高リスク区分)

## 不確実・要確認

- 〔知識〕印の Finder 挙動は本日未実測。特にダブルクリック(フォルダ)・ソート規則は
  実装後の実機比較でズレが出る可能性
- clip の QuickLook プロバイダが「CLIP STUDIO 社が配布していないのか」「この環境で
  未導入なのか」は未切り分け(サムネ対象外判定には影響しない)
- `adapter.rename` 等の Obsidian API が非対応拡張子(psd 等)に対して期待どおり働くかは
  実装時の最初の検証項目(現プラグインのコード読解では未使用のため)
