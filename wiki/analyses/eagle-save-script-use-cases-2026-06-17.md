# Eagle保存スクリプトの追加用途候補

## 問い

X 画像などを Eagle へ保存するスクリプトは、保存時点のいいね数・リポスト数を残す以外に、
どんな使い道がありそうか。

## 前提

- 既存の意図は、Eagle へ画像を保存した時点で、X ポストの反応数を画像情報と一緒に残すこと。
- Canvas 連携では、「この画像を何の参考として使ったか」という武田さんの使用意図が高価値データだと整理済み。
- Eagle 書き戻しでは、人間タグ・AI タグ・LLM 管理タグを混ぜないことが重要。

## すぐ価値が出る用途

1. **保存時点の出典スナップショット**
   - 投稿 URL、作者 ID、保存日時、いいね数、リポスト数、引用数、表示数を注釈へ残す。
   - 後から「なぜ保存したのか」「保存時点でどれくらい伸びていたのか」を復元できる。

2. **保存理由の一言メモ**
   - 保存直後に「髪」「肌」「構図」「流行」「顔」「資料」など、短い理由だけ入力できるようにする。
   - これは Canvas の使用意図データと同じ系統で、AI 分類より信頼度が高い。
   - 入力負担が増えるため、最初は任意入力か、選択肢式に留めるのがよい。

3. **重複保存の検出**
   - 画像ハッシュ、X ポスト ID、Eagle item ID をローカルに残し、同じ画像や同じ投稿を二重保存しにくくする。
   - 同じポストの複数画像は、同じ反応数スナップショットを共有できる。

4. **あとで wiki / Canvas / PureRef に接続するための足場**
   - Eagle 注釈に、出典 URL と保存理由を機械的に読める形で残す。
   - 後日 Canvas ingest や Eagle 書き戻しで、「この画像はどの制作で、何の参考として使われたか」を接続しやすくなる。

## 中期的に便利な用途

1. **バズ研究用の収集ログ**
   - 5万いいね以上、10万いいね以上など、保存時の反応数で後から抽出できる。
   - 絵柄流行、構図、題材、心理的に重い絵などの分析に回しやすい。

2. **作者・キャラ・作品候補の補助メモ**
   - X の作者名や URL から作者候補を残す。
   - ただし「誰が描いたか」「何のキャラか」は外部事実なので、Eagle へ確定タグとして書く前に裏取りが必要。

3. **権利・利用条件の監査メモ**
   - 出典 URL、投稿者、保存日時、投稿本文を残す。
   - 将来「参考にしただけか」「再投稿不可か」「商用利用できないか」を確認しやすくする。

## 後回しがよい用途

- 画像を見て自動でフォルダ分類する。
- 作者・キャラ・作品を確定タグとして自動付与する。
- 保存時に毎回長い質問を出す。
- X の画面表示から数字を読み取る無料方式を本運用にする。

これらは便利そうだが、誤分類や UI 負担が大きい。まずは「保存時点の客観情報」と
「武田さんの短い保存意図」を残す方が、費用対効果と安全性が高い。

## 推奨する最小パイロット

1. Eagle 保存は今までどおり行う。
2. 保存直後に、スクリプトが X ポスト ID を取得する。
3. X API で公開反応数を1回取得する。
4. Eagle 注釈へ、保存日時・反応数・投稿 URL を追記する。
5. 任意で「保存理由」を1語だけ追加できるようにする。
6. 取得失敗時も画像保存は止めず、注釈へ `X反応数: 未取得` と残す。

## 判断

保存スクリプトの本質は、画像ファイルを保存することではなく、**保存した瞬間の文脈を失わない入口**に
すること。最初から分類や整理を自動化するより、後で AI と wiki が読める形で
出典・反応数・保存理由を残す方が、武田さんの既存ワークフローに合う。
