## major（主なもの）

- **B-2**: 承認済みの「壊れ#4（引き継ぎ7枚のどれが現行か分からない）」が、計画では「正確な記録ほど渡しにくい」に**すり替わっている**。完成条件から元の#4が外れた。
- **B-5**: helen `run-state.json` には**すでにトップレベル `blocked` が実在**し、その `state` 語彙は
  `blocked` / `unresolved` / `cause_identified_not_a_bone_issue` / `partially_fixed`。計画の語彙に
  `waiting-user` / `ready` が入らない。既存を書き換えられないので、**語彙の違う「止まっている理由」が
  1ファイルに2本**並ぶ。どちらが正かの規則が無い。
- **B-7**: 判定④に検証手順が無い。判定②も「生成が走ること」は測るが、**生成された中身が実データと
  合っているかを照合する手順が無い**。また節5の行書式が未定義なので④は機械判定できない。
- **B-9**: 禁止事項に機械で守れないものがある。8-6（7枚が特定されていないので遵守を確認できない）、
  8-7（**誤検知＝通るべきものが止まる現象を測る手順が無い**）、8-4（節1/3/4/5 の LLM 記述が
  更新されているかを測る判定が1つも無く、中核が心がけに残っている＝自己矛盾）。
- **B-10**: `state_files` は配列なのに `synced_from_mtime` はスカラー1個。**複数ファイルのずれを
  表現できず判定⑤が成立しない**。「7節構成」と言いながら固定見出しは8つ。
  `common.updated_at` を参照する判定が無く、同じ意味の時刻が1ファイルに2つ入る。
  実測では**内部時刻と mtime が既にずれている**（ふたなり: 内部 `2026-08-27T03:10:00`（TZ無し）／
  mtime Aug 26 22:45。抽出: 内部 `2026-08-26T22:45:00+09:00`／mtime Aug 26 22:11）。
- **B-11**: KB 規約の必須手続き（`index.md` 更新・`log.md` 追記・Inbox 申告）が実装手順に無い。
  また frontmatter に7欄を新設することは CLAUDE.md 上**構造決定＝要承認**にあたるが、計画はそこに
  触れていない。

## 追加すべきリスク（レビュー側の指摘）

1. **JSON 全体の書き戻しによる形式変化（major）**: `json.load` → `json.dump` はキー順・インデント・
   非 ASCII エスケープ・改行を変える。helen は日本語が大量にあり `ensure_ascii=True` なら**サイズが激増**。
   検証5（キーと値の一致）ではこれを検知できない。既存の grep 前提スクリプトが壊れうる。
2. **同時編集による喪失（major）**: 複数セッション並行運用が既にある。読み込み→全体書き戻しは
   ロック無しでは後勝ちで消える。
3. **外付けボリューム未マウント時の挙動（major）**: `stat` 失敗時に判定⑤が通すのか止めるのかが未定義。
   通せば形骸化、止めれば全作業不能。
4. **フックのグローバル適用による巻き添え（major）**: `~/.claude/settings.json` 登録は全セッションに載る。
   誤検知の影響が KB 外へ及ぶ（現に `tools/inbox.py` が止まっている）。
5. **バックアップの置き場（minor）**: `.bak` を `work_roots` 内に置くと判定⑤の対象になる。
6. **判定①の走査範囲が未定義（minor）**: `wiki/builds/` だけか KB 全体か、`.bak` を含むか。
