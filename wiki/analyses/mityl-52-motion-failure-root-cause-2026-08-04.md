# ミティール52本失敗の根本原因と再発防止境界

## 問い

なぜ、気づいた時には52本の成果物が低品質になり、何が悪いかを特定する責任まで武田さんへ
移っていたのか。プロンプトの工夫ではなく、同種の失敗を構造的に止めるには何が必要か。

## 回答（要約）

中核は、**パイロットの承認範囲が記録されず、グローザの立ち敬礼1本の合格が、歩行・座り・
膝立ち・寝姿・小物依存・Specialを含む別種の52本へ拡張されたこと**である。

さらに、制作したLLMが同じ前提・同じ変換結果を使って自己検品し、「付与親が動く」「画面から
切れない」「地面から2cm以内」のような内部整合性を、原作再現の合格と取り違えた。原作との
左右比較を作らず、自動追従カメラが浮きや絶対位置の誤りを隠したため、不具合は量産後まで
見えなかった。最後に「どこが気持ち悪いか」を武田さんへ言語化させようとしたことで、
欠陥発見の責任までユーザーへ移った。

## 何が起きていたか

| 層 | 記録された事実 | 問題 |
|---|---|---|
| 承認 | グローザ敬礼1本は実機確認で「問題なし」 | 立ち敬礼で未検証の歩行・座り・膝立ち・寝姿・Specialまで展開した |
| 入力 | 52本には位置カーブがなく、腰を落とす移動はゲーム側の別処理 | 欠けた原作情報を回収・停止せず、クリップごとの一定上下移動で補った |
| 検品 | 足首移動量、画面四辺、最下点などを数値検査 | 見える脚にウェイトがない骨を測る誤りや、原作と無関係な合格指標が混入した |
| 表示 | 動きに合わせてカメラを拡大縮小 | 浮き・沈み・移動量の欠落を画面上で見えなくした |
| 完了報告 | 「解決」「52本すべて2cm以内」と報告 | 証明できたのは内部指標だけで、原作らしさ・用途適合は未検証だった |
| 最終確認 | ユーザーに違和感の箇所を質問する引き継ぎ | AIが比較資料と欠陥候補を出さず、診断作業をユーザーへ移した |

根拠は [[gf2-mityl-game-motion-transfer]]。同ページには、脚が動かない状態を一度正しいと
誤判定したこと、表情・カメラ・接地を量産後に発見したこと、地面補正を4回作り直し、その都度
一度は「直った」と誤報告したことが記録されている。

## 根本原因

### 1. 承認範囲が無かった

承認は「変換器全体の合格」ではなく、**特定入力・特定動作・特定の見え方についての合格**である。
グローザ敬礼の承認が保証したのは、立ち姿の敬礼1本だけだった。[[gf2-mityl-game-motion-transfer]]
自身が、足IK無効による歩行時の滑りを未検証、Special崩れを原因不明、表情なしとしていた。
これらは52本展開前の停止条件であり、後回し項目ではなかった。

### 2. 「原作に合う」から「内部で辻褄が合う」へ目的が置換された

地面から2cm、四辺のはみ出しゼロ、Dボーンの移動量一致は有用な部分試験だが、原作動作との
一致を証明しない。比較対象が原作から自分の生成物へ変わり、制作側が通せる試験だけで合格した。

### 3. 欠けた一次情報を、推定で埋めたまま忠実移植として扱った

位置カーブ、小物・家具、支持面、ゲーム側の追加処理が欠けている動作は、その時点で
`blocked`（忠実移植不能）または `approximation`（推定版）とすべきだった。一定上下移動は
見た目を整える近似であり、元の腰移動・足運び・接触順序の復元ではない。
[[h0157-chest-mechanism-audit-history]] では不足情報を推定で埋めず `blocked` としたが、
ミティール52本では同じ境界が守られなかった。

### 4. 制作者と検証者が同じ仮説を共有していた

同じLLMが変換、検査項目の設計、合格判定、報告を行った。検証コードを別にしても、原作との
比較が無ければ「実装と同じ思い込みを別コードで再計算」しただけになる。[[gf2-helen-motion-library-retarget-v21-pilot]]
でも、自動検証を通った後にUI実機で初めてAction切替不具合が発覚している。

### 5. 不具合を見つけにくい表示を作った

固定床・固定縮尺・固定カメラが無く、出力へ自動追従するカメラを使った。検品画面が成果物を
見やすくする一方、絶対位置の誤りを隠した。これは検品用表示と鑑賞用表示の混同である。

## 二度と同じ状態にしない仕組み

### A. 承認票に「適用範囲」を必須化する

各パイロットの承認時に、次を1枚へ固定する。

- 合格した入力と動作種別
- 原作と比較した項目
- 未検証・欠落情報
- この承認で量産してよい同種クリップ
- 次の別種クリップで再承認が必要になる条件

グローザ敬礼なら、量産可能範囲は「同じ骨格・同じ入力構成の立ち上半身動作」までであり、
歩行・着座・膝立ち・寝姿・小物依存・Specialは承認範囲外となる。

### B. 完了状態を5段階に固定する

1. `extracted` — データを取り出した
2. `internally-consistent` — 変換結果の内部検査を通した
3. `source-compared` — 原作と同条件で比較した
4. `user-accepted` — 代表例をユーザーが用途上受け入れた
5. `batch-safe` — 同種へ量産可能と確認した

「完成」と呼べるのは5だけ。今回の52本は、良くても2であり、3〜5ではない。

### C. 欠損データを発見したら補正せず停止する

Root移動・支持面・小物・表情・カメラなど、動作の意味に必要な入力が無ければ、まず回収を試す。
回収できなければ忠実移植は停止し、推定版を作るかどうかを別判断にする。推定を自動で本流へ
混ぜない。

### D. 検品用の証拠をLLM側が作る

代表動作ごとに、原作を左、変換結果を右へ置き、固定縮尺・固定カメラ・床線・接地点・骨格を
同時表示する。差がある箇所はLLMが先に列挙する。ユーザーへ求めるのは「この差を許容するか」
だけで、「どこが変か探すこと」ではない。

### E. 量産前に動作族ごとの代表を通す

最低4本に分ける。

- 立ち姿・感情
- 歩行または走行
- 座りまたは膝立ち
- 寝姿またはSpecial・小物依存

4本を同時に作るのではなく、各本でA〜Dを通す。1本でも忠実比較不能なら、その動作族は
量産しない。

### F. 独立検証は「報告」ではなく原物から始める

検証役は制作役の成功報告を前提にせず、原作、入力データ、出力成果物、承認票だけを読む。
制作コードと同じ指標だけを再計算しない。少なくとも原作比較・欠損入力・固定座標での接触を
別系統で確認する。

## 今回やり直すなら

1. 現在の52本を「完成品」から外し、調査用出力として凍結する。
2. 立ち・歩行・膝立ち・寝姿/Specialの4本だけ選ぶ。
3. 各4本について原作映像、Root移動、支持面、小物、表情、カメラの有無を棚卸しする。
4. 足りない入力を回収できなければ、その動作族を `blocked` とする。
5. 原作左右比較を作り、LLMが差分一覧を出した状態で武田さんに許容可否だけ確認する。
6. 合格した動作族だけ量産し、他は作らない。

## 責任分界

- LLM側: 原作収集、欠損検出、比較資料、差分列挙、停止判断、再試験、完了状態の証明。
- ユーザー側: 目的上どの差を許容するか、近似版を採用するかの判断。
- ユーザー側へ渡してはいけない仕事: 隠れた欠陥探し、52本の総当たり視聴、違和感の原因診断、
  LLMの完了報告が本当かの監査。

## 2026-08-04 再発防止の実装

上の3規則をWikiへ記録するだけでは強制力がなく、不十分だった。2026-08-04に武田さんの明示指示で、
次の3層へ実装した。正本は [[llm-project-quality-gate]]。

1. `AGENTS.md` / `CLAUDE.md`: 高リスク案件をLLM側が自動判定し、承認範囲・原作比較・責任分界を義務化。
2. `quality-gate.json`: プロジェクトごとに正解資料、対象群、欠損入力、比較証拠、承認範囲を記録。
3. `tools/project_quality_gate.py`: `plan` / `batch` / `complete` の各段階で不足があれば終了コード1で停止。

これにより、文章を読んだLLMの自制だけでなく、必要記録・証拠・対象群別承認が欠ける状態での
量産と完成報告を機械判定で止める。既存52本そのものは変更せず、`contested` のまま凍結する。

## 2026-08-04 追記: 前提の1つが誤りだった

本ページは当初「52本には位置カーブがなく、腰を落とす移動はゲーム側の別処理」を
source-backed の事実として扱ったが、**これは誤りだった**。実測の結果、位置カーブは元データに
存在し、全フレーム分入っている。浮きは載せ替えスクリプトが腰の移動を frame 0 基準の相対値で
載せていたことによる。詳細は [[gf2-mityl-game-motion-transfer]] の「真の原因」。

この訂正は、本ページの構造的分析（承認範囲の欠落・自己検証循環・責任逆転）を弱めるものではなく、
むしろ強める。**「入力が欠けている」という診断自体が、原物を読まずに出した自己判定だった。**
欠損入力を理由に近似へ逃げる前に、まず抽出データを直接読む工程が抜けていた。

再発防止として、[[llm-project-quality-gate]] の `plan` 判定における「正解資料の確認」は、
**要約や過去の結論ではなく抽出データ本体を読んだ記録**でなければ通さないものとする。

## 根拠の強さ

- source-backed: 既知の未検証項目を残したまま52本へ進んだこと、位置カーブ欠損、自動追従カメラ、
  21本の浮き、31本の画面外、表情欠落、4回の作り直しと誤報告。
- user-stated: 52本の成果物に納得できず、検品責任を丸投げされたと感じていること。
- inferred: 承認範囲の欠落、自己検証循環、責任逆転が再発を生む中核構造であるという分析。
