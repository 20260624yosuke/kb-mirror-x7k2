# ChatGPT引き継ぎ: X→Eagle保存観測の再検討

## ChatGPTへの依頼

以下の経緯を読んで、目的に対して次にどう進めるべきかをレビューしてほしい。

特に見てほしい観点:

- 今回の `X→Eagle保存観測` は、目的に対して問いの立て方が正しかったか。
- なぜ初回成果物が「有益な発見がない」と感じられたのか。
- 単に対象を狭める以外に、どんな分析設計があり得るか。
- こちらが何を曖昧にしたまま進めてしまったのか。
- 次にやるなら、どんな質問でユーザーの考えを詰めるべきか。

求めている回答は、一般的なSNS分析論ではなく、今回の目的・失敗・ユーザーの違和感に即した具体的な提案。

## 前提

ユーザーはイラスト制作をしており、X(Twitter)で伸びる絵の傾向を、自分の制作判断に返したいと考えている。

ただし、目的は「Xで流行っているものを眺める」だけではない。より正確には、以下のような流れを作りたい。

- Xで見かけた画像をEagle(画像資料管理アプリ)に保存する。
- 保存時点の投稿URL、作者、いいね数、リポスト数、表示数、保存先フォルダなどを残す。
- 後から、保存した画像群を見返して「なぜ伸びているのか」「なぜ自分は保存したのか」を読む。
- それを次の自作イラストの題材、構図、肌感、衣装、投稿文、見せ場作りへ返す。

ユーザーにとってEagleは「画像そのものの置き場」、Wikiは「意味・解釈・判断材料の置き場」という役割。

## セッション消失と復元

このプロジェクトは途中でCodexのセッションが消えた。

その後、Codex側のメモリとWiki内の記録から、消えた会話の流れをある程度復元した。復元された文脈としては、単なるEagle整理ではなく、`Xで伸びる絵の観測 → 保存画像の意味づけ → 制作判断への接続` が主目的だった。

ユーザーはその復元文脈を前提に、最初に出された計画をレビューしてほしいと依頼した。

## 最初に問題になった方針

候補として出ていた方針に「直近30〜50件のEagle保存画像を読む」があった。

ユーザーはこの方針について、

- どうするつもりなのか。
- 質問形式で詰めてほしい。
- 曖昧な部分は質問してほしい。

と依頼した。

その後、レビュー観点として以下が示された。

- ユーザーのブレストのような考えを、体系的に整理できているか。
- ユーザーの考えを汲み取れているか。
- `X→Eagle保存観測` までの流れは妥当か。
- 計画はプロトタイプ(試作品として小さく試す版)として、今後の拡張性・発展性があるか。
- 計画がユーザーの考えを汲み取った形になっているか。

## レビューで出した修正点

Codex側のレビューでは、初期方針に対して以下の修正が必要だと判断した。

- 対象は「X全体」ではなく「ユーザーがEagleに保存したX由来画像」に限定するべき。
- 保存画像には、純粋なイラストだけでなく、漫画、実写、ネタ、コスプレ、資料が混ざるため、混線しやすい。
- 反応数が高い画像だけを見ると、ユーザーが保存した理由を見落とす。
- 低反応でも、資料価値が高いものは制作上は重要になり得る。
- 「保存理由と数字が噛み合うもの」と「保存理由と数字がズレるもの」を分ける必要がある。
- 初回から自動タグ付けやEagleへの書き戻しはしない方がよい。
- まずは小さなパイロットとして、読み取り専用で観測する方がよい。

その後、ユーザーから追加条件として「前提として1万いいね以上の画像に絞って観測する」も加えるよう指示があった。

## 実行した初回パイロット

CodexはEagleのローカルAPI(Mac内で動くEagleの読み取り口)を使い、読み取り専用で観測した。

実行条件:

- 取得日: 2026-06-23
- 対象: Eagleに保存されたX由来画像
- 抽出方法: `x-...` 形式、または注釈に投稿URLを持つEagle項目
- 条件: 1万いいね以上
- 数え方: 画像単位ではなく投稿単位。同じ投稿の複数画像は1件にまとめる。
- 上限: 直近30投稿
- Eagleへの書き込み: なし。タグ追加、注釈変更、フォルダ変更はしない。

取得結果:

| 項目 | 結果 |
| --- | --- |
| X由来候補 | 500件 |
| 1万いいね以上の投稿単位グループ | 208件 |
| 観測対象 | 直近30投稿 |
| 2.5万いいね以上 | 24/30 |
| 5万いいね以上 | 7/30 |
| いいね最小値 | 13,699 |
| いいね中央値 | 34,380 |
| いいね最大値 | 98,605 |
| 画像未表示 | 2件 |

保存先フォルダの分布では、`04_snsバズり_01` が9件、`むっちり感_01` が3件、`水着_01` が3件、`05_服装_コスプレ_01` が3件などだった。

## 初回成果物で出した観測

Codexは観測を以下のようにまとめた。

- 水着・夏・肌質感の保存が複数あり、ユーザーの「夏の水着イラストが増えているのでは」という感覚と合う。
- 5万いいね以上で、表示数に対するいいね比率も高いものは、画像として刺さっている可能性がある。
- 表示数は大きいが、いいね/表示比率が低いものは、絵として刺さるというよりSNSバズ型かもしれない。
- リポスト数/いいね数は、多くが5〜12%台で、ユーザーの「リポストはいいねの十分の一くらいになりがち」という感覚におおむね近い。
- 1万いいね以上だけでは広すぎるため、制作向けには「2.5万以上 + 画像として反応率が高い + 保存先が肌/水着/構図/キャラ系」を見る方がよい。
- `04_snsバズり_01` は制作資料ではなく、X上で広がる形式の観測として分ける方がよい。

## ユーザーの反応

ユーザーは成果物を確認し、次のように評価した。

> なんていうんだろう有益な発見とかはなかったな。

Codex側も同意し、初回成果物は「読んだ記録」にはなっているが、「次の絵に効く発見」には届いていないと返答した。

その理由としてCodexは以下を挙げた。

- `1万いいね以上` が広すぎて、絵・漫画・実写・ネタ・コスプレ・SNSバズが混ざった。
- 「なぜユーザーが保存したか」が薄く、数字と画像を並べただけになった。
- 比較対象がないため、「何が違うから伸びたのか」まで行けなかった。
- 30件を横に眺めたため、1枚ごとの構図・顔・肌・衣装・投稿文の深掘りが浅かった。
- 制作判断、つまり「次に自分が何を描くか」への接続が弱かった。

そのうえでCodexは「次は水着・肌質感・夏だけに絞る」「5万いいね以上の水着絵5件 vs 1万台の水着絵5件を比較する」などを提案した。

しかし、ユーザーはこれにも次のように反応した。

> なんかピンとこないな。

つまり、単に「対象を水着に絞る」「比較数を減らす」という修正も、ユーザーの違和感には十分答えていない。

## 現時点の問題意識

このプロジェクトの問題は、たぶん「データ量」や「抽出条件」だけではない。

より根本には、以下の問いが残っている。

- ユーザーは、Xの数字から何を知りたいのか。
- ユーザーは、保存画像を見て何が分かれば「有益」と感じるのか。
- `保存した理由` と `伸びた理由` は同じものとして扱ってよいのか。
- 制作に返すなら、今描く絵・次に描く絵・伸ばしたいジャンルを先に決めるべきではないか。
- 画像群を横断して傾向を見るより、ユーザーが「気になった1枚」を深掘りする方がよいのではないか。
- そもそも、1万いいね以上というしきい値(対象に含める最低ライン)は、発見を作る条件として機能しているのか。

## ChatGPTに考えてほしいこと

次のどれか、または別案を含めてレビューしてほしい。

### 案A: 保存意図を主役にする

数字ではなく、まず「ユーザーはなぜこれを保存したのか」を分類する。

例:

- 体型・肌・質感を見たい。
- 構図を見たい。
- 投稿文やネタの伸び方を見たい。
- 衣装資料として使いたい。
- 自分の絵に近い/遠いので気になった。
- なぜ伸びたのか分からないから保存した。

この場合、いいね数は主役ではなく、保存意図ごとの補助情報になる。

### 案B: 制作中の1枚に接続する

先に「次に描く絵」を決め、その絵に関係あるEagle保存画像だけを見る。

例:

- アスナ水着絵を描くなら、水着・肌・腰上構図・顔まわりだけを見る。
- メイド衣装絵を描くなら、胸元、腰まわり、ガーター風ストラップ、白黒コントラストだけを見る。

この場合、Xで伸びたかどうかより、「この絵のどの判断に使うか」が主役になる。

### 案C: 伸びた理由ではなく、違和感を読む

ユーザーが保存した画像の中で、

- なぜこれがこんなに伸びたのか分からない。
- 数字の割に絵としては弱く見える。
- 逆に、良いのに数字が低く見える。
- 自分には刺さるが、Xではそこまで伸びていない。

というズレを中心に扱う。

この場合、「傾向」よりも「自分の感覚と数字のズレ」を観測する。

### 案D: 比較単位を投稿ではなく判断項目にする

投稿単位の表ではなく、制作判断の項目ごとに見る。

例:

- 顔の強さ
- 目線
- 肌の面積
- 画面内の余白
- 体のシルエット
- 衣装の情報量
- 投稿文の強さ
- キャラや作品の知名度

この場合、30投稿を表にするのではなく、判断項目ごとに「良い例/弱い例/保留例」を置く。

### 案E: まず質問で詰める

次の実行に入る前に、ユーザーへ質問して目的を絞る。

聞くべき質問の例:

- 「有益な発見」とは、次の絵の題材が決まることか、構図が決まることか、投稿戦略が決まることか。
- Eagle保存画像のうち、いちばん知りたいのは「なぜ伸びたか」か「なぜ自分が保存したか」か。
- 今回はX全体の傾向を見たいのか、自分の保存癖を見たいのか、自分の次作に使える資料を選びたいのか。
- 反応数が高い画像と、自分が描きたい画像がズレたとき、どちらを優先したいか。
- 1回の観測後に、どんな出力があれば「これは使える」と感じるか。

## ChatGPTへの出力希望

以下の形で返答してほしい。

1. 今回の初回パイロットが有益に感じられなかった根本原因。
2. `X→Eagle保存観測` という流れ自体を続ける価値があるか。
3. 続けるなら、次にやる最小実験。
4. やめる/後回しにするなら、代わりに何を優先すべきか。
5. ユーザーへ確認すべき質問。質問は抽象論ではなく、回答によって実際の作業内容が変わるものにする。

避けてほしい回答:

- 「サンプル数を増やしましょう」だけ。
- 「水着に絞りましょう」だけ。
- 「タグ付けを自動化しましょう」だけ。
- 一般的なSNS運用論だけ。
- ユーザーの保存意図を無視して、Xの反応数だけで分析すること。

## 現時点の暫定結論

初回パイロットで分かったことは、「EagleからX保存画像と反応数を読み出す技術的な経路は使える」という点まで。

一方で、「そのデータをどう読めば制作判断に効くか」はまだ設計できていない。

したがって、次に必要なのは自動化や大規模化ではなく、分析の問いを小さく、かつユーザーの制作判断に直結する形へ作り直すことだと考えられる。
