# LLM Wiki の粒度判断は query 精度を基準にする

## 問い

LLM Wiki の concept / source / analysis の粒度を、人間が見やすい単位ではなく、将来の `/llm-wiki query` で体系的・根拠付きに回答できる単位へどう寄せるか。

## 回答(要約)

粒度判断の最優先基準は、ユーザーが読みやすいかではなく、AI が後で query 時に **根拠・講師差分・状態・不確実性・再利用可能な技法** を高精度に取り出せるかである。

そのため、source ページは元資料の要約を保持し、concept ページは「別の質問でも再利用される判断軸・技法・用語」に切り出す。単発作例の細部は source に残し、複数章・複数講師比較に使えるものを concept 化する。

## 詳細

- 人間向けの読みやすいまとめより、AI が誤帰属・混同・旧説採用を避けられる構造を優先する。
- 講師固有の発言は、一般法則に昇格せず、`sources:` と本文で講師帰属を明記する。
- 同じ語でも講師間で射程が異なる場合は、統合ページで「矛盾」ではなく「射程差」として扱う。
- concept は短くてもよい。query 時に検索・比較・横串化できることを優先する。
- 作例固有のディテールは source ページに残す。再利用可能な型だけ concept 化する。

## 残った問い / 検証したい仮説

- Coloso 講座群の concept 粒度は、講師ごとに「中核原則」「工程」「小技」の 3 層で整理すると query 精度が上がる可能性がある。
- 既存の chan 02 ghost concept 群も、この基準で全件または中核から順に解消する必要がある。
