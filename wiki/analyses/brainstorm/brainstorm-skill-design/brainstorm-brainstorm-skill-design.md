# brainstorm スキルの設計（2026-08-28）

このメモ自体が brainstorm スキルの最初の記録。仕様の正本は [[brainstorm-skill]]。

## 武田さんの考え

- hold スキルの挙動がおかしいので、新たなスキルを作りたい。LLM 共通で同じ使用感で使いたい。
  Claude 仕様だけに留めるのは禁止。wiki や使用環境と整合性を合わせないのも禁止。
- 今までプランモードで作業していたが、**プランモードはやり取りの記録ができない**ため、コンテキスト
  自動圧縮で文脈の粒度が下がる。そもそもプランモードで使う必要がないと思った。
- KB フォルダの中にファイルを作って考えのまとめをメモしていないと、圧縮で自分の考えが消え、
  **また方針を伝え直すループ**になる。
- 複雑なスキルは求めていない。
- 承認カードが機能すれば、**LLM の推論が返ってくるワンテンポ前で「そこは違う」「俺はこう思う」と
  指摘してブレストできる**。そういうスキルが欲しかった。
- スキル起動時点ですぐ実装を依頼するケースはないので、意図しない実装・編集はしないようにしたい。
- **LLM はすごく優秀な人材で、アイデアマンである自分の考えを、成果物につながるように導線を敷く。
  これが計画だという認識。** メモの内容は計画作成時も参照すること。
- スキルは Claude 用だけ作ればよい。Codex と Kimi には自分が個別に組ませるので、**指示書だけ提出**
  してほしい。スキルの概要が伝われば、その環境でどう実現するかはそいつに考えさせた方が解像度が高い。
- 情報を探す中で LLM が矛盾点を見つけることがあり、その場で直さないと後のハルシネーションにつながる
  ので臨機応変さは必要。**でもその編集承認を取られると認知負荷に耐えられず、プロジェクトの本筋が
  見えなくなる。** この境界を LLM が自律的に理解して仕事できるようにしたい。
- wiki は自分では見ないので、LLM 向けに整理されているならそれでよい。
- 懸念は、**メモがどこにも紐づけられず、実装エージェントが自分の意図を無視してハルシネーションを
  起こすこと**。それは禁止するので仕組み化してほしい。
- 紐づけは**文言ルールではなく監査スクリプトが条件**。ルールだとコンテキストが膨らむと忘れるから。
- 計画を .md ファイルとして書き起こすのは実装ではない（スキルを使ったら計画作成まででよい）。

## 決まったこと

- 名前は `/brainstorm`。hold は新スキルへ一本化して休止（ファイルは削除しない）。
- 編集の境界は1問テスト:「この編集で、武田さんが後で見る成果物の中身・見え方・使い勝手が変わるか」。
  変わらないなら黙って直す。変わるなら直さず聞く。
- 黙って直した分は都度報告せず、メモに溜めてカードに件数だけ添える。
- 監査は①圧縮後の再注入 ②未読ブロック ③ブレスト中の成果物封鎖 の3つ全部。有効範囲は全プロジェクト。
- 未読で実装しようとしたら**拒否**する。ただし武田さんが「解除」と言えばその会話だけ通せる。
- 再注入は毎ターン軽く＋圧縮時に厚く。
- 状態ファイルは持たない。封鎖はブレストした会話の最後まで残り、実装は別の会話で行う。
- 他 LLM 向けは指示書のみ提出（[[brainstorm-skill]] に同梱）。

## まだ決まってないこと

- 自動圧縮の直後に `SessionStart` が本当に発火するか（武田さんの実機確認待ち）。
- 実運用で誤検知（本来通したい書き込みが止まる）がどれくらい出るか。`guard.log` で数える。

## 捨てた案と理由

- **入口規約に「実装前にメモを読め」と1行足す案** → 武田さん却下。「ルールだと、コンテキストが
  膨らむと忘れる」。監査スクリプトに置き換えた。
- **`quality-gate.json` に brainstorm メモのパス欄を足す案** → 選ばれず。既存の動いている仕組みに
  手を入れる作業量に見合わないため。
- **状態ファイルで封鎖を切り替える案** → 不要になった。ブレストの会話では実装しない前提なので、
  封鎖が会話の最後まで残るのはむしろ好都合。
- **PostCompact フックで再注入する案** → 公式仕様上、出力が無視されるため不可能。

## 実装への申し送り

**完成条件**（2026-08-28 時点で達成済み）

- `/brainstorm` で起動し、承認が出るまで応答が承認カードで終わる
- 話した内容が `wiki/analyses/brainstorm-*.md` に毎ターン書き足される
- ブレスト中は成果物フォルダへの書き込みが機械的に止まる
- `ready` のメモを読まずに実装しようとしたら機械的に止まる
- 圧縮後もメモの内容が context に戻る

**絶対にやってはいけないこと**

- 監査スクリプトを「失敗したら止める」方向に倒すこと。必ず素通りに倒す。作業不能の事故を作らない。
- メモの `scope` を空のまま `ready` に上げること（無関係な全プロジェクトが止まる）。
- 武田さんの言葉を要約して薄めて `## 武田さんの考え` に書くこと。
- ブレストの会話の中で実装まで進めること。実装は別の会話で、メモを読ませてから。
- 「文言ルールを足す」で問題を解決したことにすること（武田さんが明確に却下した解き方）。
