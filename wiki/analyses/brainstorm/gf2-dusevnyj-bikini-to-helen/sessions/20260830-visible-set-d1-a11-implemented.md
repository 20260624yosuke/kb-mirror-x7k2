## D1 を何に差し替えたか

旧 D1a（版1つ）・D1b（派生1つ）・D1c（体/顔/髪が1つずつ）は**削除**した。3つとも既存台帳
（兄弟プロジェクトの G13）と食い違っており、そのまま使うと正しく絞った版まで落とすため。

新しい判定は **「台帳との一致」1本**。表示メッシュ（`.subN` は合算）が台帳の「出す」と一致するか。
過剰は2種類に分けて名前で出す（台帳で外すと決めたもの / そもそも台帳に載っていないもの）。

- 変異試験3種: (1) 台帳の「出す」を1件落とす (2) 台帳に無いものを1件足す
  (3) 胸の変種を2つ同時に出す。**3/3 検出。**
- 基準の最小構成には `.sub0` / `.sub1` を1件混ぜ、submesh の合算が効いていることも同時に見ている。

### 測っていないもの（検査の説明に明記済み）

見た目の正しさ・模様の貼り間違い・姿勢・材質。加えて **台帳の一覧そのものが正しいかは測れない**
（台帳が誤っていれば、誤ったまま合格する）。

## A11 が言えること・言えないこと

- 言えること: 成果物の検査それぞれが **根拠の台帳の実パスを持ち、そのファイルが実在する**こと。
  `deliverable_checks.py` の `EVIDENCE` を読んで確かめる。
- **言えないこと: そのファイルを読んだかどうか。** 機械では測れない。この限界は A11 の
  「見ていないもの」に書いた。
- A11 自身の検出力も内蔵の変異試験2種（パスを消した版 / 存在しないパスにした版）で確認しており、
  どちらかが素通りすると A11 は合格を名乗らない。
