## 設計案（2026-08-30・承認待ち）

説明用HTML: `wiki/_attachments/project-hub-index/20260830-handoff-mechanism-design.html`

- **1案件1枚の「現在位置ページ」を wiki に置く**（正本は wiki 側、と 2026-08-30 承認済み）。
- **ページ内を機械が書く区画と人が書く区画に割る。** 節2/6/7＝機械、節1/4/5＝人、節3＝両方。
  混ぜないので、片方が片方を消さない。
- **新ディレクトリ・新 type は作らない**（私の宣言）。`wiki/builds/` に置き、frontmatter に欄を足す。
  理由: 新 type / 新ディレクトリは承認の要る重い変更で、得られるのは分類の見た目だけ。
- 機械化する5条件: ①正本は1枚だけ（2枚目を止める）②節2/6/7 を自動生成（「引き継ぎ資料を作って」を不要にする）
  ③片付いた行は表から消えて別節へ移る（追記のみの構造を変える）④判断は専用節に集め古いものを失効
  ⑤記録と実データの時刻がずれたら書き込みを止める。①③⑤は brainstorm_guard の応用。

### 決めてほしい1点: run-state.json の欄名が案件ごとに違う（2026-08-30 実測）

| 案件 | 記録ファイル | 「いつ更新したか」の欄名 |
| --- | --- | --- |
| helen 原作再現 | 226KB | `last_updated` |
| ふたなり化 | 3.3KB | `updated_at` |
| キャラ抽出 | 49KB | `updated_at` |
| 水着化 | **無し** | — |

- **案1（私の推し）**: 全案件に共通の最小4欄（`updated_at` / `current_step` / `next_action` / `blocked`）を
  足す。既存の欄は1つも消さない。水着化には新規作成。
  失うもの: 仕組みを作る前に4案件のファイルを触る作業が入る（追加のみだが危険はゼロではない）。
- **案2**: 実データは触らず、生成側に案件ごとの読み取り対応表を持たせる。
