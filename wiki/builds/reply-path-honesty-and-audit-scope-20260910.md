# 返答パスの正直さ検査（D3）と、引き継ぎ到達性監査の対象範囲の修正

2026-09-10。武田さんの指摘で、機械監査の**意図と実装のズレ**を直した。

## 何がズレていたか（実測）

武田さんの言葉:

> この機械監査は、プロジェクトを進めるにあたり、ブリーフされた回答の内容の添付ファイルパスが
> そもそも憶測で生成されたものだった場合を防ぐためであって、Kbフォルダの状態報告機械監査として
> 作成した意図はありません。

用意されていたのは別物2つで、**欲しかった方が未実装**だった。

| | 欲しかったもの | 実際に止めていたもの |
|---|---|---|
| 何 | 返答に書いたパスが憶測でないか | KB メモとその入口群が次の担当者から辿れるか |
| どこ | `tools/deliverable_path_guard.py` の D3 | `~/.claude/skills/brainstorm/brainstorm_guard.py` の `guard-stop-handoff`（H1〜H7） |
| 状態 | **未実装**（説明文に「実在の確認は D3 として別途」と書いたまま作られていなかった） | 稼働中 |
| 対象の選び方 | — | **作業フォルダ**（`cwd` が scope 内なら発言と無関係に選ぶ） |

2026-09-10 の実測:

- 発言と無関係に **14 本**のメモが毎回対象になった（作業フォルダが KB だから、というだけの理由）。
- 出た不合格 **9 件は全て、その会話で一度も言及していない別案件**のファイル（実在しない
  `/Users/takedayousuke/.claude/plans/mellow-questing-elephant-*`）。
- 「引き継ぎらしさ」の語句一致に、`_index.md` のような**どの返答にも出うる一般名が 51 件**含まれていた。

ズレは監査の質ではなく**対象の選び方**。返答を見るべき検査が、フォルダを見る検査になっていた。

## 直したこと（3点）

### 1. D3 を実装した（`tools/deliverable_path_guard.py`）

返答本文に書いたパスだけを見る。KB メモは見ない。落とすのは次を全部満たす場合だけ。

1. 本文にパスとして書かれている
2. 実在しない
3. **この会話に一度も現れていない**（道具の入力・道具の結果・武田さんの発言のどれにも無い）
4. 「まだ無い」「これから作る」等の断り書きがその行に無い
5. 穴埋め記号を含まない

3 が要。実際に読み書きした・武田さんが書いた・道具が返した、のどれでもないパスは、
**私が頭の中で作った**もの以外にあり得ない。実在照合だけだと「消したファイルの報告」まで
落ちるが、この条件なら落ちない。判定に使う本文から **assistant の過去の本文は除外**する
（自分の憶測を自分で裏づけにしないため）。

**実装中に D3 自身の欠陥を実測で発見して直した。** 既存の `PATH_RE` は空白で切れるため、
この環境のパス（`/Volumes/SSD_M.2_Realtek RTL9210 NVME Media_/…`）が断片になり、
**実在するパスを「憶測」と誤判定した**。抽出を、武田さんへ渡す3書式
（Markdown リンクの行き先・バッククォート内・行そのものが絶対パス／箇条書きの先頭記号は外す）
に限定して解決した。散文中の裸のパスは拾えない（取りこぼす側＝素通りに倒す）。

### 2. 引き継ぎ到達性の Stop 発火を、返答で名指ししたメモだけに絞った

`audit_targets(cwd, spoken)` による cwd 起因の自動選択をやめ、
`handoff_targets_from_reply(spoken)` に差し替えた。`_index.md` のような一般名は
`<案件>/_index.md` かフルパスでのみ名指しとみなす。`entry_paths` はフルパスを丸ごと
言ったときだけ（裸のファイル名は一般名と衝突するため）。

同じ H1〜H7 は `_guard_ready_promotion`（メモを `ready` に上げる瞬間）で既に掛かっているので、
会話終了ごとに KB 全体を測り直す必要はない。

### 3. 自分が書き換えていないメモの不合格は、止めず記録だけにした

このターンで実際に更新したメモかを、**最後の人の発言の時刻とファイル更新時刻**で見分ける
（`touched_handoff` が 2026-09-09 に確立した手と同じ）。担当外メモの不合格は
`guard.log` へ `handoff NOTE not-mine memo=… fails=N` として残し、会話は止めない。
時刻が読めない会話記録では「自分の担当」に倒す（従来どおり止める側）。

## タイミングは変えていない（変える必要がなかった）

武田さんの問い:

> 監査のタイミングって本文推論確定、監査、再推論、結論って流れですよね？この流れがボトルネックなのかな。

流れの理解は正しく、Stop フックは仕組み上あとから当てるしかない（テキストを出す前に当てる
フックは無い）。ただし**ボトルネックは順番ではなく範囲**だった。再推論が起きたのは、
無関係な 9 件を読まされて担当外だと判断し直したため。範囲を返答の中身に絞れば、書くパスは
ほぼ全部その場で触ったものなので不合格がほぼ出ず、再推論のループ自体が起きない。

## 使わなかったもの・落とした情報

- **散文の中に裸で書いたパスの検査**。落とした理由: 空白を含むパスで誤検出が出るため。
  手元でどう変わるか: 憶測パスをリンクでも素のパスでもない形（文中に埋め込む形）で書いた場合、
  D3 は見逃す。武田さんが渡される形（押せるリンク＋素のパス）で書く限り取りこぼさない。
  戻せるか: `_d3_candidates` に抽出規則を足せば戻せる。ただし空白パスの誤検出対策が必要。
- **Stop で KB 全体の到達性を測ること**。落とした理由: 担当外の不合格で会話が止まるため。
  手元でどう変わるか: 会話終了ごとの KB 全体点検が無くなる。到達性はメモを `ready` に上げる
  瞬間に検査されるので、引き継ぎに使う状態の担保は残る。
  戻せるか: `handoff_targets_from_reply` を `audit_targets` に戻せば元に戻る。

## 機械化した指摘

- 「返答の添付パスが憶測かどうか」→ 再発しうる・機械判定できる → **D3 として実装**。
