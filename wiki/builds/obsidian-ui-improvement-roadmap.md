## ④ 動画ビュワー改善 — 完了

- **状態**: **完了(2026-07-04時点の④優先実行、2026-07-11 実機確認)**。Media Extended 導入済み、
  武田さんが実機で「いい感じ」「問題ない」「十分な使用感」と確認。コントロール改善・暗いグラデーション
  両方とも Media Extended 導入のみで解消(個別 CSS 対応は不要と確定)
- **意図**: Obsidian 内の動画再生を「今より改善」する。YouTube 完全再現は求めない。
  暗いグラデーション除去も含む。作業が重くなる案は不採用
- **対象範囲**: `_attachments/` 配下のローカル `.mp4` 再生が主。YouTube 等の外部動画は副次的
- **現状**: Obsidian 標準の `<video>` 埋め込みはコントロールが最小限(再生/一時停止/シーク程度)

### 既製プラグイン候補

| 候補 | 概要 | 導入の重さ | 確信度 |
|---|---|---|---|
| **Media Extended** (aidenlx) | ローカル動画+YouTube/Vimeo をピン留めプレイヤーで再生。グローバルホットキー、タイムスタンプリンク(`#t=`フラグメント)、ループ、自動再生。v4 は closed source | コミュニティプラグインからインストール。設定項目多めだが既定で使える | **高** — 15万DL超、アクティブ、ローカル再生対応を公式ドキュメント([mx.aidenlx.site](https://mx.aidenlx.site/docs/v4))で確認 |
| **VLC Bridge** | VLC Player との連携。Obsidian からVLCを制御し、タイムスタンプリンクやスナップショットをノートへ貼る | VLC 本体の別途インストールが必要。Obsidian 内完結ではない | **中** — 外部アプリ依存だが、コーデック問題(HEVC/ProRes)を VLC 側で吸収できる利点 |

### UX懸念

- Electron の HTML5 `<video>` 依存のため、画面録画由来の HEVC/ProRes 等は再生不可の恐れ。
  Media Extended も内部は同じ `<video>` なので、コーデック問題は解決しない可能性がある。
  VLC Bridge ならコーデック問題を外部プレイヤーで吸収できる
- **暗いグラデーション除去は Media Extended 導入で一緒に解決する見込みが高い(2次情報)**:
  Obsidian 標準の動画埋め込みは Chromium(Electron)ネイティブの `<video controls>` を使っており、
  ブラウザ標準仕様として下部コントロールバーに半透明の暗いオーバーレイがかかる実装になっている
  (一般に知られたChromium実装として補強、要実機確認)。Media Extended はこのネイティブコントロール
  をカスタムプレイヤーへ置き換えるため、導入だけで解消する可能性が高い。個別 CSS 対応
  (`video { filter: ... }` 等)は、導入後もまだ気になる場合の保険として後回しにする

### 経緯(2026-07-11)

1. Media Extended 導入は武田さんが手動で実施(前面GUI操作+第三者プラグイン有効化の判断は
   本人が行うのが安全という判断、下記「導入手順」の通り)
2. 導入後、武田さんが実機で再生を試用し「いい感じ」「問題ない」「十分な使用感」と報告
   (実装後の改善確認・完了)
3. コーデック(HEVC/ProRes)問題や暗いグラデーションの残存報告は無し。VLC Bridge・追加CSSは不要

### 導入手順(記録・武田さんが実施済み)

1. Obsidian アプリを開く
2. 画面左下の歯車アイコン(設定)をクリック
3. 設定画面の左側メニューから「コミュニティプラグイン」をクリック
4. 「閲覧」ボタンをクリック(プラグイン検索画面が開く)
5. 検索欄に「Media Extended」と入力
6. 検索結果の「Media Extended」(作者名: aidenlx)をクリック
7. 「インストール」ボタンをクリック
8. インストール後「有効化」ボタンをクリック(自動で有効化されない場合のみ)
9. 設定画面を閉じ、動画ファイルを1つ開いて再生を確認
   (例: `raw/_coloso/2026_05_31_ひづるめ/_attachments/15_04.mp4`)

- **担当モデル**: 設計(CSS スニペット含む)=高性能 / インストール手順書=Sonnet 5 可(本節が該当)
- **武田さんの作業**: プラグイン試用(5分)
- **撤退ライン**: Media Extended + VLC Bridge の両方が「今より改善」に届かなければ保留

### 追補(2026-08-22): YouTube風スキップ操作の要望

- 初回④の意図(**YouTube 完全再現は求めない**)は変わらない。対象はシーク/スキップ操作のみ
- 要望: 「動画に関する操作をyoutubeに近い操作感にして欲しい。スキップとか」(2026-08-22)
- 現状: Media Extended 導入済みで再生コントロール自体の不満は解消済みだが、シーク・スキップの
  操作感が YouTube と違うとの指摘

#### 調査結果(2026-08-22・main.js 解析。実機未確認)

- MX v4 プレイヤーには YouTube 風キーが**内蔵**: `J`/`←`=5秒戻る、`L`/`→`=5秒進む、
  `K`/`Space`=再生/一時停止、`↑`/`↓`=音量、`M`=ミュート、`F`=全画面、`I`=PiP、`C`=字幕
- **プレイヤーにフォーカスがある時のみ有効**(動画の画面を先にクリックする必要あり)
- 制約: シーク幅 5 秒は**固定**(設定項目なし)。Obsidian ホットキーへ割り当てられるシーク系
  コマンドは MX に存在しない。10秒ジャンプ等の改造は閉じたプラグイン(minify・クローズド)の
  内部イベント直叩きになり更新で壊れるため**不採用推奨**
- 武田さんの記憶では「矢印でスキップできなかった」。原因候補(未検証):
  ①動画面をクリックせずキーを押していた(フォーカス無し)
  ②ノート埋め込み(`![[…mp4]]`)の標準 video 要素で見ていた(内蔵キーは MX プレイヤー経由のみ)

#### 実機確認手順(武田さん・2026-08-22 以降)

1. 左サイドバーのファイル一覧から `.mp4` をクリック(MX プレイヤーで開く)
2. 動画の画面を1回クリック(フォーカスを与える)
3. `←` / `→`(5秒送り)、`Space`(停止/再生)、`↑`/`↓`(音量)を試す
4. 効かなければ、ノート埋め込み(`![[…mp4]]`)からの再生と比較(こちらでは効かない可能性)

#### 再開手順(問題が残った場合)

- 効かない → フォーカス問題か、開き方(埋め込み vs MXプレイヤー)かを切り分ける
- 「10秒ジャンプが必要」という結論なら、要件を確定してから重い改造案を改めて承認に出す
  (現時点では不採用推奨のまま)
- ②Miller Columns 自動フォーカスの実装は方針承認まで進んだが実装未了。
  再開時は .bak 退避→トグル追加→再読込の手順(本ログ 2026-08-22 参照)

- Google Tasks 側はサブタスク `④動画ビュワー追補：YouTube風のスキップ操作` を**開いたまま**
  (実機確認のトラッカー)。元文全文は同サブタスクの notes へ保存済み

## ② 親フォルダ視認性(Finder カラム表示) — 実質完了(妥協ラインで運用開始)

- **状態**: **実質完了**(2026-07-12)。キー起動ポップアップ(Quick Explorer の
  `Browse current folder`)は実機で「スクロールできない・親が見えない・調整が面倒」で不採用 →
  **常設カラムプラグインを自作**(Miller Columns)。v0.1.0 実機確認 → フィードバック反映の
  v0.2.0(幅ドラッグ調整・ツールチップ・右クリック削除)を実機確認し、武田さんが
  「妥協はできるライン」と判断・運用開始。既知の不満2点(削除反映の遅延、幅ドラッグが
  全列共通)は残存するが今回は追加対応しない。正本は [[obsidian-miller-columns]]。
  決定事項: 置き場所=左サイドバーのタブ(フォルダ操作はカラムだけで完結してよい)/
  自動追従なし=Finder 忠実再現(「現在のファイルの場所を表示」ボタン方式)
- **意図**: 大量フォルダでスクロール必須・色分けでは不十分な左サイドバーを改善し、
  今いるフォルダの親階層が一目で分かるようにしたい。Finder のカラム表示(Miller 列)が理想
- **対象範囲**: Obsidian 左サイドバーのファイルエクスプローラー
- **現状**: 標準はツリー式。深い階層は折り畳みの入れ子で、現在位置の親が見えにくい

### 方式の変遷(2026-07-12)

- **試したこと**: Quick Explorer のパンくずをステータスバーに表示 → 画面下だと Dock と操作が
  バッティング。CSS スニペットで画面上部へ移動 → 「視認性が悪い＋使用感も良くない」(武田さん)
- **武田さんの要望確定**: 「面倒だから Finder のカラムを再現して」
- **調査結論**: Finder カラムを**常設(列を出しっぱなし)**で再現する既製プラグインは Obsidian に
  存在しない(WebSearch 2回で確認)。自作は規模が大きい(=今回やらない)
- **採用方式**: Quick Explorer 内蔵コマンド `Browse current folder`(id: `browse-current`)/
  `Browse vault`(id: `browse-vault`)を**ホットキーに割り当て**、キー1つで Finder 風カスケード
  (フォルダ選択→右へ次階層)を開く。常時表示のパンくずは CSS スニペットで非表示にし、
  上帯の見にくさと下帯の Dock バッティングを両方解消
- **トレードオフ**: 「押したら出る」形で、Finder のように列を出しっぱなしにはできない。
  常設版が必要なら自作(重い)になるため今回は範囲外

### 既製プラグイン候補

| 候補 | 概要 | 導入の重さ | 確信度 |
|---|---|---|---|
| **Quick Explorer** (pjeby) | ステータスバーにブレッドクラム(パンくずリスト)を表示。クリックで上位フォルダのファイル一覧をポップアップ。キーボードでフォルダ間を高速移動 | コミュニティプラグインからインストール。軽量 | **高** — 実在確認済み。ブレッドクラム方式で「親フォルダ視認性」を別アプローチで解決。Finder カラム表示そのものではないが、親階層を常時表示する点で意図に近い |
| **Notebook Navigator** (johansan) | 左ペインを2ペイン(フォルダツリー＋ファイルリスト)に分割。ファイルプレビュー、タグブラウズ、ドラッグ&ドロップ対応 | コミュニティプラグインからインストール。標準エクスプローラーを置き換える | **高** — 15万DL超、アクティブ開発。2ペイン分割で階層が見やすくなるが、Miller 列ではない |

### UX懸念

- **Finder 風マルチカラム(Miller 列)を完全再現する既製プラグインは見つからなかった**。
  Web 検索で `Miller columns`・`column view`・`file browser` を組み合わせて調査したが、
  該当なし
- Quick Explorer のブレッドクラム方式は、Finder カラムとは操作感が異なるが、
  「親フォルダが一目で分かる」という意図は満たせる可能性がある
- 16GB/多窓環境で狭い左ペインにカラムを並べるのは窮屈。ブレッドクラム(上部の1行表示)の方が
  画面占有が小さく、普段使いの実現性は高い

### 次の一手(キー起動方式)

1. パンくず非表示スニペット `.obsidian/snippets/quick-explorer-top.css` を適用(実装済み。
   中身は `#quick-explorer { display: none }`。ファイル名は据え置きで武田さんの再切替不要)
2. `Browse current folder` にホットキーを割り当て(武田さんが設定操作)
3. キーを押して Finder カラムが開くか・使用感が面倒でないかを実機確認
4. 合わなければ撤退 → Notebook Navigator(2ペイン常設)を試す → それも不可なら②は保留

### 実装手順(武田さん向け・Mac・Obsidian アプリ内)

Quick Explorer は導入済み。以下は**ホットキー割り当て**の手順(1回だけ):

1. Obsidian の左下の歯車アイコン(設定)をクリック
2. 左メニューの「ホットキー」をクリック
3. 上部の検索欄に「Browse current folder」と入力
4. 「Quick Explorer: Browse current folder」の行の右側にある ⊕(プラスの)アイコンをクリック

7. 設定を閉じ、適当なファイルを開いた状態で割り当てたキーを押し、Finder 風カラムが開くか確認

- **担当モデル**: 手順案内=Sonnet 5 可(本節が該当)

## ① DB/タイムラインビュー

- **意図**: Notion 的なデータベースビュー(テーブル・タイムライン)を Obsidian で使いたい。
  UX 重視
- **対象範囲**: Obsidian Bases 機能(v1.10、2025年8月リリース)とその拡張プラグイン
- **現状**: Bases はテーブル/カード/リストビューを提供。タイムラインは native ではないが、
  コミュニティプラグインで追加可能になっている

### Bases の守備範囲(2026-07 時点の調査)

- **テーブル/カード/リスト**: Bases native。frontmatter プロパティを列として表示・編集・
  ソート・フィルタ。Notion のデータベースに近い操作感
- **タイムライン/ガント**: native ではない。v1.10 で「プラグインが新しいビュータイプを
  追加できる API」が開放され、コミュニティプラグインで対応

### 既製プラグイン候補(タイムライン系)

| 候補 | 概要 | 導入の重さ | 確信度 |
|---|---|---|---|
| **Timeline for Bases** (TfTHacker) | Bases にガント風タイムラインビューを追加。日/週/月/四半期/年表示、グループのドラッグ移動(frontmatter 自動更新)、today マーカー | **BRAT 経由でインストール**(公式コミュニティプラグインリストに未登録)。BRAT 未導入なら先にBRAT を入れる必要あり | **中〜高** — GitHub リポジトリ([TfTHacker/timeline-for-bases](https://github.com/TfTHacker/timeline-for-bases))で実在確認。フォーラム投稿(2026年3月)あり。BRAT 経由のため安定性は公式登録品より一段下がる |
| **Time & Line** (Beta) | Bases 用ガントチャート＋タイムラインビューのセット。紀元前・曖昧日付にも対応 | BRAT 経由(Beta) | **中** — フォーラム投稿([2026年3月](https://forum.obsidian.md/t/time-line-a-set-of-gantt-chart-timeline-views-for-bases-beta/112884))で存在確認。Beta 段階 |
| **Planner** (SawyerRensel) | カレンダー＋カンバン＋タイムライン＋タスクリストを統合。Bases native 連携 | コミュニティプラグインからインストール可能な見込み | **中** — GitHub([SawyerRensel/Planner](https://github.com/SawyerRensel/Planner))で実在確認。統合型のため機能が広い分、設定が多い可能性 |

### UX懸念

- **frontmatter プロパティ前提**: Bases のすべてのビューは frontmatter のプロパティを
  データソースにする。`raw/` の X クリップ・講座文字起こしはプロパティが不揃い(日付・タグ等が
  欠落)なので、DB ビューに載せるには**プロパティの追加整備が先に要る**
- **BRAT 依存**: タイムライン系プラグインの主要候補2つが公式未登録で BRAT 経由。
  BRAT 自体は広く使われているが、公式プラグインより更新追従の手間がある
- **未知度が高い**: Bases 自体が比較的新しく(2025年8月)、タイムライン拡張は 2026年3月頃から
  出始めたばかり。安定性・完成度は試用しないと判断できない

### 次の一手

1. まず Bases の native ビュー(テーブル/カード)を `wiki/` の整備済みページで試す(プロパティが
   揃っているため)。「Notion 的 DB ビュー」の感触を掴む
2. タイムラインが必要なら BRAT を導入し、Timeline for Bases を試す
3. `raw/` のファイルを Bases に載せるにはプロパティ整備が必要。その作業量を見てから判断

- **担当モデル**: Bases 活用設計=高性能 / BRAT・プラグインのインストール手順書=Sonnet 5 可
- **武田さんの作業**: Bases の試用(10分)、タイムラインプラグインの試用(5分)
- **撤退ライン**: Bases native のテーブル/カードが「Notion 的」に感じられなければ、
  タイムラインまで進まず保留。プロパティ整備のコストが見合わなければ保留
