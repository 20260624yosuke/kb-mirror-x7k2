# opencode 承認前書込の事前阻止の詳細計画

B2（承認前書込の阻止なし）と B3（親未読での実装阻止なし）を現行仕様で閉じる。
正本は `wiki/builds/brainstorm-skill.md`、思想は各サービス一単位・基盤別不具合不可、
目標は使用感一致ではなく実会話での機械的遮断である。

## 0. 前提と範囲

### 対象

- Phase 0: 共通足場の移設（別計画書の承認範囲。未承認のままなら本計画の Phase 1 より先に承認を取る）
- Phase 1: `tool.execute.before` での書込事前阻止の実装（運用基盤配下のみ）
- Phase 2: 実会話での阻止と通過の観測

### 対象外

- B4（再注入）、B5（終了阻止）、B1（照合器の目印変更）
- 正本側と別基盤側の既存監査の改修
- `permission.ask` 経路の追加（第二経路として温存し今回は使わない）
- 判定の中身の変更と材料の追加緩和

### 変更してよい場所

`.opencode/` 配下のみ。起動路の禁止に触れない。

## 1. 現状の実体（確認済み）

- 関所は承認カードのみ停止し、書込と殻実行は観測だけで素通りする
  （`tool.execute.before` の write/edit 分岐は追跡後に return する）。
- 例外送出で呼出しを止める方式は承認カードで実績がある。同じ方式が書込にも使える。
- 型定義に事前受信点・許可照会・受信時接点があり、終了接点は一覧に存在しない。
- 会話番号が不明な呼出しは止めない決まりがある（他会話への巻き添え防止）。
- 検査基盤の異常は通す決まりがある（機械自身の故障で仕事を止めない）。

## 2. 設計

### 2.1 判定の一元化

判定は共通層の純粋関数だけを使う。関所側に判定を複写しない。
共通層に `decide` 相当の入出力を足す（入力は親状態・カード状態・対象内外・メモ族か、
出力は阻止か通過か）。材料10件はそのまま通ること。

### 2.2 カード状態の保持

会話ごとに次を保持する。承認は会話と親と計画版に束ねる。

- 主回答と確認回答の値
- 対象の親メモの実パス
- 対象の計画版の SHA
- 部分回答・確認否定・空回答は未承認のままにする

回答の取得は `tool.execute.after` の question 結果を使う。
取得できない場合は疑似状態で補わず、未承認として扱う。

### 2.3 対象の内外判定

- 親メモ族への書込は常に通す（記録で行き詰まりを作らない）。
- 適用範囲外への書込は通す（この関所の所有外）。
- 適用範囲内の非メモ書込だけが阻止対象である。
- 経路に半角空白が入る前提で、空白で切る抽出は使わない。
  実在確認を伴う抽出にする（既知の誤検知の再発防止）。

### 2.4 殻実行の扱い

書込記号の近似判定のため、すり抜けと誤検知が残ることを明記する。
正本側にも同じ既知の穴がある。近似の範囲は試験で固定する。

## 3. 試験

### 3.1 共有材料（既存10件・変更なし）

未承認書込は阻止、承認済書込は通過、部分回答と確認否定は未承認、
旧承認の流用は阻止、不正遷移は拒否、正規再開は通過、親不整合は阻止、
基準 flow は通過。

### 3.2 関所レベルの合成試験（新規）

- 未承認の書込呼出しは阻止される
- 承認済の書込呼出しは通過する
- 部分回答後の書込は阻止される
- 確認否定後の書込は阻止される
- メモ族への書込は未承認でも通過する
- 範囲外への書込は未承認でも通過する
- 検査基盤の異常時は通す（fail-open）
- 会話番号不明時は止めない

### 3.3 実会話の観測（完成条件）

- 未承認書込が実際に止まること
- 承認済書込が実際に通ること
- 合成試験の合格を完成扱いにしない

## 4. 受入条件

- 実会話で阻止1件と通過1件が観測されること
- 既存自己試験（表示・支援機能・照合）が合格のままであること
- 変更が運用基盤配下に収まること
- 未確認を成功扱いにしないこと（再注入と終了は別扱い）

## 5. 危険と対策

| 危険 | 対策 |
|---|---|
| 追加部品の再読込に再起動が要る | 実機で先に確認し、要るなら再起動手順を踏む |
| 回答の観測が取れない | 疑似状態で補わず未承認に倒す |
| 誤検知で仕事が止まる | メモ族と範囲外は通し、基盤異常は通す |
| 呼出しごとの起動 cost | 計測し、悪化時は照会経路への切替を別途検討 |

## 6. 承認の区切り

本計画の承認対象は Phase 1 の実装と Phase 2 の観測である。
移設の承認は別計画の範囲であり、未承認なら先に取る。
B4 と B5 の着手は含まない。
