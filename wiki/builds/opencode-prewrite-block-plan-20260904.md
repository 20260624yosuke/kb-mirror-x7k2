# opencode 承認前書込の事前阻止の詳細計画（改訂版 r9）

F1（承認前書込の阻止なし）と F4（親未読での実装阻止なし）を現行仕様で閉じる。
B番号との対応は末尾の対応表に置き、本文の表記は F 番号に統一する。
正本は `wiki/builds/brainstorm-skill.md`、思想は各サービス一単位・基盤別不具合不可、
目標は使用感一致ではなく実会話での機械的遮断である。

r8 は再審査で NO_GO（致命的0件・重要12件・軽微4件）となり、
本改訂版で接点名の直書き・複写先の実名・探針の再現手順・
殻規則の確定・証拠書式の固定を行う。

## 0. 前提と範囲

### 対象

- Phase 0: 共通足場の複製と参照切替（正本は禁止域の原本のままとする。
  複写元は共通判定・材料・実行器の3件とし、複写先は運用基盤側の同名3件とする。
  目録は復帰置き場に `manifest-sha256.txt` として置く。
  作成は複写コマンド、照合は3件分のハッシュと目録の突合せとし、
  不一致時は Phase 1 と Phase 2 の着手を禁止して写し戻しを行う。
  所有者は実装会話とし、照合は Phase 1 と Phase 2 の開始前に行う。
  共通層の変更が必要になったら本計画を停止し別途承認を取る。
  実コマンドは Phase 0b の先頭に固定する）
- Phase 0b: 検証探針（下記6件。Phase 1 の着手条件）
- Phase 1: `tool.execute.before` での書込事前阻止と
  `tool.execute.after` での回答採取の実装（運用基盤配下のみ）
- Phase 2: 実会話での阻止と通過の観測

- 正本側と別基盤側の既存監査の改修
- 判定の中身の変更と材料の追加緩和

### 変更してよい場所

`.opencode/` 配下のみ。禁止条項は起動路2件の末尾節に特定する。

## 1. 探針結果と証拠（実測・2026-09-04）

- 探針1（回答の形状）: 暫定合格に格下げする。単問カードの記録であり、
  2 問束ねの実証になっていない。証拠は復帰置き場の生記録に保存済みである。
- 探針2（書込の阻止）: 暫定合格とする。仮書込は止まり仮ファイルは作られず、
  止まったのは当該呼出しだけで会話は続いた。証拠3点は保存済みである。
  新証拠様式での再採取を Phase 0b に含める。
- 探針3（再読込）: 仮説として扱う。Phase 0b の検証項目とし、
  再起動前後の生記録の保存を必須とする。
  再起動は編集画面の再起動とし、確認は仮書込の阻止1件の前後比較とする。
- いずれも関所は写しに戻して一致を確認済みである。

## 2. Phase 0b の探針手順と着手基準

Phase 1 に進む条件は6件の証拠付き完了である。
一時記録の設置場所は運用基盤配下の写しに限り、撤去手順を含める。
一時作業品の置き場所は一時領域とし、知識ベースを汚さない。

### 2.0 複写と照合の実コマンド

複写元3件と複写先3件は次とする。知識ベース起点の相対表記である。

```plaintext
from: tools/harness_compat/common.py
from: tools/harness_compat/fixtures.py
from: tools/harness_compat/run.py
to:   .opencode/harness_compat/common.py
to:   .opencode/harness_compat/fixtures.py
to:   .opencode/harness_compat/run.py
manifest: .opencode/_restore/<date>-impl/manifest-sha256.txt
```

作成と照合と写し戻しのコマンドは次とする。

```plaintext
cp tools/harness_compat/common.py tools/harness_compat/fixtures.py tools/harness_compat/run.py .opencode/harness_compat/
shasum -a 256 tools/harness_compat/common.py tools/harness_compat/fixtures.py tools/harness_compat/run.py | tee manifest
shasum -a 256 .opencode/harness_compat/common.py .opencode/harness_compat/fixtures.py .opencode/harness_compat/run.py
diff <(expected) <(actual) or exit on mismatch, then restore and stop
```

### 2.1 2 問探針

2 問カード（1問目と確認の2択）を出して回答し、
`answers[0][0]` と `answers[1][0]` の双方を含む生記録を保存する。
合格基準は両要素の存在と値の一致である。
単問の実阻止も同時に証拠化し、実会話の阻止3件とは別枠で数える。

### 2.2 殻引数キー

殻文面3種（`echo x > 仮書込`・ヒアドキュメント・`python3 -c 書込呼出し`）で
実行前接点の入力全文を一時記録で採取し、文面の入る引数キーを列挙する。
想定は `command` とし、3種一致で確定とする。相違時は記録して正す。

### 2.3 許可順序

許可照会の入力全文を一時記録で採取し、経路抽出の可否を確認する。
抽出可なら二重拒否の対象にし、不可なら事前受信点を正とし
許可側は現状維持とする。

### 2.4 再起動

編集画面の再起動の前後で仮書込の阻止1件の振舞いを比べ、
前後双方の生記録を保存する。合格基準は再起動前の旧振舞いと
再起動後の新振舞いの差の確認である。

### 2.5 性能

100 件以上の書込判定を無副作用の繰返しで起こす。
繰返しは一時領域の計時台本で行い、知識ベースには書かない。
関所の判定呼出し全体の時間を測って 95 パーセンタイルを算出する。
測定コマンドと条件を記録に残す。暫定予算は 1500 ミリ秒以内とし、
合否不使用と明記する。

### 2.6 制限超過

共通判定の呼出しに 15 秒の遅延を入れる包みで超過を再現し、
通過と監査記録の確認を行う。包みの実コードは一時差分として保存し、
設置場所・遅延量・撤去手順を記録する。撤去後に写し照合を行う。

## 3. 設計

### 3.1 判定の一元化（追加なし）

判定は既存の共通関数をそのまま呼ぶ。新規追加は行わない。
版束ねと既読は関所側の責務とし、共通層には持ち込まない。
共通層に変更が入る場合は材料と実行器の更新とセットにし、
その場合は本計画を停止し別途承認を取る。

### 3.2 カード状態の保持（束ね仕様）

回答の採取は `tool.execute.after` で行い、阻止は `tool.execute.before` で行う。
束ねは承認の識別と書込の照合を分ける。承認鍵は `sessionID` と
回答採取した質問の `callID` と親メモの実パスとする。
文面一致だけでの流用は不可とする。保持するのは次である。

- 主回答（`answers[0][0]`）と確認回答（`answers[1][0]`）
- 対象の親メモの実パスと決定時の計画版の SHA
- SHA は親ファイルの先頭区画内の `^\s*brainstorm_status\s*:.*$` に合う行を落とし、
  残りを改行 LF 統一・各行末尾空白除去・`\n` 結合・末尾改行1つにした文の
  sha256 とする。参照実装は運用基盤側の写しに置く。
  回答通過時に鍵と組で保存し、書込時に再計算して比較する
- 対象集合は決定時に active だった親の集合とし、有効なのは承認で ready へ
  遷移したものだけとする。active のままの親での書込は阻止する
- 部分回答・確認否定・空回答・単問カードは未承認のままにする
- 回答が取得できない場合は疑似状態で補わず未承認に倒し、検出条件を記録する

通過条件は共通判定の通過と SHA 一致と ready の論理積とする。
共通層を迂回して SHA だけで通過させない。

### 3.3 対象の内外判定（正規化あり）

- 基点は `directory` に固定する。取得不能時は未承認倒しとする。
- 親メモ族への書込は常に通す（記録で行き詰まりを作らない）。
  メモ族は正規化後の親メモ群配下の接頭辞と定める。
- 適用範囲外への書込は通す（この関所の所有外）。
  適用範囲は束ね対象の親の適用範囲とし、複数ある場合は和集合とする。
- 適用範囲内の非メモ書込だけが阻止対象である。
- 対象経路は呼出し引数の実パスを直接読む。`filePath` と `path` の双方を読む。
  空白で切る抽出は使わない。
- 経路は上記の基点を起点に絶対化し、`..` と末尾斜線を正規化してから判定する。
  適用範囲の一致は接頭辞の境界付きで行い、名前の似た別場所を混同しない。
  参照の解決は行わないことを宣言し、残存迂回として受入条件に追記する。
- 新規ファイル（実在しない経路）は正規化後の接頭辞の一致で内外を判定する。
  書込対象の実在確認は行わない。

### 3.4 言語境界と性能予算（暫定数値あり）

- 関所から共通判定へは起動方式で呼ぶ。
- 書込経路の制限時間は 10000 ミリ秒とし、超過時は通す（fail-open）。
  10 秒は暫定であり、合否には使わず目標として扱う。
  暫定値の見直し条件は実測後の超過頻度とする。
  現行の 60 秒と 15 秒とは用途が違うため置き換えではなく追加とする。
- 追加遅延の測定は 100 件以上の書込判定で 95 パーセンタイルを算出し、
  測定区間は関所の判定呼出し全体、測定コマンドを記録に残す。
  暫定予算は 1500 ミリ秒以内とし、合否不使用と明記する。
- 容易とは書かない。

### 3.5 殻実行の扱い（単一接点で監視する）

殻実行は `tool.execute.before` の `bash` で監視する。第二接点は使わない。
殻文面の引数キーは Phase 0b で実測確定する。相違時は記録して正す。
それまでは殻規則を仮置きとし、確定まで殻阻止の実装着手を禁止する。
近似であることを明記する。検出規則は次とし、該当したら内外判定へ進む。
連鎖は `;`・`&&`・`||`・`|`・改行で区切った各断片に適用する。
引用剥がしは単引用・二重引用・逆引用・括弧展開・行末注釈の順に行う。

- リダイレクト記号を含む断片（引用内の記号は除く）
- ヒアドキュメントの開始行（`<<`・`<<-`・`<<<` を含む）
- 書込を開く実行文（上書き・追記の呼出し）
- 復号して書き出す管
- 複写と移動と取得書込と参照作成の呼出し（絶対経路・間接・代理実行を含む）

期待値の行列は次である。読取行は書込を開かない行と定義するため、
絶対経路の読取行の通過と絶対経路の書込行の阻止は矛盾しない。

| 殻の行 | 期待 |
|---|---|
| 適用範囲内へのリダイレクト書込 | 阻止 |
| ヒアドキュメントでの書込 | 阻止 |
| 書込を開く実行文 | 阻止 |
| 復号して書き出す管 | 阻止 |
| 複写と移動と取得書込と参照作成 | 阻止 |
| 読取だけの行 | 通過 |
| 適用範囲外への書込 | 通過 |

否定例として引用内の記号と連鎖の読取断片と変数間接と絶対経路の読取呼出しを
試験に含める。殻近似のすり抜けは残存迂回として受入条件に追記する。
誤検知時の回避路は承認済み時に限る明示例外とし、無条件の回避路は作らない。
すり抜けは不可として記録する。

### 3.6 既読追跡の定義と真理値表（F4 用）

- 既読は当該会話での親メモ実パスへの `read` の観測に限定する。
  引数キーは `filePath` と `path` の双方とし、書込側と同一の実パス読みとする。
  他経路の読取は既読としない（過阻止側に倒す設計として宣言する）。
- 観測点は `tool.execute.before` の読取名とし、書込側と同一の正規化と基点を使う。
  正規化関数は運用基盤側の写しに置き、書込側と共有する。
- 保持は会話ごとの記録とし、再起動跨ぎは無効とする。複数親は親ごとに記録する。
- 判定の真理値表は次であり、結合は関所側で行う。

| 既読 | 承認済 | 結果 |
|---|---|---|
| 未読 | 未承認 | 阻止 |
| 未読 | 承認済 | 阻止 |
| 既読 | 未承認 | 阻止 |
| 既読 | 承認済 | 通過 |

- 優先順位は、回答不能時は未承認阻止、基盤異常時は監査記録の上で通過とし、
  メモ族と範囲外は上表より先に通過させる。

### 3.7 許可経路の扱い（二重拒否にする）

`tool.execute.before` と `permission.ask` の双方に同一判定を入れる。
対象は書込と編集とし、殻は文面抽出が可能な場合に限る。
順序の実測依存をなくすためである。
許可側の引数形状は Phase 0b で確定し、経路抽出が不可なら
事前受信点を正とし許可側は現状維持とする。
失敗の扱いは三分し、回答不能は未承認阻止、検査基盤の異常は
監査記録の上で通過、許可側の形状不明は現状維持とする。
監査記録の採取は手作業で行い、関所自身は書かない。

## 4. 試験

### 4.1 共有材料（既存10件・変更なし）

未承認書込は阻止、承認済書込は通過、部分回答と確認否定は未承認、
旧承認の流用は阻止、不正遷移は拒否、正規再開は通過、親不整合は阻止、
基準 flow は通過。

### 4.2 関所レベルの合成試験

各試験に準備・実行コマンド・判定基準を付す。以下は項目であり、
詳細手順は実装時に固定する。殻と引数キー確定前の項目は Phase 0b 完了まで着手禁止とする。

- 未承認の書込呼出しは阻止される
- 承認済の書込呼出しは通過する
- 部分回答後の書込は阻止される
- 確認否定後の書込は阻止される
- 単問カード後の書込は阻止される
- 旧版承認での新版への書込は阻止される（旧承認流用）
- 異なる親への承認での書込は阻止される
- 異なる会話の承認での書込は阻止される
- 異なるカードの承認語の流用は阻止される（承認呼出番号の不一致）
- 許可拒否経路での未承認書込は阻止される
- 打切りの回答での書込は阻止される
- 親が未読の状態での範囲内書込は阻止される（F4）
- 親の既読と承認済での書込は通過する（F4 の対比）
- 未読と承認済の組合せは阻止される
- 既読と未承認の組合せは阻止される
- メモ族への書込は未承認でも通過する
- 範囲外への書込は未承認でも通過する
- `..` 脱出の迂回例は阻止される
- 名前の似た別場所は通過する
- 参照の例は試験せず残存として明記する
- 殻の行列7行は期待どおりに阻止または通過する
- 引用内の記号と連鎖の読取断片と変数間接と絶対経路の読取呼出しは通過する
- 制限時間の超過時は通す（遅延注入の包みで再現する。
  包みの設置場所・遅延量・撤去手順を記録する）
- 検査基盤の不在時は通す（写しを退避して再現し、復帰手順を記録する）
- 会話番号不明の入力形状では、カードは通し書込は阻止する

### 4.3 実会話の観測（完成条件）

- 未承認書込が実際に止まること（F1・阻止1件目）
- 親未読での範囲内書込が実際に止まること（F4・阻止2件目）
- 殻の書込が実際に止まること（F1・阻止3件目）
- 殻の読取が実際に通ること（F1・通過の対比）
- 承認済書込が実際に通ること（F1・通過1件目）
- 親の既読と承認済での書込が実際に通ること（F4・通過2件目）
- 単問カードの実阻止は Phase 0b の必須証拠とし、実会話の阻止3件とは別枠で数える
- 証拠は1件ごとにファイル名・時刻・時間帯・会話番号・呼出番号・
  承認呼出番号・束ね SHA・親・道具名・引数全文・阻止文の全文・
  打切り旗・判定入力で残す。ファイル名は日時と番号の形式
  （例: `20260904-223000-prewrite-evidence-01.json`）とする。
  時刻は時間帯付き1種に統一する。
  書込阻止の文言は `prewrite-gate:` で始め、カード阻止と区別する。
  保存先は復帰置き場の日付フォルダとし、保持は案件の終了まで、
  採取は手作業とする。通過件は阻止文の代わりに通過の記録を残す。
  会話番号と呼出番号の採取元は接点の識別子とする。
- 合成試験の合格を完成扱いにしない

証拠 JSON の書式例は次とする。

```plaintext
{
  "time": "2026-09-04T22:30:00+09:00",
  "session": "<sessionID>",
  "call": "<callID>",
  "approval_call": "<callID>",
  "sha": "<sha256>",
  "parent": "<absolute path>",
  "tool": "write",
  "args_excerpt": "<text>",
  "verdict": "BLOCK",
  "message": "prewrite-gate: <reason>",
  "truncated": false
}
```

## 5. 受入条件

- Phase 0 の複製と参照切替が目録とハッシュ照合で完了していること
  （本計画への承認とは分離して判定する）

## 6. 危険と対策

| 危険 | 対策 |
|---|---|
| 追加部品の再読込に再起動が要る | 編集画面の再起動後に仮呼出し1件で確認する |
| 回答の観測が取れない | 疑似状態で補わず未承認に倒す |
| 誤検知で仕事が止まる | メモ族と範囲外は通し、基盤異常は通す。殻の回避路は承認済みに限る |
| 呼出しごとの起動 cost | 上記の測定で確かめ、超過時は移植か維持かを決める |
