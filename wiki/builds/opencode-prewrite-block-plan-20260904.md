# opencode 承認前書込の事前阻止の詳細計画（改訂版 r2）

F1（承認前書込の阻止なし）と F4（親未読での実装阻止なし）を現行仕様で閉じる。
B番号との対応は末尾の対応表に置き、本文の表記は F 番号に統一する。
正本は `wiki/builds/brainstorm-skill.md`、思想は各サービス一単位・基盤別不具合不可、
目標は使用感一致ではなく実会話での機械的遮断である。

初版は独立審査で NO_GO（致命的4件・重要7件・軽微6件）となり、
本改訂版で探針結果を取り込んで全件に応答する。

## 0. 前提と範囲

### 対象

- Phase 0: 共通足場の移設（置き場所は `.opencode/harness_compat/` に確定。例外承認は取らない）
- Phase 1: `tool.execute.before` での書込事前阻止の実装（運用基盤配下のみ）
- Phase 2: 実会話での阻止と通過の観測

### 対象外

- F2（再注入）、F3（終了阻止）、B1（照合器の目印変更）
- 正本側と別基盤側の既存監査の改修
- `permission.ask` 経路の追加（第二経路として温存し今回は使わない）
- 判定の中身の変更と材料の追加緩和

### 変更してよい場所

`.opencode/` 配下のみ。起動路の禁止に触れない。

## 1. 探針結果（実測・2026-09-04）

- 探針1（回答の形状）: 合格。回答は実行後接点の結果内の回答欄に、
  質問ごとの選択束で入る。主回答が1番目、確認回答が2番目である。
  空欄と否定の扱いもここで判定できる。
- 探針2（書込の阻止）: 合格。仮書込は止まり仮ファイルは作られず、
  止まったのは当該呼出しだけで会話は続いた。利用者への表示文を確認した。
- 探針3（再読込）: 回答が出た。追加部品は再起動で載り、会話の途中では載らない。
  今後の実装は再起動と対にする。
- いずれも一時記録は消し、関所は写しに戻して一致を確認済みである。

## 2. 現状の実体（確認済み）

- 関所は承認カードのみ停止し、書込と殻実行は観測だけで素通りする。
- 例外送出で当該呼出しを止める方式は、承認カードと仮書込の双方で実績がある。
- 型定義に事前受信点・許可照会・受信時接点があり、終了接点は一覧に存在しない。
- 会話番号が不明な呼出しは止めない決まりがある（他会話への巻き添え防止）。
- 検査基盤の異常は通す決まりがある（機械自身の故障で仕事を止めない）。

## 3. 設計

### 3.1 判定の一元化（追加なし）

判定は既存の共通関数をそのまま呼ぶ。新規追加は行わない。
版束ねは関所側の責務とし、共通層には持ち込まない。
共通層に変更が入る場合は材料と実行器の更新とセットにする。

### 3.2 カード状態の保持

会話ごとに次を保持する。承認は会話と親と計画版に束ねる。

- 主回答は回答欄の1番目の先頭要素、確認回答は2番目の先頭要素とする
  （探針1の写像。複数選択時は先頭要素で判定する）
- 対象の親メモの実パスと計画版の SHA
- 部分回答・確認否定・空回答は未承認のままにする
- 回答が取得できない場合は疑似状態で補わず未承認に倒し、検出条件を記録する

### 3.3 対象の内外判定

- 親メモ族への書込は常に通す（記録で行き詰まりを作らない）。
- 適用範囲外への書込は通す（この関所の所有外）。
- 適用範囲内の非メモ書込だけが阻止対象である。
- 対象経路は呼出し引数の実パスを直接読む。空白で切る抽出は使わない。
  （現行の関所と検査は実パス直読であり、分割処理は範囲内に存在しない）
- 新規ファイル（実在しない経路）は接頭辞の一致で内外を判定する。
  実在確認は到達性監査の側に任せ、ここでは行わない。

### 3.4 言語境界と性能予算

- 関所から共通判定へは起動方式で呼ぶ。書込経路の制限時間は短くし、
  異常時は通す（fail-open）。追加遅延の予算を測り、超過時は移植か維持かを決める。
- 容易とは書かない。新規面は次節に列挙する。

### 3.5 新規面の列挙

実行後受信点の追加、会話別カード保持、適用範囲解決、メモ族判定、
殻実行の行列、親未読と旧版流用の関所試験、実会話の観測手順である。

### 3.6 殻実行の扱い

書込記号の近似判定のため、すり抜けと誤検知が残る。
誤検知時の回避路を用意し、すり抜けは不可として記録する。
近似の範囲は下記の行列で固定する。

## 4. 試験

### 4.1 共有材料（既存10件・変更なし）

未承認書込は阻止、承認済書込は通過、部分回答と確認否定は未承認、
旧承認の流用は阻止、不正遷移は拒否、正規再開は通過、親不整合は阻止、
基準 flow は通過。

### 4.2 関所レベルの合成試験

- 未承認の書込呼出しは阻止される
- 承認済の書込呼出しは通過する
- 部分回答後の書込は阻止される
- 確認否定後の書込は阻止される
- 旧版承認での新版への書込は阻止される（旧承認流用）
- 親が無い状態での範囲内書込は阻止される（F4）
- メモ族への書込は未承認でも通過する
- 範囲外への書込は未承認でも通過する
- 殻実行の行列（リダイレクト・ヒアドキュメント・書込付き実行・復号）は
  期待どおりに阻止または通過する
- 検査基盤の異常時は通す（fail-open）
- 会話番号不明時は止めない

### 4.3 実会話の観測（完成条件）

- 未承認書込が実際に止まること（F1）
- 承認済書込が実際に通ること（F1）
- 親未読での範囲内書込が実際に止まること（F4）
- 証拠は阻止文と道具名と抜粋で残し、カード阻止と区別する
- 合成試験の合格を完成扱いにしない

## 5. 受入条件

- Phase 0 の承認と完了を確認済みであること
- 実会話で阻止2件と通過1件が観測されること
- 既存自己試験（表示・支援機能・照合）が合格のままであること
- 変更が運用基盤配下に収まること
- 未確認を成功扱いにしないこと（再注入と終了は別扱い）

## 6. 危険と対策

| 危険 | 対策 |
|---|---|
| 追加部品の再読込に再起動が要る | 再起動手順を踏む（探針3で確定済み） |
| 回答の観測が取れない | 疑似状態で補わず未承認に倒す |
| 誤検知で仕事が止まる | メモ族と範囲外は通し、基盤異常は通す |
| 呼出しごとの起動 cost | 予算を測り、超過時は移植か維持かを決める |

## 7. 承認の区切り

本計画の承認対象は Phase 1 の実装と Phase 2 の観測である。
F2 と F3 の着手は含まない。
