## 3. 設計

### 3.1 判定の一元化（追加なし）

判定は既存の共通関数をそのまま呼ぶ。新規追加は行わない。
版束ねと既読は関所側の責務とし、共通層には持ち込まない。
共通層に変更が入る場合は材料と実行器の更新とセットにし、
その場合は本計画を停止し別途承認を取る。

### 3.2 カード状態の保持（束ね仕様）

回答の採取は `tool.execute.after` で行い、阻止は `tool.execute.before` で行う。
束ねは承認の識別と書込の照合を分ける。承認鍵は `sessionID` と
回答採取した質問の `callID` と親メモの実パスとする。
文面一致だけでの流用は不可とする。保持するのは次である。

- 主回答（`answers[0][0]`）と確認回答（`answers[1][0]`）
- 対象の親メモの実パスと決定時の計画版の SHA
- SHA は親ファイルの先頭区画内の `^\s*brainstorm_status\s*:.*$` に合う行を落とし、
  残りを改行 LF 統一・各行末尾空白除去・`\n` 結合・末尾改行1つにした文の
  sha256 とする。参照実装は運用基盤側の写しに置く。
  回答通過時に鍵と組で保存し、書込時に再計算して比較する
- 対象集合は決定時に active だった親の集合とし、有効なのは承認で ready へ
  遷移したものだけとする。active のままの親での書込は阻止する
- 部分回答・確認否定・空回答・単問カードは未承認のままにする
- 回答が取得できない場合は疑似状態で補わず未承認に倒し、検出条件を記録する

通過条件は共通判定の通過と SHA 一致と ready の論理積とする。
共通層を迂回して SHA だけで通過させない。

### 3.3 対象の内外判定（正規化あり）

- 基点は `directory` に固定する。取得不能時は未承認倒しとする。
- 親メモ族への書込は常に通す（記録で行き詰まりを作らない）。
  メモ族は正規化後の親メモ群配下の接頭辞と定める。
- 適用範囲外への書込は通す（この関所の所有外）。
  適用範囲は束ね対象の親の適用範囲とし、複数ある場合は和集合とする。
- 適用範囲内の非メモ書込だけが阻止対象である。
- 対象経路は呼出し引数の実パスを直接読む。`filePath` と `path` の双方を読む。
  空白で切る抽出は使わない。
- 経路は上記の基点を起点に絶対化し、`..` と末尾斜線を正規化してから判定する。
  適用範囲の一致は接頭辞の境界付きで行い、名前の似た別場所を混同しない。
  参照の解決は行わないことを宣言し、残存迂回として受入条件に追記する。
- 新規ファイル（実在しない経路）は正規化後の接頭辞の一致で内外を判定する。
  書込対象の実在確認は行わない。

### 3.4 言語境界と性能予算（暫定数値あり）

- 関所から共通判定へは起動方式で呼ぶ。
- 書込経路の制限時間は 10000 ミリ秒とし、超過時は通す（fail-open）。
  10 秒は暫定であり、合否には使わず目標として扱う。
  暫定値の見直し条件は実測後の超過頻度とする。
  現行の 60 秒と 15 秒とは用途が違うため置き換えではなく追加とする。
- 追加遅延の測定は 100 件以上の書込判定で 95 パーセンタイルを算出し、
  測定区間は関所の判定呼出し全体、測定コマンドを記録に残す。
  暫定予算は 1500 ミリ秒以内とし、合否不使用と明記する。
- 容易とは書かない。

### 3.5 殻実行の扱い（単一接点で監視する）

殻実行は `tool.execute.before` の `bash` で監視する。第二接点は使わない。
殻文面の引数キーは `command` と確定した（Phase 0b の生記録による）。
近似であることを明記する。検出規則は次とし、該当したら内外判定へ進む。
連鎖は `;`・`&&`・`||`・`|`・改行で区切った各断片に適用する。
引用剥がしは単引用・二重引用・逆引用・括弧展開・行末注釈の順に行う。

- リダイレクト記号を含む断片（引用内の記号は除く）
- ヒアドキュメントの開始行（`<<`・`<<-`・`<<<` を含む）
- 書込を開く実行文（上書き・追記の呼出し）
- 復号して書き出す管
- 複写と移動と取得書込と参照作成の呼出し（絶対経路・間接・代理実行を含む）

期待値の行列は次である。読取行は書込を開かない行と定義するため、
絶対経路の読取行の通過と絶対経路の書込行の阻止は矛盾しない。

| 殻の行 | 期待 |
|---|---|
| 適用範囲内へのリダイレクト書込 | 阻止 |
| ヒアドキュメントでの書込 | 阻止 |
| 書込を開く実行文 | 阻止 |
| 復号して書き出す管 | 阻止 |
| 複写と移動と取得書込と参照作成 | 阻止 |
| 読取だけの行 | 通過 |
| 適用範囲外への書込 | 通過 |

否定例として引用内の記号と連鎖の読取断片と変数間接と絶対経路の読取呼出しを
試験に含める。殻近似のすり抜けは残存迂回として受入条件に追記する。
誤検知時の回避路は承認済み時に限る明示例外とし、無条件の回避路は作らない。
すり抜けは不可として記録する。

### 3.6 既読追跡の定義と真理値表（F4 用）

- 既読は当該会話での親メモ実パスへの `read` の観測に限定する。
  引数キーは `filePath` と `path` の双方とし、書込側と同一の実パス読みとする。
  他経路の読取は既読としない（過阻止側に倒す設計として宣言する）。
- 観測点は `tool.execute.before` の読取名とし、書込側と同一の正規化と基点を使う。
  正規化関数は運用基盤側の写しに置き、書込側と共有する。
- 保持は会話ごとの記録とし、再起動跨ぎは無効とする。複数親は親ごとに記録する。
- 判定の真理値表は次であり、結合は関所側で行う。

| 既読 | 承認済 | 結果 |
|---|---|---|
| 未読 | 未承認 | 阻止 |
| 未読 | 承認済 | 阻止 |
| 既読 | 未承認 | 阻止 |
| 既読 | 承認済 | 通過 |

- 優先順位は、回答不能時は未承認阻止、基盤異常時は監査記録の上で通過とし、
  メモ族と範囲外は上表より先に通過させる。

### 3.7 許可経路の扱い（現状維持にする）

`tool.execute.before` を正とし、許可側は現状維持とする。
現設定では許可照会は発火しないことを確認したため、二重拒否は行わない。
順序の実測依存はなくす。
失敗の扱いは三分し、回答不能は未承認阻止、検査基盤の異常は
監査記録の上で通過、許可側の形状不明は現状維持とする。
監査記録の採取は手作業で行い、関所自身は書かない。

## 4. 試験

### 4.1 共有材料（既存10件・変更なし）

未承認書込は阻止、承認済書込は通過、部分回答と確認否定は未承認、
旧承認の流用は阻止、不正遷移は拒否、正規再開は通過、親不整合は阻止、
基準 flow は通過。

### 4.2 関所レベルの合成試験

各試験に準備・実行コマンド・判定基準を付す。以下は項目であり、
詳細手順は実装時に固定する。殻と引数キー確定前の項目は Phase 0b 完了まで着手禁止とする。

- 未承認の書込呼出しは阻止される
- 承認済の書込呼出しは通過する
- 部分回答後の書込は阻止される
- 確認否定後の書込は阻止される
- 単問カード後の書込は阻止される
- 旧版承認での新版への書込は阻止される（旧承認流用）
- 異なる親への承認での書込は阻止される
- 異なる会話の承認での書込は阻止される
- 異なるカードの承認語の流用は阻止される（承認呼出番号の不一致）
- 許可拒否経路での未承認書込は阻止される
- 打切りの回答での書込は阻止される
- 親が未読の状態での範囲内書込は阻止される（F4）
- 親の既読と承認済での書込は通過する（F4 の対比）
- 未読と承認済の組合せは阻止される
- 既読と未承認の組合せは阻止される
- メモ族への書込は未承認でも通過する
- 範囲外への書込は未承認でも通過する
- `..` 脱出の迂回例は阻止される
- 名前の似た別場所は通過する
- 参照の例は正規化後の接頭辞判定で拾えない1件を記録し、試験せず残存として明記する
- 殻の行列7行は期待どおりに阻止または通過する
- 引用内の記号と連鎖の読取断片と変数間接と絶対経路の読取呼出しは通過する
- 制限時間の超過時は通す（遅延注入の包みで再現する。
  包みの設置場所・遅延量・撤去手順を記録する）
- 検査基盤の不在時は通す（写しを退避して再現し、復帰手順を記録する）
- 会話番号不明の入力形状では、カードは通し書込は阻止する

### 4.3 実会話の観測（完成条件）

- 未承認書込が実際に止まること（F1・阻止1件目）
- 親未読での範囲内書込が実際に止まること（F4・阻止2件目）
- 殻の書込が実際に止まること（F1・阻止3件目）
- 殻の読取が実際に通ること（F1・通過の対比）
- 承認済書込が実際に通ること（F1・通過1件目）
- 親の既読と承認済での書込が実際に通ること（F4・通過2件目）
- 単問カードの実阻止は Phase 0b の必須証拠とし、実会話の阻止3件とは別枠で数える
- 証拠は1件ごとにファイル名・時刻・時間帯・会話番号・呼出番号・
  承認呼出番号・束ね SHA・親・道具名・引数全文・阻止文の全文・
  打切り旗・判定入力で残す。ファイル名は日時と番号の形式
  （例: `20260904-223000-prewrite-evidence-01.json`）とする。
  時刻は時間帯付き1種に統一する。
  書込阻止の文言は `prewrite-gate:` で始め、カード阻止と区別する。
  保存先は復帰置き場の日付フォルダとし、保持は案件の終了まで、
  採取は手作業とする。通過件は阻止文の代わりに通過の記録を残す。
  会話番号と呼出番号の採取元は接点の識別子とする。
- 合成試験の合格を完成扱いにしない

証拠 JSON の書式例は次とする。

```plaintext
{
  "time": "2026-09-04T22:30:00+09:00",
  "session": "<sessionID>",
  "call": "<callID>",
  "approval_call": "<callID>",
  "sha": "<sha256>",
  "parent": "<absolute path>",
  "tool": "write",
  "args_excerpt": "<text>",
  "verdict": "BLOCK",
  "message": "prewrite-gate: <reason>",
```

## 6. 危険と対策

| 危険 | 対策 |
|---|---|
| 追加部品の再読込に再起動が要る | 編集画面の再起動後に仮呼出し1件で確認する |
| 回答の観測が取れない | 疑似状態で補わず未承認に倒す |
| 誤検知で仕事が止まる | メモ族と範囲外は通し、基盤異常は通す。殻の回避路は承認済みに限る |
| 呼出しごとの起動 cost | 上記の測定で確かめ、超過時は移植か維持かを決める |
