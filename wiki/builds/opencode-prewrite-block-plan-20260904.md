# opencode 承認前書込の事前阻止の詳細計画（改訂版 r5）

F1（承認前書込の阻止なし）と F4（親未読での実装阻止なし）を現行仕様で閉じる。
B番号との対応は末尾の対応表に置き、本文の表記は F 番号に統一する。
正本は `wiki/builds/brainstorm-skill.md`、思想は各サービス一単位・基盤別不具合不可、
目標は使用感一致ではなく実会話での機械的遮断である。

r4 は再審査で NO_GO（致命的1件・重要13件・軽微1件）となり、
本改訂版で殻の単一接点への戻し・SHA 除外規定・真理値表・二重拒否・
複製運用の同期定義を行う。

## 0. 前提と範囲

### 対象

- Phase 0: 共通足場の複製と参照切替（正本は禁止域の原本のままとする。
  運用基盤側の複写は参照用の写しであり、変更時は原本を変えて写し直す。
  写しの新旧判定はハッシュ目録で行い、所有者は実装会話とする。
  照合は Phase 1 と Phase 2 の開始前に行う）
- Phase 0b: 検証探針（2 問探針・殻引数キー・許可順序の特定。Phase 1 の着手条件）
- Phase 1: `tool.execute.before` での書込事前阻止の実装（運用基盤配下のみ）
- Phase 2: 実会話での阻止と通過の観測

### 対象外

- F2（再注入）、F3（終了阻止）、B1（照合器の目印変更）
- 正本側と別基盤側の既存監査の改修
- 判定の中身の変更と材料の追加緩和

### 変更してよい場所

`.opencode/` 配下のみ。禁止条項は起動路2件の末尾節に特定する。
原本の残る禁止域には書かない。

## 1. 探針結果と証拠（実測・2026-09-04）

- 探針1（回答の形状）: 暫定合格に格下げする。単問カードの記録であり、
  2 問束ねの実証になっていない。証拠は復帰置き場の生記録に保存済みである。
  Phase 0b で 2 問カードの再探針を行い、`answers[0][0]` と `answers[1][0]` の
  双方を含む生記録を保存してから写像を確定する。単問カードは未承認倒しとする。
- 探針2（書込の阻止）: 暫定合格とする。仮書込は止まり仮ファイルは作られず、
  止まったのは当該呼出しだけで会話は続いた。証拠は不存在の確認・阻止文・
  継続の事実の3点で保存済みである。新証拠様式での再採取を Phase 0b に含める。
- 探針3（再読込）: 観測手順として記録する。追加部品は本体の再起動で載り、
  会話の途中では載らない。再起動は編集画面の再起動で足りる。
  確認は仮呼出し1件の振舞いで行う。再起動前後の生記録は次回から保存する。
- いずれも関所は写しに戻して一致を確認済みである。

## 2. 現状の実体（確認済み）

- 関所は承認カードのみ停止し、書込と殻実行は観測だけで素通りする。
- 例外送出で当該呼出しを止める方式は、承認カードと仮書込の双方で実績がある。
- 型定義に事前受信点・許可照会・受信時接点があり、終了接点は一覧に存在しない。
  命令実行の接点は命令用であり殻用ではない。殻は事前受信点の書込名で見る。
- 会話番号が不明な呼出しは止めない決まりがある（他会話への巻き添え防止）。
  書込経路にも同じ条件を適用する。
- 検査基盤の異常は通す決まりがある（機械自身の故障で仕事を止めない）。
  書込経路の共通判定の起動失敗にも同じ条件を適用し、監査記録を残す。

## 3. 設計

### 3.1 判定の一元化（追加なし）

判定は既存の共通関数をそのまま呼ぶ。新規追加は行わない。
版束ねと既読は関所側の責務とし、共通層には持ち込まない。
共通層に変更が入る場合は材料と実行器の更新とセットにする。

### 3.2 カード状態の保持（束ね仕様）

束ね鍵は会話番号と親メモの実パスとカード識別とする。
カード識別は承認待ち見出しと確認質問の同一性とする。保持するのは次である。

- 主回答（回答欄1番目の先頭要素）と確認回答（2番目の先頭要素）
- 対象の親メモの実パスと決定時の計画版の SHA
- SHA は親ファイル内容から状態行と直し記録節を除いた正規化文の sha256 とし、
  回答通過時に鍵と組で保存し、書込時に再計算して比較する
- 対象集合は決定時に active だった親とし、書込時に active または ready で
  SHA 一致のものだけ有効とする。新出現の active 親は未束ねとして阻止する
- 部分回答・確認否定・空回答・単問カードは未承認のままにする
- 回答が取得できない場合は疑似状態で補わず未承認に倒し、検出条件を記録する

### 3.3 対象の内外判定（正規化あり）

- 基点は実行基盤の作業場所に固定する。取得不能時は未承認倒しとする。
- 親メモ族への書込は常に通す（記録で行き詰まりを作らない）。
  メモ族は正規化後の親メモ群配下の接頭辞と定める。
- 適用範囲外への書込は通す（この関所の所有外）。
- 適用範囲内の非メモ書込だけが阻止対象である。
- 対象経路は呼出し引数の実パスを直接読む。`filePath` と `path` の双方を読む。
  空白で切る抽出は使わない。
- 経路は上記の基点を起点に絶対化し、`..` と末尾斜線を正規化してから判定する。
  適用範囲の一致は接頭辞の境界付きで行い、名前の似た別場所を混同しない。
  参照の解決は行わないことを宣言する。
- 新規ファイル（実在しない経路）は正規化後の接頭辞の一致で内外を判定する。
  書込対象の実在確認は行わない。

### 3.4 言語境界と性能予算（暫定数値あり）

- 関所から共通判定へは起動方式で呼ぶ。
- 書込経路の制限時間は 10000 ミリ秒とし、超過時は通す（fail-open）。
  10 秒は暫定であり、合否には使わず目標として扱う。
- 追加遅延の測定は 20 件連続の書込判定で 95 パーセンタイルを算出し、
  測定区間は関所の判定呼出し全体、測定コマンドを記録に残す。
  暫定予算は 1500 ミリ秒以内とし、合否不使用と明記する。
- 容易とは書かない。

### 3.5 殻実行の扱い（単一接点で監視する）

殻実行は事前受信点の書込名で監視する。第二接点は使わない。
殻文面の引数キーは想定を置き、Phase 0b で実測確定する。
相違時は記録して正す。近似であることを明記する。検出規則は次とし、
該当したら内外判定へ進む。連鎖記号で区切られた各断片に適用する。

- リダイレクト記号を含む断片（引用内の記号は除く）
- ヒアドキュメントの開始行
- 書込を開く実行文（上書き・追記の呼出し）
- 復号して書き出す管
- 複写と移動と取得書込の呼出し

期待値の行列は次である。

| 殻の行 | 期待 |
|---|---|
| 適用範囲内へのリダイレクト書込 | 阻止 |
| ヒアドキュメントでの書込 | 阻止 |
| 書込を開く実行文 | 阻止 |
| 復号して書き出す管 | 阻止 |
| 複写と移動と取得書込 | 阻止 |
| 読取だけの行 | 通過 |
| 適用範囲外への書込 | 通過 |

否定例として引用内の記号と連鎖の読取断片を試験に含める。
誤検知時の回避路を用意し、すり抜けは不可として記録する。

### 3.6 既読追跡の定義と真理値表（F4 用）

- 既読は当該会話での親メモ実パスへの読取呼出しの観測と定める。
  観測点は事前受信点の読取名とし、書込側と同一の正規化と基点を使う。
- 保持は会話ごとの記録とし、再起動跨ぎは無効とする。複数親は親ごとに記録する。
- 判定の真理値表は次であり、結合は関所側で行う。

| 既読 | 承認済 | 結果 |
|---|---|---|
| 未読 | 未承認 | 阻止 |
| 未読 | 承認済 | 阻止 |
| 既読 | 未承認 | 阻止 |
| 既読 | 承認済 | 通過 |

- メモ族と範囲外は上表より先に通過させる。

### 3.7 許可経路の扱い（二重拒否にする）

事前受信点と許可照会の双方に同一判定を入れる。
順序の実測依存をなくすためである。いずれかの失敗時は監査記録を残して通す。
監査記録の採取は手作業で行い、関所自身は書かない。

## 4. 試験

### 4.1 共有材料（既存10件・変更なし）

未承認書込は阻止、承認済書込は通過、部分回答と確認否定は未承認、
旧承認の流用は阻止、不正遷移は拒否、正規再開は通過、親不整合は阻止、
基準 flow は通過。

### 4.2 関所レベルの合成試験

- 未承認の書込呼出しは阻止される
- 承認済の書込呼出しは通過する
- 部分回答後の書込は阻止される
- 確認否定後の書込は阻止される
- 単問カード後の書込は阻止される
- 旧版承認での新版への書込は阻止される（旧承認流用）
- 異なる親への承認での書込は阻止される
- 異なる会話の承認での書込は阻止される
- 異なるカードの承認語の流用は阻止される
- 親が未読の状態での範囲内書込は阻止される（F4）
- 親の既読と承認済での書込は通過する（F4 の対比）
- 未読と承認済の組合せは阻止される
- 既読と未承認の組合せは阻止される
- メモ族への書込は未承認でも通過する
- 範囲外への書込は未承認でも通過する
- `..` 脱出の迂回例は阻止される
- 名前の似た別場所は通過する
- 殻の行列7行は期待どおりに阻止または通過する
- 引用内の記号と連鎖の読取断片は通過する
- 制限時間の超過時は通す
- 検査基盤の異常時は通す（fail-open）
- 会話番号不明時は止めない

### 4.3 実会話の観測（完成条件）

- 未承認書込が実際に止まること（F1・阻止1件目）
- 親未読での範囲内書込が実際に止まること（F4・阻止2件目）
- 殻の書込が実際に止まること（F1・阻止3件目）
- 承認済書込が実際に通ること（F1・通過1件目）
- 親の既読と承認済での書込が実際に通ること（F4・通過2件目）
- 証拠は1件ごとに時刻・会話番号・呼出番号・束ね SHA・親・
  阻止文の全文・道具名・引数抜粋で残す。
  書込阻止の文言は `prewrite-gate:` で始め、カード阻止と区別する。
  保存先は復帰置き場の日付フォルダとし、命名則と保持を定めて残す。
  証拠の採取は手作業で行い、関所自身は書かない。
- 合成試験の合格を完成扱いにしない

## 5. 受入条件

- Phase 0 の複製と参照切替が目録とハッシュ照合で完了していること
  （本計画への承認とは分離して判定する）
- Phase 0b の 2 問探針・殻引数キー・許可順序の特定が証拠付きで完了していること
- 実会話で阻止3件と通過2件が上記の割付で観測されること
- 既存自己試験が合格のままであること。正式名は次である。
  `display_check --selftest`、`muse_brainstorm_check --selftest`、
  `harness_compat run --selftest`
- 変更が運用基盤配下に収まること
- 未確認を成功扱いにしないこと（再注入と終了は別扱い）

## 6. 危険と対策

| 危険 | 対策 |
|---|---|
| 追加部品の再読込に再起動が要る | 編集画面の再起動後に仮呼出し1件で確認する |
| 回答の観測が取れない | 疑似状態で補わず未承認に倒す |
| 誤検知で仕事が止まる | メモ族と範囲外は通し、基盤異常は通す。殻の回避路を用意する |
| 呼出しごとの起動 cost | 上記の測定で確かめ、超過時は移植か維持かを決める |

## 7. 承認の区切り

本計画の承認対象は Phase 1 の実装と Phase 2 の観測である。
F2 と F3 の着手は含まない。

## 9. 改訂履歴

- r2: 探針3件の結果を取り込み、全指摘に応答。再審査で NO_GO
  （致命的3件・重要7件・軽微2件）。証拠破棄と殻行列の欠落が主因。
- r3: 証拠付き再探針の結果を取り込み、証拠を保存する運用に変えた。
  殻実行を対象に入れて行列と回避路を定め、束ね仕様・既読追跡・
  再起動手順・性能数値・移動の宣言・正規化・証拠様式を追加した。
  再審査で NO_GO（致命的4件・重要7件・軽微2件）。
  2 問束ねの未実証・殻の迂回・既読追跡の未定義・移動の禁止抵触が主因。
- r4: Phase 0 を複製と参照切替に変え、旧置き場の消滅をやめた。
  Phase 0b に 2 問探針と殻経路の特定を置き、着手条件にした。
  束ねに SHA 算定と複数親の扱いを定め、既読追跡を定義し、
  再起動手順・性能の測定法・正規化の基点・証拠様式を確定し、
  試験に殻7件・異親異会話・既読対比を追加した。
  再審査で NO_GO（致命的1件・重要13件・軽微1件）。
  第二接点の不存在と束ね・正規化・証拠の不足が主因。
- r5: 殻を単一接点に戻し、引数キーを実測確定にした。
  SHA から可変部を除外し、対象集合と時点を定義し、カード識別を束ねに加えた。
  真理値表と結合順序を定め、読取側の正規化を書込側と同一にした。
  許可経路を二重拒否にし、殻規則を実行可能化し、実会話に F4 通過を足し、
  制限超過の試験と監査記録の分担を定め、証拠様式を確定し、
  性能を暫定扱いにし、複製運用の同期を定義した。
