# opencode 承認前書込の事前阻止の詳細計画（改訂版 r3）

F1（承認前書込の阻止なし）と F4（親未読での実装阻止なし）を現行仕様で閉じる。
B番号との対応は末尾の対応表に置き、本文の表記は F 番号に統一する。
正本は `wiki/builds/brainstorm-skill.md`、思想は各サービス一単位・基盤別不具合不可、
目標は使用感一致ではなく実会話での機械的遮断である。

r2 は再審査で NO_GO（致命的3件・重要7件・軽微2件）となり、
本改訂版で証拠保存・殻実行決定・束ね仕様・数値予算を追加する。

## 0. 前提と範囲

### 対象

- Phase 0: 共通足場の移動（移動と定める。複写と二重正本は行わない。
  移動後は運用基盤側を正とし、旧置き場は消滅させる。例外承認は取らない）
- Phase 1: `tool.execute.before` での書込事前阻止の実装（運用基盤配下のみ）
- Phase 2: 実会話での阻止と通過の観測

### 対象外

- F2（再注入）、F3（終了阻止）、B1（照合器の目印変更）
- 正本側と別基盤側の既存監査の改修
- `permission.ask` 経路の追加（第二経路として温存し今回は使わない。
  書込は必ず事前受信点を経由するため、温存は迂回路にならない）
- 判定の中身の変更と材料の追加緩和

### 変更してよい場所

`.opencode/` 配下のみ。起動路の禁止に触れない。

## 1. 探針結果と証拠（実測・2026-09-04）

- 探針1（回答の形状）: 合格。回答は実行後接点の結果内の回答欄に、
  質問ごとの選択束で入る。主回答が1番目の先頭要素、確認回答が2番目の先頭要素である。
  証拠は復帰置き場の生記録に保存し、消さない。
- 探針2（書込の阻止）: 合格。仮書込は止まり仮ファイルは作られず、
  止まったのは当該呼出しだけで会話は続いた。
  証拠は不存在の確認・阻止文・継続の事実の3点で保存し、消さない。
- 探針3（再読込）: 回答が出た。追加部品は本体の再起動で載り、
  会話の途中では載らない。再起動は編集画面の再起動で足りることを確認した。
  今後の実装は再起動と対にする。再起動後の確認は版表示ではなく、
  仮呼出し1件の振舞いで行う。
- いずれも関所は写しに戻して一致を確認済みである。

## 2. 現状の実体（確認済み）

- 関所は承認カードのみ停止し、書込と殻実行は観測だけで素通りする。
- 例外送出で当該呼出しを止める方式は、承認カードと仮書込の双方で実績がある。
- 型定義に事前受信点・許可照会・受信時接点があり、終了接点は一覧に存在しない。
- 会話番号が不明な呼出しは止めない決まりがある（他会話への巻き添え防止）。
  書込経路にも同じ条件を適用する。
- 検査基盤の異常は通す決まりがある（機械自身の故障で仕事を止めない）。
  書込経路の共通判定の起動失敗にも同じ条件を適用する。

## 3. 設計

### 3.1 判定の一元化（追加なし）

判定は既存の共通関数をそのまま呼ぶ。新規追加は行わない。
版束ねは関所側の責務とし、共通層には持ち込まない。
共通層に変更が入る場合は材料と実行器の更新とセットにする。

### 3.2 カード状態の保持（束ね仕様）

束ね鍵は会話番号と親メモの実パスとする。保持するのは次である。

- 主回答（回答欄1番目の先頭要素）と確認回答（2番目の先頭要素）
- 対象の親メモの実パスと決定時の計画版の SHA
- 部分回答・確認否定・空回答は未承認のままにする
- 回答が取得できない場合は疑似状態で補わず未承認に倒し、検出条件を記録する

書込時の照合は、同一会話・同一親・SHA 一致・承認済の4点が揃ったときだけ通過とする。
計画版が変わった後の旧承認での書込は阻止する。

### 3.3 対象の内外判定（正規化あり）

- 親メモ族への書込は常に通す（記録で行き詰まりを作らない）。
  メモ族は正規化後の親メモ配下と定める。
- 適用範囲外への書込は通す（この関所の所有外）。
- 適用範囲内の非メモ書込だけが阻止対象である。
- 対象経路は呼出し引数の実パスを直接読む。空白で切る抽出は使わない。
- 経路は会話の作業場所を起点に絶対化し、`..` と末尾斜線を正規化してから判定する。
  適用範囲の一致は接頭辞の境界付きで行い、名前の似た別場所を混同しない。
- 新規ファイル（実在しない経路）は正規化後の接頭辞の一致で内外を判定する。
  実在確認は到達性監査の側に任せ、ここでは行わない。

### 3.4 言語境界と性能予算（数値あり）

- 関所から共通判定へは起動方式で呼ぶ。
- 書込経路の制限時間は 10000 ミリ秒とし、超過時は通す（fail-open）。
- 追加遅延の予算は 20 件連続の書込判定で 95 パーセンタイル 1500 ミリ秒以内とする。
  超過時は移植か維持かを別途決める。
- 容易とは書かない。

### 3.5 殻実行の扱い（対象に入れる）

殻実行は事前受信点で監視する。近似であることを明記する。
検出規則は次とし、該当したら適用範囲内外の判定へ進む。

- リダイレクト記号を含む行
- ヒアドキュメントの開始行
- 書込を開く実行文（上書き・追記の呼出し）
- 復号して書き出す管

期待値の行列は次である。

| 殻の行 | 期待 |
|---|---|
| 適用範囲内へのリダイレクト書込 | 阻止 |
| ヒアドキュメントでの書込 | 阻止 |
| 書込を開く実行文 | 阻止 |
| 復号して書き出す管 | 阻止 |
| 読取だけの行 | 通過 |
| 適用範囲外への書込 | 通過 |

誤検知時の回避路を用意し、すり抜けは不可として記録する。

## 4. 試験

### 4.1 共有材料（既存10件・変更なし）

未承認書込は阻止、承認済書込は通過、部分回答と確認否定は未承認、
旧承認の流用は阻止、不正遷移は拒否、正規再開は通過、親不整合は阻止、
基準 flow は通過。

### 4.2 関所レベルの合成試験

- 未承認の書込呼出しは阻止される
- 承認済の書込呼出しは通過する
- 部分回答後の書込は阻止される
- 確認否定後の書込は阻止される
- 旧版承認での新版への書込は阻止される（旧承認流用）
- 親が未読の状態での範囲内書込は阻止される（F4）
- 親の既読と承認済での書込は通過する（F4 の対比）
- メモ族への書込は未承認でも通過する
- 範囲外への書込は未承認でも通過する
- `..` 脱出の迂回例は阻止される
- 名前の似た別場所は通過する
- 検査基盤の異常時は通す（fail-open）
- 会話番号不明時は止めない

### 4.3 実会話の観測（完成条件）

- 未承認書込が実際に止まること（F1・阻止1件目）
- 親未読での範囲内書込が実際に止まること（F4・阻止2件目）
- 承認済書込が実際に通ること（F1・通過1件目）
- 証拠は1件ごとに阻止文の全文・道具名・引数抜粋で残し、
  書込阻止の文言は `prewrite-gate:` で始め、カード阻止と区別する。
  保存先は復帰置き場の日付フォルダとする。
- 合成試験の合格を完成扱いにしない

## 5. 受入条件

- Phase 0 の承認と完了を確認済みであること（承認の所在は本計画への承認とする）
- 実会話で阻止2件と通過1件が上記の割付で観測されること
- 既存自己試験が合格のままであること。正式名は次である。
  `display_check --selftest`、`muse_brainstorm_check --selftest`、
  `harness_compat run --selftest`
- 変更が運用基盤配下に収まること
- 未確認を成功扱いにしないこと（再注入と終了は別扱い）

## 6. 危険と対策

| 危険 | 対策 |
|---|---|
| 追加部品の再読込に再起動が要る | 編集画面の再起動後に仮呼出し1件で確認する |
| 回答の観測が取れない | 疑似状態で補わず未承認に倒す |
| 誤検知で仕事が止まる | メモ族と範囲外は通し、基盤異常は通す。殻の回避路を用意する |
| 呼出しごとの起動 cost | 上記の予算で測り、超過時は移植か維持かを決める |

## 7. 承認の区切り

本計画の承認対象は Phase 1 の実装と Phase 2 の観測である。
F2 と F3 の着手は含まない。
