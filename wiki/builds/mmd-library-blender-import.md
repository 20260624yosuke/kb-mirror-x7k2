## これは何 / 目的

ドルフロ2ほかの MMD モデル(PMX)をまとめて Blender に取り込み、**Finder でサムネを見て
ダブルクリックで開ける**状態にする仕組み。[[gf2-helen-starlit-waltz-3d-reference-build]] の
「未完了: 他キャラ/別衣装へ一般化するテンプレート化」を解消したもの。

狙いは2つ。

1. 溜まった配布モデルを、開いて見られる `.blend` にする(モーション適応は非対象)。
2. **ファイル名だけでは中身が分からない**という武田さんの不便を解消する。
   ヘレンのプロジェクトで `01_blend/` に本体7個と `.blend1` 自動バックアップ6個が同居し、
   新旧の区別がつかなくなっていたのが出発点。

## サムネ管理の方式(なぜこの作り)

**macOS 標準のカスタムアイコン**を使う。`.blend` ファイル本体にレンダー画像を貼るので、
Finder のギャラリー表示でサムネが並び、**ダブルクリックでそのまま Blender が開く**。
「サムネを見る場所」と「ファイルを開く場所」が同じになるのが要点。

- 実装は Swift 1本 `04-set-icon.swift` → `bin/set-icon`。Apple 公式 API の
  `NSWorkspace.setIcon(_:forFile:options:)` だけを使い、サードパーティに依存しない。
  `--clear` で元に戻せる(逃げ道)。
- 外付けSSDは **APFS** なのでカスタムアイコンが使える(exFAT なら不可だった)。
- 2026-07-26 にスパイクで実機確認済み。武田さんが Finder で「猿が見えた」と確認。

**不採用にした案**: Eagle(入るのが PNG であって `.blend` ではない。クリックで開くのは画像) /
QuickLook 拡張(数年更新が止まり macOS 26 で動く見込みが薄い) /
Obsidian ギャラリー新規開発(工数過大)。PNG は作ってあるので Eagle へは後から追加できる。

## 設計上の判断とその根拠

### ヘレンのスクリプトから流用できたもの・できなかったもの

`helen-reference-capture.py` は `helen-model-map.json` に**ヘレン専用の値**
(アーマチュア名、胸/ドレスの高さ比、ボーン名 `左腕`)を依存しており、**そのままでは使えない**。

- 流用した: 外接箱(bounds)の考え方、EEVEE 設定、SHA-256 検証
- 作り直した: **カメラは外接箱から自動で決める**。全視点で同じ距離を使い、
  視点ごとに大きさが変わらないようにした(比べられるようにするため)
- **ポーズは一切変更しない**。ボーン名がモデルごとに違うので触ると壊れる

### `.blend1` を作らせない

`bpy.context.preferences.filepaths.save_version = 0` を設定。
武田さんが困っていた「新旧が区別できない」の直接の原因が `.blend1` の増殖だったので、
新しい方では最初から作らせない。

> [!warning] 事後修復スクリプトでの再発(2026-07-27 に発見・修正済み)
> `03-build-model.py` にはこの設定があるが、**保存済み blend を後から開いて
> 上書き保存する `07-repair-saved-blend.py` には無かった**。事後修復で
> `星穹铁道—女主（欢愉）_记忆命途` / `_雙節棍` の2体に `.blend1` が発生した。
> 「1ファイルで完結する取り込み」だけでなく、**既存 blend を開き直して再保存する
> あらゆる補助スクリプトにも同じ設定が要る**という教訓。同スクリプトの冒頭に
> 追記して解消済み。今後 blend を再保存する新しいスクリプトを足す時は必ずこれを疑う。

### 命名: 一次情報源は PMX 内蔵の英語コードネーム

**2026-07-26 に方針を全面変更した。** それ以前は中国語名からこちらで音写していたが、
これは検証できない創作であり、実際に誤りだらけだった。

| 中国語名 | 旧(こちらの音写・誤り) | 正しい値(PMX 内蔵) |
|---|---|---|
| 维尔德 | ヴェルデ | **Welrod** |
| 安朵丝 | アンドロス | **Andoris** |
| 六分仪 | セクスタンス | **Sextans** |
| 杜莎妮 | ドゥシャニ | **Dusevnyj** |
| 可露凯 | コルフェ | **Clukay** |

現在は `GirlsFrontline WelrodDefault` のような **PMX に埋め込まれた英語名**を分解して
`Welrod` + `Default` を得る。配布物そのものに書かれた値なので推測の余地がない。
日本語表記は `VERIFIED_JP_NAMES` に**確認できたものだけ**入れる(現状はヘレンのみ)。
推測で足さないこと。英語名が取れないものは配布元の中国語名をそのまま使い、勝手に訳さない。

### 壊れた名前の復元 — 「証拠がなければ触らない」

壊れ方は3種類ある。

- 型A: `\241\276` のような8進エスケープが文字として残った形 → 8進を戻して GBK で解釈
- 型B: GBK のバイト列を cp932 として読んでしまった形 → cp932 で戻して GBK で解釈
- 型C: 壊れていない

> [!warning] 初版のバグ(2026-07-26 に修正済み)
> 初版は**文字化けの証拠を確認せずに**型Bの変換をかけていたため、
> **既に正しい中国語名まで壊していた**(`夏安原皮` → `壞埨尨旂`)。しかも実フォルダ名を
> その名前へ改名していたので、ディスク上のフォルダ名10件が壊れた。
> 現在は `looks_mojibake()` で「8進エスケープがある」「半角カナがある」のどちらかが
> 無ければ**一切手を出さない**。壊れたフォルダは `02c-repair-folder-names.py` で、
> **配布 RAR の名前(正解)と突き合わせて一致したものだけ**戻した。

RAR5 は名前を UTF-8 で持つため、**RAR 側は文字化けしない**(`-e GBK` 指定は不要)。

> [!note] 02c は新規の文字化けには不要(2026-07-30 に確認)
> `02-catalog.py` の目録化ループ自体が `recover_name()` を呼び、型A/型Bの証拠があれば
> **その場でフォルダ名を直しつつ目録化する**(`02-catalog.py` 149〜160行目)。実際に
> Finder で作成した「選択項目から作成したフォルダ」由来の型A文字化け
> (`【少女前线2：追放】闪电（紫雨心）`)が、02実行だけで自動修復されるのを確認した。
> `02c-repair-folder-names.py` は**2026-07-26の旧バグでの誤変換を戻す専用**であり、
> 新規に届いた配布物の文字化け対応では通常不要。02実行後に `00_source/extracted/` を
> 目視して文字化けが残っていた場合のみ、下見(`--commit`無し)から検討する。

### ピンク一色になる問題 — テクスチャ参照の修復

Blender は「画像ファイルが見つからない」ときマテリアルを**ピンク一色**で描く。
初回構築では **66体中48体**がこれに該当していた。

原因は配布物側のデータ不備で、PMX のテクスチャ表に**ファイル名ではなくフォルダ名
`spa` だけ**が入っていた。参照先がフォルダなので永遠に読めない。

`repair_textures()` で2段階に処理する。

1. 配布フォルダ内を再帰的に探し、同名(大文字小文字と文字化けを無視)の画像が
   実在すれば繋ぎ直す。
2. 見つからなければ、その画像を使っているノードごと外して画像を捨てる。
   マテリアルは既定値に戻るのでピンクにならない。

結果: 繋ぎ直し2件 / 実体なしで除去68件 → **未解決0件**。
**2026-07-27、武田さんが Finder のサムネで実機確認し、色バグ(ピンク)は見当たらないと確認済み**
(詳細な全数目視までは行っていない旨、本人明言)。

### 出力はシリーズ(作品)ごとに分ける

`01_blend/` 直下に全部置くと作品が混ざって探せないため、`detect_series()` で
配布物名と PMX 名から作品を判定し、サブフォルダへ分ける。判定はパッケージ単位で行い、
同じ配布物の中で分かれないようにしている。

- `ドールズフロントライン2` 69体 / `崩壊スターレイル` 6体 / `二重螺旋` 5体 / `その他` 1体
  (2026-07-30 時点、計81体)

  `琳奈_泳装` — PMX 内蔵名が中国語のみでゲーム接頭辞が無く、判定材料が無いため)。

### 命名: 「原名のまま」のときは翻訳語を二重に足さない

2026-07-27、追加投入した `ﾁﾕﾄﾎ_ﾓｾﾗｰ`(文字化け復元後 `琳奈_泳装`)で発覚。
PMX 内蔵名が英語コードネームとして取れない(中国語のまま)場合、`to_japanese()` は
`base = source`(配布元名をそのまま採用)にする。ここへ `COSTUME_WORDS` の翻訳
(`泳装`→`水着`)を無条件で追加すると、**base に既に生の中国語 `泳装` が含まれているため**
`琳奈_泳装_水着` のように同じ意味が二重に出る。

英語コードネームが取れているとき(`base` が英語名になるとき)は、中国語の衣装語が
base に含まれないので翻訳追加が意味を持つが、「原名のまま」のときは常に冗長になる。
そのため `code` が取れているときだけ `COSTUME_WORDS` を追加するよう修正した。
既存68体中この分岐に該当したのは新規追加した1件のみで、既存の命名には影響なし
(適用前後で構築結果のキー集合が完全一致することを確認済み)。

### 照明: ヘレンの3灯構成は使わない

MMD のモデルは陰影をテクスチャに描き込み、さらにトゥーンの段で陰を付ける。
そこへ強い斜め光を足すと顔にまだらな明暗が出る(2026-07-26 にフローラで実際に発生)。
**広い環境光 + 段差を作らない非常に大きな前方フィル1灯**に変更した。
Blender 4.x 既定の AgX は色を淡くするので `Standard` に変更している。

### 編集済み法線(カスタム分割法線)を捨てる

ゲーム用キャラモデルは、元のゲームの描画方式に合わせて法線が手で編集してある。
フローラの実測値は **平均15.9度・最大177.9度ずれ・全体の14.5%が30度以上**。
Blender は光を物理的に計算するため、そのままだと顎・口元・額に斑点が出る。

取り込み後に `customdata_custom_splitnormals_clear()` で捨て、面の形から計算し直す。
全身で比べると髪や衣装の立体感はむしろ良くなる。
`CLEAR_CUSTOM_NORMALS = False` で元に戻せる。

> 武田さんの判断で調査を打ち切った。再開する場合は下の「調査で潰した範囲」から続けること。

## 顔の斑点(アザ状の模様)の調査記録

「顔にアザのような明暗が出る。視点を変えると形が変わる」という症状の切り分け。
**すべて実測**で、推測ではない。

| 疑ったもの | 結果 |
|---|---|
| テクスチャの欠け・破損 | シロ。8枚すべて解決。無地表示(Workbench FLAT)でも斑点なし |
| スフィアマップ(spa/sph) | シロ。**このモデルは1つも持っていない** |
| 輪郭線用の外殻 / Solidify | シロ。モディファイアはアーマチュアのみ |
| 面の完全な重なり(Zファイティング) | シロ。60,158面中28面のみ。頭部は12面 |
| フラットシェーディング | シロ。0面。シャープ辺も0 |
| ディザ透過のノイズ | シロ。サンプル1でも再現せず |
| トゥーンを無効化 | **斑点は残った** → 無関係 |
| **編集済み法線を消す** | **斑点が消えた**(私のレンダー上では) |

- ビューポートは既定でシーンのライトを使わない(画面に付いてくるスタジオ照明を使う)。
  これも一因の可能性があるが、レンダー表示に切り替えても斑点は残ったと報告されている。

## モデルを後から追加する手順(2026-07-27 に確立)

新しい RAR や展開済みフォルダが Downloads 等に届いたときの定型手順。

1. `python3 01-move-source.py <パス> [<パス>...]` で下見(コピーのみ)。
   欠け・不一致が0件であることを確認してから `--commit` を付けて再実行し、元データを消す。
2. `python3 02-catalog.py`(引数なし)。展開済みのものは自動でスキップされるので、
   何度実行しても安全。目録・要確認・変種グループが最新化される。
3. `python3 03-build.py`(引数なし)。`構築結果` に無い(＝未処理の)モデルだけを処理する。
   既存モデルは触らない。
4. `python3 06-audit-saved-blends.py -- --blend <保存先>` で保存後の未解決テクスチャを確認。
5. `python3 05-make-check-page.py` で確認ページを更新。

この手順で2026-07-27 に2体(`Sabrina_夏_水着`、`琳奈_泳装`)を追加し、
66体→68体になった。追加時に命名ロジックを1件修正しているが、**既存66体の
命名・ファイルは一切変化しないことを確認済み**(構築結果のキー集合を追加前後で比較して一致)。

**武田さんの実機確認(2026-07-27)**: `01_blend/` 配下のサムネイルを確認し、
`Sabrina_夏_水着.blend` はファイルを開いて中身も確認、問題なしと回答。
`琳奈_泳装.blend` はサムネ確認のみ(単体で開いての確認は未実施)。
