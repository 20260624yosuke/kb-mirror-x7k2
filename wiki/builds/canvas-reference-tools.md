# Canvas参照ツール

## 現在の統合見解

Canvas参照ツールは、Obsidian Canvas を PureRef 代替の参照画像ボードとして使いやすくするための自作 Obsidian プラグイン。2026-07-14 時点では v0.5.25 系として以下を実装済み。

- Canvas のズーム範囲を拡張する。
- Canvas 画像ノードを、元画像ファイルを変更せず表示上だけ左右反転する。
- Canvas 画像ノードを、元画像ファイルを変更せず表示上だけ回転する(15度/90度コマンド + 選択時の四隅回転ハンドル + AABB 枠自動調整)。
- Canvas 画像ノードを、元画像ファイルを変更せず表示上だけ切り取る(**C キーを押しながらドラッグで範囲指定**。選択中の単一画像が対象で、画像の外からドラッグ可。解除は Cmd+Shift+C)。v0.5.2 では、v0.5.1 の誤修復値も含め、切り取り後の画像が後から元画像比率へ戻されて伸びる問題を修正。
- **クロップ済み画像の回転**にも対応(v0.4.6、方向1)。v0.4.9 では、複数選択でまとめてサイズ変更した時も、選択中の回転画像すべてがサイズ変更に追従するよう修正。2026-06-17 に武田さんが実機確認し、「とりあえず不満はない。見つけたら報告」と記録。回転済み画像のクロップ(方向2)は未実装。
- 選択ノードの複製、標準 Cmd+C での内部コピー、カーソル位置への Cmd+V 貼り付け。
- 画像ノード1つの Cmd+C で、**外部アプリ(クリスタ等)へ貼れる PNG**(反転・回転・切り取りを
  反映した見たまま)を macOS の共通クリップボードへ書き込む。Obsidian とクリスタを直接
  接続する専用処理ではなく、画像クリップボードを読める他アプリにも渡せる方式。
- 画像ノード選択中の**スペースキーで画面いっぱいに拡大表示**し、もう一度スペースで元の表示へ戻す(v0.4.5 でスペースのパンは無効化)。
- **Opt(Alt)+ドラッグでキャンバスをパン**する(PureRef と同じ操作感。スペースのパンと拡大の競合を解消、v0.4.5)。
- 選択画像ノードの**高さ揃え**(選択中の最大画像基準・縦横比維持)、**横一列整頓・縦一列整頓・左端揃え・追加順グリッド整頓・詰めグリッド整頓**(v0.5.16〜v0.5.17 で追加順グリッド/詰めグリッドを追補。間隔は v0.5.20 で設定値化・既定0px・中央揃え)。整頓・つなぎ線とも画像だけでなく動画ファイル(mp4等)を含む「メディアノード」を対象にする(v0.5.16〜v0.5.17 でメディア対応)。
- 選択画像ノードを**テキストへ線でつなぐ**(v0.5.7)。画像を選んでコマンド/右クリック → 次のクリックでつなぎ先を指定(テキスト=そこへ / 空白=空テキスト新規作成)し、各画像 → テキストの矢印つき edge を Canvas に追記する。グループ枠(位置で所属判定)と違い、ノードを動かしても線は追従する。2026-07-04 に武田さんが v0.5.15 環境で実機確認し、問題なし。
- Canvas テキストノードのボックスサイズに合わせて文字サイズを自動拡縮する。
- Canvas 右クリックメニューから機能とショートカットの説明を開く。
- 重い Canvas から `__light.canvas` と `_attachments_light/` を生成する。
- `__light.canvas` を作業正本にして、コマンド `このlight Canvasを原寸同期して軽量化` で
  light版の原寸混在画像を軽量化し、元 `.canvas` を原寸ミラーとして更新する。既存ペアの初回移行では、
  light側だけの追加がなく元Canvasの方が新しい場合に限り、元Canvas側の追加・既存ノード差分を light版へ取り込む。
- `light Canvas同期状態を検査` で `raw/_MY_ART` 配下の light ペアの差分を一覧確認できる。
- **MY-ART Canvas ギャラリー**(v0.5.8〜、正本 [[myart-canvas-gallery]]): MY-ART の全 Canvas を
  「最後に開いた窓の見た目」のサムネで一覧し、クリックで開く。窓を閉じてもギャラリーから呼び戻せる
  ようにして、デスクトップ4のメモリ圧迫を解消するための機能。サムネは Electron `capturePage` の
  実描画スナップショット、Canvas から離れた/閉じた瞬間に自動更新。2026-07-14 時点で
  **更新順 / 名前順 / 追加日順の並び替え**にも対応し、武田さん実機で動作良好を確認済み。
- ユーザーに見えるプラグイン名・通知・設定・右クリックメニューは日本語表記にする。
- **右クリックメニューをジャンル別サブメニュー化**(v0.5.20 で1項目へ集約 → v0.5.21 でジャンル別の入れ子サブメニューへ再編)。プラグインの全項目を「Canvas参照ツール」1項目の中へ集約したうえで、その中を「整頓」「画像加工」「線つなぎ」「light Canvas」の4ジャンルへ分け、複製・テキスト枠追従・ヘルプは直下に残す(Obsidian内部 API `MenuItem.setSubmenu()` を使用。文言・アイコン・実行内容は変更なし)。武田さんの実機フィードバック「25項目が1階層に並んで目をこらすのがだるい」を受けた再編。**2026-07-10、武田さんが実機確認し「動作してます」と報告(実機確認済み)**。
- **Cmd(⌘)+クリックで複数選択**(v0.5.20 で実装 → 実機で不動作と判明し v0.5.21 で修正)。標準の Shift+クリック追加選択を残したまま、Cmd+クリックでもノードをトグル追加/除去できる。設定 `enableCmdClickSelect`(既定 true)。**2026-07-10、武田さんが実機確認し「動作してます」と報告(実機確認済み)**。
- **ノード作成日時(createdAt)の記録**(v0.5.20。2026-07-10 に武田さんの実 Canvas で全ノード付与を機械確認・実機確認済み)。新規作成・貼り付け・ドロップ・複製したノードに日本時間の作成日時を .canvas へ記録する。表示UIはなく、LLM が .canvas JSON を読んだ時に時間軸で推論するための記録専用。既存ノードへの遡及付与はしない。設定 `enableCreatedAtStamp`(既定 true)。
- **ズームアウト時のテキスト消失**は、プラグイン側の実装なしで Obsidian 本体のコア設定「カード内容を隠すズームの閾値」スライダーを最大にするだけで解決することを2026-07-10に武田さんが実機確認(詳細は「既知の問題・保留」参照)。
- **Obsidian 終了停止対策**(2026-07-12): macOS 再起動/終了時に Obsidian 本体プロセスが残る問題を調査。`canvas-reference-tools` 無効、全コミュニティプラグイン無効、空 vault でも 70秒以上残ったため、主因は本プラグイン単体ではなく Obsidian 1.12.7 / Electron / macOS 側の終了承認後停止と判断。運用対策として、アプリ終了開始時だけ外部の終了ガードを起動し、通常終了が完了しない場合だけ残存プロセスを片付ける処理を追加。実装後、この vault では通常終了が2秒で完了することを確認。詳細は「検証」節の 2026-07-12 エントリ。

実装先:

- `.obsidian/plugins/canvas-reference-tools/`
- `manifest.json` の plugin id: `canvas-reference-tools`
- version: `0.5.25`
- desktop only: `true`

## 機能

### ズーム範囲拡張

Obsidian Canvas の内部 `tZoom` クランプを拡張する。ローカル Obsidian 1.12.7 では、Canvas の既定クランプは log2 値で `-4..1`、実倍率で `1/16..2x`。

実装方針:

- `requestFrame()` と touch pinch 側の `Math.clamp(tZoom, -4, 1)` を、`monkey-around` で限定的に差し替える。
- `zoomToBbox()` は線形スケール値を clamp してから `Math.log2()` しているため、個別 override で `2^minZoomExp..2^maxZoomExp` を使う。
- `requestFrame.toString()` が期待する内部実装と合わない場合は、ズーム patch を無効化して Notice を出す。

設定:

- `enableZoomPatch`: 既定 true
- `minZoomExp`: 既定 `-8`、実倍率 `1/256x`
- `maxZoomExp`: 既定 `4`、実倍率 `16x`

ユーザー確認:

- 2026-05-30、武田さんが「拡大縮小の機能はいい感じ」「直感的な操作で確認できた」と確認済み。

### 画像ノード左右反転

Canvas の画像 file node を表示上だけ左右反転する。元画像ファイルは変更しない。

実装方針:

- コマンド `選択したCanvas画像ノードを左右反転` を追加。
- 対象は `type: "file"` かつ画像拡張子の Canvas node。
- 反転状態は `.canvas` の該当 node に `flipX: true` として保存する。
- 再実行で `flipX` を削除し、通常表示へ戻す。
- DOM では `node.nodeEl` に `canvas-reference-tools-flip-x` class を付け、CSS で画像要素だけ `scaleX(-1)` にする。

現在のショートカット:

- `canvas-reference-tools:toggle-selected-canvas-image-flip-x`
- `Mod + Shift + E`

ユーザー確認:

- 2026-05-30、武田さんが左右反転の実行に成功。

### 右クリックヘルプ

Canvas 右クリックメニューに以下を追加。

- `Canvas参照ツール: 選択画像を左右反転 (<現在のホットキー>)`
- `Canvas参照ツール: 機能とショートカット`

ヘルプモーダルでは、機能概要、現在のショートカット、保存先、現在のズーム範囲を表示する。ショートカットは Obsidian 内部の `hotkeyManager.printHotkeyForCommand()` から現在値を読む。

ユーザー確認:

- 2026-05-30、武田さんが「使用感いい」と確認済み。

### 画像ノードの切り取り(C キーを押しながらドラッグ。v0.4.6 で C+ドラッグへ戻し、クロップ+回転に対応)

画像ノードを1つ選び、**C キーを押しながらドラッグ**すると、その範囲だけを残して周囲を表示上切り落とす(PureRef の crop と同じ見え方)。元画像ファイルは変更しない。

操作の要点(v0.4.3〜v0.4.6 で変遷):

- **C を押しながらドラッグ**(v0.4.6)。v0.4.3〜v0.4.5 は「一度押して待機 → ドラッグ」式だったが、武田さんの希望で押しっぱなし式へ戻した。押している間はクロスヘアカーソルを出す。キー不要の右クリック「切り取り(ドラッグで範囲指定)」コマンドは一発待機として残す。
- **切り取り対象は「選択中の単一画像」**(v0.4.5)。ドラッグ開始位置を問わず、**画像の外からドラッグを始めてよい**(`getSingleSelectedImageNode` を優先し、単一画像選択でない時だけ従来の座標ヒットテスト `resolveCropTargetNode` へフォールバック)。ドラッグ点は 0..1 にクランプされるため、画像外から始めた範囲は自動で画像の縁に収まる。
- **ドラッグ中の見た目**: 残す範囲(内側)は明るいまま、捨てる範囲(外側)を box-shadow の暗幕で沈める(v0.4.4。画像ノード内にクリップするので他の画像は暗くならない)。さらに**ドラッグ枠線(2px アクセント色)は画像の外まで伸びる**(v0.4.5。`body` にクライアント座標 `position: fixed` で描画し、ズーム倍率で太さが変わらない)。
- **解除/元に戻す**は `Cmd/Ctrl+Shift+C`。Obsidian 本体のホットキーが効かない環境があるため、window 捕捉の keydown で**プラグインが直接処理**する(v0.4.3。本体より先に走り、`stopImmediatePropagation` で二重発火も防ぐ)。C キー不要の右クリック「切り取り(ドラッグで範囲指定)」コマンドからも待機を開始できる。

データモデル・描画(v0.4.0 から不変):

- 保存キー: `cropFracX / cropFracY / cropFracW / cropFracH`(元画像に対する表示範囲、0..1 の分数)。
- 確定時にノード枠をドラッグ矩形へ縮め、画像はその場に固定表示のまま周囲が消える。
- 切り取り済み画像を再度 待機 → ドラッグすると、表示中の範囲からさらに絞り込む(分数を合成)。
- 左右反転中は、表示座標 ↔ 元画像座標の X 軸鏡映変換を確定・描画・解除の全経路で挟む
  (`src/crop-math.ts` に純粋関数として分離し、単体テストで往復一致を固定)。
- 解除はコマンド `選択したCanvas画像ノードの切り取りを解除`(既定ホットキー `Mod+Shift+C`)。
  枠を元画像全体へ広げ直し、分数キーを削除する。
- 描画は content `overflow: hidden` + img 絶対配置(width/height/left/top の CSS 変数 4 つ)。
- `node.aspectRatio` を切り取り後の比率へ差し替え、描画同期のたびに再設定する(再起動対応)。
- Esc で中断。8px 未満の極小ドラッグはクリック扱いで無視。回転中の画像は切り取り不可(Notice)。
- 切り取り待機状態はウィンドウ非アクティブ・タブ非表示で必ずリセットする(待機の取り残し防止)。

### 画像ノードの回転

選択した画像 file node を表示上だけ回転する。元画像ファイルは変更しない。

実装方針(v0.3.0 で 90 度単位から拡張):

- コマンド: 右/左に15度回転、右に90度回転、回転を解除。
- 単一選択時はノード四隅に回転ハンドルを表示(Shift で 15 度スナップ)。
- 保存キー: `rotation` + `rotationBaseWidth` / `rotationBaseHeight`。
- 回転後の画像全体が入る AABB へノード枠を自動調整する。
- **クロップ済み画像の回転に対応**(v0.4.6、方向1)。クロップ枠ごと回転する合成描画(`src/node-visuals.ts` の `crop-rotate-active` クラス + `src/styles.css`)。逆方向(回転済み画像のクロップ=方向2)は未実装で、回転中の画像のクロップはガードで止めている。
- 複数選択リサイズ時にも、選択中の回転画像ごとにリサイズ・セッションを開始し、終了時に `rotationBaseWidth/Height` を更新する(v0.4.9)。

### 画像ノードの整頓(高さ揃え / 横一列 / 縦一列。v0.4.0 で旧グリッド整頓を置換)

- コマンド `選択したCanvas画像ノードの高さを揃える`: 選択中で一番大きい画像の高さに、
  縦横比を保ち中心固定で拡縮。回転ノードは AABB と rotationBase を同率拡縮。
- コマンド `…を横一列に整頓`: 現在の x 順(同値は y 順)に、選択範囲の左端から間隔 0px で連結。
  上下は選択範囲の垂直中央揃え。
- コマンド `…を縦一列に整頓`: y 順に上端から連結、左右中央揃え。
- コマンド `…を左端に揃える`: 行検出 → 行内左詰め(v0.5.0 追加)。
- コマンド `…を追加順に並び替え`(グリッド)/ `…を選択範囲に収めて再配置`(詰めグリッド): v0.5.16〜v0.5.17 で追加(本ページ未記載だった分を2026-07-09に追補)。追加順グリッドは `.canvas` ファイル内のノード出現順、詰めグリッドは選択範囲の外接矩形に収まるよう再配置する。
- レイアウト計算は `src/arrange-math.ts` に純粋関数として分離し、単体テストで固定。
- 整頓の間隔は `arrangeGap` 設定(既定 `0`px、v0.5.20)で全コマンド共通に変更できる。旧固定値 `ARRANGE_GAP = 24` を置換。

### 右クリックメニューのジャンル別サブメニュー化(v0.5.20で1項目へ集約 → v0.5.21でジャンル分け)

プラグインの右クリック項目が増えたため、既定を「詰め詰め(隙間0px)」へ変えたタイミングで全項目を1つのサブメニューへ集約した(v0.5.20)。実機フィードバックで「1階層に25項目が並んで目をこらすのがだるい」と指摘を受け、v0.5.21 でジャンル別の入れ子サブメニューへ再編した。

実装方針:

- `src/context-menu.ts`: `Menu.addItem()` で作った項目に対し、Obsidian 内部 API `MenuItem.setSubmenu()`(公式 `obsidian.d.ts` には型定義がないが、`app.js` 実装で存在確認済み。モバイル用サブメニュー描画に本体自身が使っている)を呼び、返る `Menu` へ項目を追加する汎用ヘルパー `createSubmenu(parentMenu, title, icon)` を用意。
- トップの「Canvas参照ツール」サブメニューの中を、`createSubmenu` で以下の入れ子サブメニューへ分割(v0.5.21):
  - **整頓**(6項目): 高さ揃え / 横一列 / 縦一列 / 左端揃え / 追加順グリッド / 詰めグリッド
  - **画像加工**(7項目): 左右反転 / 右15度 / 左15度 / 右90度 / 回転解除 / 切り取り開始 / 切り取り解除
  - **線つなぎ**(6項目): 自動方向 / 上辺 / 右辺 / 下辺 / 左辺 / 接続辺を最短に再計算
  - **light Canvas**(3項目): 軽量版生成 / 原寸同期 / 同期状態検査
  - 直下に残す: 選択ノードを複製 / 選択テキストを枠に追従 / ヘルプ
- ジャンル名(整頓/画像加工/線つなぎ/light Canvas)は仮の既定案。武田さんに実機で違和感があれば文字列変更のみで直せる構造。
- 項目の文言・アイコン・実行内容は変更しない(場所の整理のみ)。
- **2026-07-10 実機確認済み**: 武田さんが実機で「動作してます」と報告。入れ子サブメニューはホバー展開する(フォールバック不要)。

### Cmd(⌘)+クリックで複数選択(v0.5.20で実装 → v0.5.21でclick介入を追加修正)

武田さんの慣れである Cmd+クリックでの追加選択を、Obsidian 標準の Shift+クリックに加えて使えるようにした。

実装方針(`src/cmd-click-select.ts`。`src/pan.ts` と同じ capture pointerdown 様式):

- Obsidian `app.js` の実装確認(推測ではない): `CanvasNode.onPointerdown` は常に `canvas.handleSelectionDrag(event, nodeEl, node)` を呼び、その内部で「掴んだノードが未選択なら `selectOnly(node)`」を無条件に実行する。この処理は Shift/Cmd の判定より先に走るため、Cmd+クリックを「追加選択」として成立させるには、pointerdown の時点で本体の処理自体を止める必要がある。
- アクティブ Canvas の `wrapperEl` に capture の pointerdown を登録し、`event.metaKey` かつ一次ポインタ・左ボタン・ヒットしたノードがある時だけ `preventDefault + stopPropagation` で本体の pointerdown を止め、`canvas.toggleSelect(node)`(Obsidian 内部 API、`app.js` で `add/delete` によるトグル実装を確認済み)を直接呼ぶ。
- ヒットテストは `connect-to-text.ts` の `findNodeByEl`(export化して共有)を流用。
- 調査の結果、Canvas 内で metaKey(Cmd)を使う既定動作は他に見つからなかった(ドラッグ中の複製は Mac では altKey)。そのためこの機能が Cmd+ドラッグ等の別の既定動作と衝突する既知のケースはない。
- 設定トグル `enableCmdClickSelect`(既定 true)。

**v0.5.21 の不動作修正**: v0.5.20 は実機で「動作していない」と報告された。原因を `app.js` で特定 — pointerdown の `preventDefault` は、同じ操作から発火する**後続の click イベントを止めない**(ブラウザ仕様)。Obsidian の `nodeEl` には別途 `addEventListener("click", onClick)` が張られており、`onClick` は `e.shiftKey ? toggleSelect(this) : selectOnly(this)` を実行する。metaKey は shiftKey ではないため、pointerdown 側で `toggleSelect` した直後にこの click ハンドラが `selectOnly` で単独選択へ上書きしていた。対策として、同じ `wrapperEl` に capture の **click リスナー**も追加し、metaKey かつノード命中時は `preventDefault + stopPropagation` で本体の click ハンドラ自体を止める(選択トグルは pointerdown 側で完了済みなので、click 側は「止めるだけ」)。dblclick は別イベントのため影響なし。**2026-07-10、武田さんが実機確認し「動作してます」と報告(実機確認済み)**。

### ノード作成日時の記録(createdAt、v0.5.20)

LLM が `.canvas` JSON を読んだ時に、ノードのつながりに加えて時間軸でも推論できるようにするための記録専用メタデータ。表示UIはない。

実装方針:

- `src/created-at.ts`: `formatJstTimestamp`(UTC→JST `+09:00` 固定オフセットへ変換する純粋関数)と `withCreatedAtStamp`(`createdAt` が無い場合のみ付与する純粋関数)を単体テストつきで分離。
- `src/node-visuals.ts` が既に `canvas.addNode` を monkey-around で patch している(反転・クロップ等を貼り付け/ドロップ直後のノードへ適用するため)ため、同じフックに `stampNodeCreatedAt` を相乗りさせた。この addNode patch は貼り付け・ドロップ・複製を含む新規ノード全経路で発火することが、既存の反転/クロップ適用が実機で機能している事実から裏付けられている。
- 既存ノードには付与しない(「無い場合のみ付与」の判定で自然に満たす)。Undo で消えたノードを Redo で戻した場合も、保存済みデータに元の `createdAt` が残っているため上書きされない。
- light Canvas 同期(`src/canvas-light-sync-model.ts`)は `deepClone` でノードデータを丸ごと複製する実装(未知キーの whitelist なし)のため、`createdAt` は追加対応なしでそのまま生き残ることをソース確認済み。
- 設定トグル `enableCreatedAtStamp`(既定 true)。

### 外部アプリ用の画像コピー(v0.4.0)

画像 file node を1つだけ選んで Cmd+C すると、Canvas 内部用の情報に加えて、表示中の見たまま
(反転・回転・切り取り反映)を元解像度基準で描画した PNG をクリップボードへ書き込む。
クリスタ等へ Cmd+V で貼り付けできる。

**方式の確認(2026-06-15)**: この機能は Obsidian からクリスタへ直接送る専用連携ではない。
実装は macOS の共通クリップボードへ画像を書き込む方式であり、外部アプリ互換性を持たせる
という目的はすでに満たしている。大規模な方式変更は不要。現在は Canvas 内部貼り付けも維持する
ため、画像と同時にマーカー付き JSON のテキストも保持している。

実装方針:

- Canvas 本体のコピーは `obsidian/canvas` 独自形式のみで画像を含まない(Obsidian 1.12.7 の
  内部実装を確認済み)。そこで copy 完了直後に、Electron `clipboard.write({ image, text })` で
  「PNG + マーカー付き JSON(`{"crtClipboard":1,"canvas":{...}}`)」の 2 形式へ差し替える。
  Electron 不可時は `navigator.clipboard.write` へフォールバック、それも失敗時は従来のまま + Notice。
- Canvas 本体のペーストは「①ファイル → ②obsidian/canvas → ③テキスト」の優先順のため、
  そのままだと PNG が新規添付として保存されてしまう。`handlePaste` パッチの冒頭でマーカー付き
  JSON を検出し、複製と同じ `cloneData` + `importData` 経路で取り込む(内部ペースト両立)。
- コピー連打時は連番トークンで最新コピーだけを書き込む。カット(Cmd+X)でも同様に動く
  (シリアライズ済みデータから描画するため、ノード削除後でも安全)。
- 複数選択・画像以外の選択は従来どおり内部コピーのみ(複数画像の合成コピーは対象外)。
- 副作用: テキストエディタへ Cmd+V すると JSON 文字列が貼り付く(従来は何も貼れない)。仕様。

### スペースキーで選択画像を拡大表示(v0.4.0)

画像 file node を含む選択がある時にスペースを押すと、選択画像群の外接矩形を画面いっぱいに
表示する。もう一度スペースで元の表示位置へ戻る(トグル)。

実装方針:

- 各ウィンドウの window に capture で keydown を監視(本体がキー伝播を window 段で止めるため document では届かない)。発動条件は「修飾キーなし + アクティブ Canvas にフォーカス + テキスト編集中でない」。
- **v0.4.5 から、スペースのネイティブパンを常に無効化**する。canvas フォーカス中・テキスト編集でない時は、選択の有無にかかわらず preventDefault + stopImmediatePropagation で本体のスペースパンを抑止する。画像を選択していれば拡大トグル、未選択なら何もしない(拡大もパンもしない)。パンは Opt+ドラッグへ一本化(`src/pan.ts`)。
  - 旧仕様(v0.4.0〜v0.4.4): 未選択時はイベントに触れず、従来のスペース+ドラッグのパンが生きていた → v0.4.5 で廃止(スペース拡大とスペースパンの競合を解消)。
- ズームは選択画像の外接矩形 → 既存の `zoomToBbox` パッチ経路。復帰は `tx/ty/tZoom` の保存値。
- 「同じ選択のまま、拡大位置から動いていない時だけ戻る」判定(選択IDとビューポート近似比較)。
  別の画像を選び直してスペースを押した場合は、そちらへの拡大として扱う。

### キャンバスのパン(Opt+ドラッグ。v0.4.5)

`Opt(Alt)` キーを押しながら左ドラッグでキャンバスを移動(パン)する。PureRef と同じ操作感。スペースのパンを無効化した代わりの主パン手段。

実装方針(`src/pan.ts`):

- アクティブ Canvas の `wrapperEl` に capture で pointerdown を登録。`event.altKey` かつ一次ポインタ・左ボタンの時だけパン開始(テキスト編集中は除外)。preventDefault + stopPropagation で Obsidian の Alt 既定動作も抑止。
- 換算式は**推測ではなく** `zoom-limits.ts` の `zoomToBbox` 実装から確定。`tx/ty` は「ビューポート中心のワールド座標」、scale = `2^tZoom`(画面px/ワールド単位)なので、画面で指が `dx` 動いたら `newTx = startTx - dx/scale`(`ty` も同様)。pointermove で `tx/ty` を更新し `zoomCenter` を null にして `markViewportChanged()`。
- 遅延読み込みタブ(about:blank の仮文書)には登録しない。設定 OFF・プラグイン終了で全リスナーを解除。
- 設定トグル `enablePan`(既定 true)。

### テキストノードの自動拡縮

選択した text node に対して、その時点のボックスサイズを基準値として保存し、以後のリサイズ時に文字サイズを調整する。

実装方針:

- コマンド `選択したCanvasテキストノードの自動拡縮を切替` を追加。
- 保存キー: `textAutoScale`, `textScaleBaseWidth`, `textScaleBaseHeight`
- `CanvasNode.setData()` patch 後に `contentEl.style.fontSize` を更新する。
- フォントサイズは基準サイズに対する `width` / `height` の小さい方を使い、極端な値を避けるため `0.35..6` に clamp する。

### 選択画像をテキストへ線でつなぐ(v0.5.7)

画像ノードを1つ以上選び、コマンド/右クリックで起動すると「つなぎ先クリック待ち」モードに入る。次の左クリックでつなぎ先を決める。武田さんの要望は「コマンド実行後にテキストをクリックして指定」する方式。

操作:

- **テキストノードをクリック** → その指定テキストへ、選択中の各画像から矢印つき edge を引く。
- **空白をクリック** → その場に空テキストを新規作成(中心をクリック位置に合わせる・作成後 focus)し、各画像からその新規テキストへ edge を引く(mode 2 を内包)。
- **画像など他ノードをクリック** → 誤爆させず案内だけ出して武装を維持。
- **Esc / ウィンドウのフォーカス喪失** → 中止。

実装方針(`src/connect-to-text.ts`):

- 同時に1つだけの「武装セッション」。武装時に選択されていた画像ノードは **id で保持**し、クリック解決時に `canvas.nodes` から引き直す。
- `wrapperEl` に capture で pointerdown を登録し(crop と同じ様式・`AbortController` + `registerCleanup`)、掴んだクリックは `preventDefault + stopPropagation` で Canvas 側の選択/ドラッグを抑止。ヒットテストは `event.target.closest(".canvas-node")` → `canvas.nodes` から一致ノードを探す。
- 空白クリック時のテキスト生成は `canvas.createTextNode({ pos, size, text: "", save: true, focus: true })`。`pos` は `posFromClient(client)` から中心合わせで算出。
- edge は各画像について `{ id, fromNode: 画像, fromSide, toNode: テキスト, toSide, fromEnd: "none", toEnd: "arrow" }`。接続辺(`fromSide/toSide`)は画像中心とテキスト中心の位置関係から一番自然な辺を選ぶ。矢印は画像 → テキスト向き(要望どおり)。
- Canvas への追記は `canvas.importData({ nodes: [], edges }, false)` +
  `requestSave()` + `requestFrame()`。`clearBefore=false` で既存ノード/エッジを消さず、edge の端点は Canvas 全体の node マップから解決される(複製/貼り付けと同じ経路)想定。
- 設定トグル `enableConnectToText`(既定 true)。

**実機確認済み(2026-07-04)**: `importData({nodes:[], edges}, false)` で既存ノードを端点とする edge が実際に生成・描画され、画像やテキストを動かしても追従することを武田さんが v0.5.15 環境で確認済み。

### ズームアウト時にテキストが消える(2026-07-09 調査 → 2026-07-10 本体設定変更で解決確認済み)

- **症状**: Canvas をズームアウトすると、テキストノードの内容が表示されなくなる。
- **調査結果(Obsidian `app.js` のソース確認。推測ではない)**:
  1. **消している処理**: `CanvasNode.render()` が `this.updateBreakpoint(zoom > canvas.zoomBreakpoint || isEditing)` を呼び、閾値を下回ると `unmountContent()` が走る。これは CSS での縮小表示ではなく、**カード内容の DOM 自体を取り外す**パフォーマンス最適化(ノード数が多い Canvas での描画負荷軽減)。
  2. **`zoomBreakpoint` は Obsidian 本体の既存設定で、実は既にユーザーが調整できる**: `Canvas.zoomBreakpoint`(getter)= `内部基準値 - 設定値`。設定値は Obsidian の設定画面「Canvas」(コアプラグイン設定)内の **"Zoom threshold for hiding card content"**(スライダー、既定 `0`、範囲 `-0.7〜2.4`、説明文「Lower values will increase performance but hide card content sooner when zooming out.」)。この値を上げるほど、より広くズームアウトしてから初めて内容が消えるようになる。日本語UIでの表示文言は未確認(英語版の文字列で特定)。
  3. **プラグインから安全に介入できるか**: 本体の公式・表示設定として既に存在するため、プラグイン側でパッチする前に、**まずこの設定を試すのが最も低リスクかつ工数ゼロ**。既存の `zoom-limits.ts` のような限定 patch は、この件では不要と判断(本体設定で解決する可能性が高いため)。
  4. **設定で足りない場合の打開案(未実装・効果と危険度)**:
     - a. 設定スライダーを最大 `2.4` まで上げる(危険度なし。トレードオフ: 本体の説明どおり、ノード数が多い巨大 Canvas では描画コストが上がる可能性)。
     - b. プラグインから `zoomBreakpoint` 設定値を強制的に上書きする patch(内部 API 直接操作。バージョンアップで壊れるリスクがあり、ユーザーが GUI で調整できる値をプラグインが上書きする設計のねじれもあるため非推奨)。
     - c. カード内容自体が DOM から外れるため、CSS だけでのオーバーレイ表示は不可(要素が無い)。別途「ズーム時だけ表示する独立ラベル要素」を作る実装が必要になり、工数が大きい。
- **状態**: 実装なし(武田さん指定どおり調査のみ)。2026-07-10、武田さんから「まず本体設定で試したいが操作がわからない」と要望があり、以下の手順を案内した(実装なし・案内のみ):
  1. Obsidian 左下の歯車(設定)をクリック
  2. 左の一覧の下の方「コアプラグイン」の中の **Canvas** をクリック
  3. **「カード内容を隠すズームの閾値」** というスライダーを探す
  4. スライダーを**右端(最大)**までドラッグ
  5. 設定を閉じて Canvas でズームアウトして確認(既定 `1/3.2倍` 付近 → 最大設定で `1/17倍` 付近まで文字が残るはず)
  それでも不足する場合に (b)/(c) を次ラウンドで検討。**2026-07-10、武田さんが上記手順で設定変更し「検証した」と確認済み。本体設定の変更だけで解決し、プラグイン側の実装(b/c)は不要と確定**。

### 純粋クロップ画像が後から元画像比率へ戻り、伸びて表示される(2026-06-26 v0.5.2で再修正)

- **症状**: 回転を含まない通常の切り取り画像で、切り取り直後は正常でも、後からノード枠が元画像の縦横比へ戻り、画像だけが細長く伸びて表示される。
- **確認事実**: 対象 Canvas `raw/_MY_ART/2026_06/2026_06_02_アイドルxアスナx立ち絵_01/2026_05_30_アスナxアイドル衣装.canvas` では、`cropFracW/H` を持つ画像ノード11件中10件で、保存された `width/height` が切り取り後に必要な比率ではなく元画像寄りの比率になっていた。例: `画像 5.jpg` の file node `cfc3b5addc379c7d` は現在比率0.581だが、元画像比率と切り取り範囲から必要な比率は1.538。
- **原因**: 切り取り状態として `cropFracX/Y/W/H` だけを保存し、元画像の縦横比を保存していなかった。また切り取り確定時に、Obsidian 側の画像ノード比率制約が元画像比率のまま残り、ノード枠が後から元画像比率へ戻される経路があった。
- **v0.5.1 の不足**: 画像の自然サイズを読めない瞬間に、壊れた現在のノード比率から `cropBaseAspectRatio` を作って保存してしまった。そのため `f24170b5dda0fc6f` や `c063db0fd3823374` では誤った `cropBaseAspectRatio` が残り、伸びたままだった。
- **修正(v0.5.2)**: 保存済み `cropBaseAspectRatio` があっても画像の自然サイズを優先する。自然サイズが読める場合は、v0.5.1 が保存した誤値を上書きし、既存の壊れた切り取りノードを正しい枠比率へ自動修復する。自然サイズが読めない場合は、壊れた現在のノード比率から新しい基準値を作らない。
- **状態**: 実装済み・自動試験済み・ビルド済み・ユーザー実機で目視改善確認済み。ただし、読み込み直後は一時的に伸びたまま表示され、その後プラグイン確認中に自然に修復された。遅延修復の発火タイミングは未確定 → **2026-07-07 に発火タイミングを特定**(下の節)。
- **追記(2026-07-07、v0.5.19)**: 武田さんの観察「選択したまま他 Canvas をアクティブにして戻すと歪みが直る」から、修復処理(`patchOpenCanvases` → 全ノード `applyNodeVisuals`)の発火が `active-leaf-change` / `layout-change` の2イベントに限られていたことがソース上で確定。Obsidian 本体がプラグインのフックを通らず枠比率を戻す・画像要素を作り直すと、次のタブ切替まで歪みが放置されていた。v0.5.19 でクロップ中ノードに ResizeObserver(枠サイズ変化)+ MutationObserver(img 差し替え)の見張りを付け、歪んだ瞬間に自動同期するよう修正。歪みの引き金(枠リセット説 vs 部品作り直し説)の実測特定はしていないが、どちらも見張りで拾う設計。

### 回転+クロップ画像のサイズ変更で画像が伸びる(2026-06-14 見送り、2026-06-16 複数選択経路を修正)

- **症状**: クロップ → 回転(ここまでは正常表示)→ ノードのサイズ変更ハンドルを操作すると、クロップが外れて元画像が旧クロップ枠の寸法に押し潰され、画像が伸びて見える。

- **プラグイン側の調査**: クロップ削除は `clearNodeCrop`(Cmd+Shift+C 経由)でしか起きず、リサイズ経路では呼ばれない。回転リサイズ・セッションの setData は `...data` でクロップを引き継ぐ。→ **Obsidian 本体のリサイズ処理が cropFracW/H を落としている**と推定(ただし未確認)。
- **試した対策(いずれも武田さん環境で改善せず)**:
  - v0.4.7: 合成描画の img を「%指定」→「固定px指定」へ(content の実寸変化で歪まないように)。
  - v0.4.8: 回転リサイズ・セッション開始時に cropFractions を控え、終了時にデータへ書き戻し + 描画フォールバック。
  - v0.4.9: 複数選択リサイズでは `selectedNodes.length !== 1` の条件で回転リサイズ・セッションが開始されず、`syncRotationLayout` が保存済みの回転前サイズから旧 AABB へ戻していた。選択中の回転画像すべてにセッションを開始するよう修正。

### Obsidian 終了後に本体プロセスが残る(2026-07-12 調査、終了ガードで運用対策済み)

- **症状**: `osascript -e 'tell application "Obsidian" to quit'` で通常終了を送っても、AppKit 側では `applicationShouldTerminate:YES` と `App termination approved` が出た後、Obsidian 本体プロセスが70秒以上残る。Renderer は落ち、親プロセス/GPU/network utility だけが残る形だった。
- **当初仮説**: MY-ART Canvas ギャラリーの `window-close` 時サムネ再撮影、特に Electron `capturePage` と PNG/index 保存が終了を止めている可能性を第一候補にした。計画レビューでは、通常終了ログだけでは瞬間を取り逃がすため、終了前からプロセス・macOSログ・必要時 sample を観測する方針へ修正。
- **切り分け結果**:
  - `canvas-reference-tools` だけを無効化しても、20秒超過で sample、70秒後も残存。
  - 全コミュニティプラグインを無効化しても、20秒超過で sample、70秒後も残存。
  - 一時の空 vault でも、20秒超過で sample、70秒後も残存。
  - したがって、`canvas-reference-tools` 単体・この vault の中身・コミュニティプラグイン群は主因ではない。現時点の見立ては、Obsidian 1.12.7 / Electron / macOS 側の終了承認後停止。
- **実装した運用対策**: `.obsidian/plugins/canvas-reference-tools/main.ts` に終了ガードを追加。Electron app の `before-quit` で detached な外部プロセスを起動し、通常終了が完了すれば何もしない。一定時間後も Obsidian 本体 PID が残っている場合だけ `TERM`、さらに残れば `KILL` で片付ける。プラグインの通常リロードや無効化では発火せず、アプリ終了時だけ働く。
- **検証結果**: `npm run build` 成功、`npm test` 成功。`community-plugins.json` は元リストへ復元済み。ガード実装後、この vault を明示的に開いて通常 Quit を観測したところ `exited_after_seconds=2` で終了。最後に Obsidian プロセス残存なしを確認。
- **未確定**: ガードで運用上は再起動停止を避けられる見込みだが、Obsidian/Electron/macOS 側の根本原因そのものは未修正。Obsidian 本体アップデート後は、このガードが不要になる可能性、または app/remote API の変化でガードの見直しが必要になる可能性がある。

### 2026-06-13 — v0.4.1〜v0.4.2 切り取り不具合の実機デバッグと修正(自動GUI操作で確認したが武田さんの実機では当初未動作)

  window(capture)へ移動**して解消。実キーで武装・拡大とも動作確認済み。
- **原因2: 切り取り表示で `.canvas-node-content` の幅が約1pxに潰れ、画像が見えない。**
  回転機能が 2026-06-07 に踏んだのと同じ Obsidian 側レイアウトの罠。→ crop-active 時に
  content へ `width:100%; height:100%` を明示して解消。
- 付随修正:
  - 遅延読み込みタブ(about:blank の仮文書。実測57個)へキーリスナーが重複登録される
    リークを発見 → **アクティブな Canvas のウィンドウだけに登録**する方式へ変更(登録数 57→1)。
  - C キー判定を `code === "KeyC"` + `key === "c"/"C"` の二重化(日本語入力対策)。
  - クリック対象の解決に座標ヒットテストのフォールバックを追加。
  - C キー不要の代替経路「選択画像を切り取り(ドラッグで範囲指定)」コマンドを新設
    (右クリックメニュー/コマンドパレット/ホットキー割り当て可)。
  - スペース拡大は「同じ選択のまま動いていない時だけ戻る」判定に選択IDを追加
    (別画像を選び直した場合はそちらへの拡大)。

### 2026-06-06 — v0.3.0 実装後の不具合修正

- 回転画像の角が外側の `.canvas-node` 枠で切れないよう、回転中の外側ノード枠にも
  `overflow: visible` を限定適用した。
- `enableNodeCopy` 設定を追加し、選択ノードを実際の `Cmd+C` で Canvas 内部の
  `handleCopy` へ渡す処理を追加した。
- コピー処理はアクティブな Canvas だけを対象にし、テキスト編集中と未選択時は処理しない。
- Obsidian が既に同じコピーイベントで `handleCopy` を呼んだ場合は二重実行しない。
- `handleCopy` が利用できない場合は、ノードコピー機能だけを全体で無効化し、一度だけ通知する。
- 実機確認結果:
  - 回転画像クリッピングは改善しなかった。外側 `.canvas-node` の `overflow` は原因ではなかった。
  - 画像の回転機能そのものも改善していない。実機画像では、回転角度と回転後の外枠拡大は
    動作する一方、画像の中心が拡大後の外枠中央へ移動せず左上寄りに残り、画像の大部分が
    表示領域外へ切れている。
  - メインウィンドウでは選択ノードの Cmd+C が動作した。
  - ポップアウトウィンドウ（別ウィンドウ）では選択ノードの Cmd+C が動作しなかった。
- コピー失敗の有力原因: 現在の実装がメインウィンドウのグローバル `document` だけへ
  `copy` リスナーを登録し、フォーカス判定でも同じ `document` を参照している。各 Canvas の
  `wrapperEl.ownerDocument` を使う必要がある。
- 回転失敗の有力原因: AABB（回転後の画像全体を収める外枠）の計算自体ではなく、拡大後の
  `.canvas-node-content` の寸法・位置、または画像の `left: 50%` / `top: 50%` の基準要素が
  外枠全体になっていない可能性が高い。実際の DOM 寸法と計算済みスタイル確認が必要。
- 状態: **実装済み・自動試験済み・一部実機確認済み・回転機能とクリッピングに未解決あり**。
