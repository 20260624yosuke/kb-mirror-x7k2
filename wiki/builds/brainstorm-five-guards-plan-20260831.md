## 5つの穴と、それぞれの検査

### 穴1: 順序が未確定のまま動けてしまう（取り違えの根本）

実測: 「軸は2つ」と示されたのが 08-30 02:44、私が計画を書き始めたのが 06:10、
順序が決まったのが 08-31 00:57（**18時間47分後**）。その間ずっと私が勝手に片方を選んで走っていた。

**検査（意味の理解は不要）**

1. メモの**引用行のかたまり**をそのまま抜き、候補として並べる（実測 19件抜けた）。要約も分類もしない。
2. 成果物を書く前に、候補をカードに並べて**武田さんが選ぶ**。
3. 機械が見るのは「**直近の武田さんの発言より後に、指示を選んだカード回答が記録にあるか**」だけ。

「軸が2本か3本か」は誰も数えない。数えるのは「選んだ回答が在るか無いか」。
カード回答は記録の `toolUseResult` に残る（実測 221件を機械で読めた）。

**優先順位を LLM に書かせない。** メモの優先順位は武田さんのカード回答からしか書き込めず、
回答が記録に無ければ **LLM の憶測とみなして無効**にする。

### 穴2: 成果物の場所を出さなくても会話を閉じられる

実測: この会話で HTML を7回書いたのに、私がチャットに出した文 11本のうち
**場所を含むものは 0本**だった。いまの検査は「スキルを起動したか」しか見ていない。

**検査**: そのターンで成果物の置き場のファイルを作った・直したのに、
最後の文にそのパスが Markdown リンクとして無ければ、会話を閉じさせない。

### 穴3: 追記だけで直しても止まらない

実測: この HTML への書き込み8回のうち、既存を書き換えたのは **2回（146字と50字）だけ**。
そのため冒頭の要約が「4＝未解決」のまま残り、後半と結論が反対になった。

**検査**: `Edit` の `old_string` が `new_string` に丸ごと含まれる（＝純粋な追記）回数を数え、
連続で続いたら止める。**閾値は未定。過去の成果物で「何回落ちるはずか」を数えてから決める。**

### 穴4: CSS の骨格を外しても止まらない

実測: 正本 `design-system/document.css` が想定する骨格は
`mb-page` → `mb-header` → `mb-wrap` → `mb-main` ＋ `aside.mb-glossary`。
私は `mb-wrap` から始めており `mb-page` も `mb-main` も無く、
**見出しや表が2カラムへ交互に流れ込んで文字が重なっていた**。

**検査（3つとも有無・数の判定）**

- 骨格が揃っているか（`mb-page` / `mb-wrap` / `mb-main` / `mb-glossary` の数）。
  **既存の良い版3枚がすべて通ることを実測済み**（three-holes-fixed / handoff-mechanism-design / where-i-drifted）。
- クラスが要素と合っているか。CSS が `blockquote.mb-quote` のように要素を指定している場合、
  その要素に付いているか（今回 `div.mb-quote` を4件やっていた）。
- 実在しないクラスを使っていないか（今回 `mb-lead` `mb-danger`。正しくは `mb-lede`）。

### 穴5: 見た目を一度も見ずに完成と言えてしまう

実測: `file://` で開くと外部 CSS も本文に埋めた `style` も落ち、**無地で描画される**。
`http://127.0.0.1:<port>/` でフォルダを配ると**正しく描画される**。
つまり見た目を確認する手段はあったのに、使っていなかった。

**検査**: そのターンに HTML の成果物があるのに、`http://` 経由で画面を取った記録が無ければ止める。

- **閾値を数えずに置かない。** 過去の記録で落ちる回数を先に数える。数えずに置くと止まりすぎる。
- **優先順位を LLM が書けるようにしない。** 武田さんのカード回答が記録に無い順序は無効とする。
- **「軸がいくつあるか」を機械に判断させない。** 判断させた時点で判断者が LLM に戻る。
- 既存の4検査を作り直さない。足すだけにする。
- メモ置き場（`wiki/analyses/`）への書き込みを穴1・穴2の検査対象にしない
  （メモを書けなくなると議論そのものが止まる。過去に同じ副作用を出している）。

### M-1 への対応: 穴1の判定式を具体化する

  **`【優先順位】` の印のついたカードへの回答が transcript に記録されているか**を見る。

### M-2 への対応: 穴5は原因を断定せず、検出根拠を定義する

  URL のパス部分を対象ファイルと照合し、**別ページを撮っただけでは通らない**ようにする。
