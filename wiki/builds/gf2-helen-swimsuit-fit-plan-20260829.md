## 1. 目的と非対象

### 目的

ドルフロ2から抽出したキャラクターを Blender 上のオブジェクトとして扱う既存の導線を使い、
**ヘレンの体型のキャラが水着を着た作画資料**を作る。原作再現ではない。原作に該当スキンは存在しない。

ドナーは Dusevnyj SSR0101 の P3 衣装のビキニ上衣。受け手は Helen SSR0101。

### 目的でないもの

- 原作の見た目の完全再現。
- ハーネス（判定の仕組み）を作ること自体。ハーネスは成果物へ到達するための手段。
- 質感・材質・透過・照明・色。ただし透過が輪郭や布面積を変える場合は形状問題として扱う。
- モーション。立ち絵に近い1状態でよい。

### 非対象（今回やらない）

- Dusevnyj の白い透けブラウス。
- Dusevnyj の P3 下衣。下半身は Helen 自身の布を使う。
- 全モーション検査。
- **水着の種類の名前の同定。**（2026-08-29 承認: 名前は付けずに進む。形状の数値だけで役割を定義する）

### 成果物の形

**Helen 全身1体。** 下半身は Helen 自身の既存の布。編集は上半身のみ。トルソーのみは禁止。

### 2.3 上衣は21個の部品でできている（revision 3 で追加）

`c_DusevnyjSSR0101_slg_P3_cloth1_lod0` submesh0（2562頂点・4006面・開いた辺1084）を
連結成分に分けた。左右対称の対になっている。

判定に使うのは2つの数値だけ。**厚み比**（いちばん薄い方向 ÷ いちばん長い方向）と**高さ幅**。
データ内の最大の切れ目は厚み比 **3.26倍**（0.136→0.444）、高さ幅 **4.08倍**（7.9→32.2mm）で、
どちらも2倍を大きく超える。しきい値の置き方で結果が変わらない。

> 21部品のうち **7部品（0, 3, 4, 5, 8, 9, 10）が複数の規則に当たる**。
> とくに部品10 は厚み比 **0.728 でデータ中の最大値**で、「厚み比 ≥ 0.30」だけならカップになる。
> **適用順は上から: 小物 → カップ → 肩ひも → 垂れ → 帯 → 中間。** この順でなければ下表を再現できない。

## 3. 採用する手順（案P: 役割ごとに作り替える）

**部品ごとに、変えるものと変えないものを分ける。** これが案N・案N2 に無かった自由度。

| 役割 | 変えるもの | 変えないもの | 現実の水着で言うと |
|---|---|---|---|
| **カップ** | ヘレンの肌に沿わせて作り直す | 厚み（内外の間隔） | サイズを替える |
| **帯** | 長さ（アンダーバスト周に合わせる・比1.19相当） | 断面（高さ5.3mm） | 紐で周りを合わせる |
| **肩ひも** | 長さ（端点が体側で決まる） | 幅 | 紐で肩ひもを合わせる |
| **下へ垂れる** | 何も変えない | 全部 | — |
| **小物** | 位置だけ（剛体） | 大きさ・形 | — |

根拠: 現実の水着でも紐で調整できるのは周りの長さと肩ひもの長さで、**カップの容積は紐では増やせない**
（`wiki/_attachments/helen-swimsuit-status/20260829-swimwear-sizing-and-cup-volume.html` に出典つきで記載）。
実測の体格差（バスト1.40〜1.50倍・アンダーバスト1.19倍）と一致する。

### 3.1 カップの作り方（2026-08-29 承認）

**カップの内側の面をヘレンの肌に沿わせ、外側を厚み分だけ押し出す。**

- 密着は構造上保証される（内側が肌に載るため）。
- バストの形はヘレン自身の形になる。
- 厚み比は保てる。
- **ドナー固有のカップの彫り方は失われる。**
- 新しい面を作るので **G6 の `created` が 0 でなくなる。** approximation として別途承認を取ること。

**未決定**: 内側をどの範囲に沿わせるか（カップの外周をどこで決めるか）。ドナーのカップの外周を
ヘレンの体表へ投影して決める案が有力だが未検証。

### 3.2 部品どうしのつなぎ目（未検証・最大のリスク）

21部品は連結成分としては離れているが、見た目上は接している場所がある（帯とカップ、帯と小物）。
**役割ごとに別々に動かすと、その接触が崩れる可能性がある。** 検証方法も未設計。

**G4a と G4b と G7 は必ず同時に見る。** 片方だけでは、もう片方を壊す方法が合格する。

### 4.1 G4b の合格線を 5.3% から 3.36% へ訂正（revision 3）

revision 2 は「中央値 +10mm 以下の4組から取った」と書きながら 5.3% を採用していた。
その4組の実測は 2.28 / 3.36 / 0.00 / 1.51 で、**正しい範囲は 0〜3.36%**。
5.3 は Sabrina 水着#1（中央 +7.05mm）の値で、4組に入っていない。

### 4.2 G10 を作り直す（revision 3・最重要）

**revision 2 の G10 は検出力がゼロだった。** `--selftest` は `scale=1.0`・上下端も Z 中心も同一・
`target=dfield(G)` で呼ぶため初期値 P=G が反復の不動点になり、`fit` の中身が壊れていても 0mm を返す。
**実験で確認済み**: 案N の中核である局所回転を単位行列に置き換えた版でも「0.0000mm・合格」を返した。

**新しい設計**: ドナーの体を**既知の剛体変形**（例: 20mm の平行移動、または15度の回転）で動かす。
上衣も同じだけ動かせば距離も形も完全に保てるので**正解が存在し**、しかも初期値は正解ではないため
不動点で素通りしない。測るのは次の3つ。

| 測るもの | 理想 |
|---|---|
| 距離差（目標距離との差） | 0mm |
| 辺の崩れ（剛体解があるので理想は無変化） | 0% |
| 復元率（1.0=完全復元 / 0.0=何もしていない） | 1.0 |

**合格線は、実装したうえで「壊した版」を並べて決めること。**
壊した版の作り方は最低4種類（局所回転を単位行列に / 行列式の反転処理を削除 / 侵入止めを削除 /
目標距離を0.5倍）。**正しい版が壊した版より良いことを確認できるまで、合格線を決めてはならない。**

参考（案N で測った値・案P では作り直す）: 案N の復元率 0.293 に対し、
侵入止めを削除した版が 0.863、局所回転を殺した版が 0.483 だった。**壊した版のほうが良かった。**

### 4.3 却下した測り方（再提出しないこと）

- **腰帯に残る開いた縁の本数で被覆を測る** → 布を1枚も残さない場合に面が存在せず開いた縁も0本になり、
  何も着ていない状態が満点になる。穴の不在は被覆の証明にならない。
- **G3a（体の面積のうち衣装が近くにある割合）** → 原作の中だけで 6.6%〜58.3% と振れ、衣装の種類で決まる。
- **G4b を「0mm未満の割合」で測る** → 表面に載っている状態（0〜0.6mm）と突き刺さっている状態を
  区別できない。深さ1mm を基準にする。

## 6. 却下した適合方式（再提出しないこと）

| 方式 | 落ちた理由 |
|---|---|
| 一様拡縮のみ | めり込み52.7% |
| 高さ別拡縮 | めり込み49% |
| 半径表による対応づけ移送 | 辺が最大73倍に伸びる |
| 体表面どうしの直接対応づけ | 辺が最大61倍。距離指標が循環して評価不能 |
| 拡縮＋法線押出 | 42面が裏返る |
| 変位の大きさだけをならす | 裏返り490〜758面 |
| 変位をベクトルでならす | 裏返りは消せるが被覆が届かない |
| 体をなめらかな場として扱う | 二面角2.3倍のまま |
| 差分座標だけを保つ交互法 | 面積比が0.31〜2.34と不均一 |
| 硬い押し戻し | 形が潰れる（立体比0.807・裏返り178面） |
| **案N（1枚の硬い殻・深い頂点だけ20倍のバネ）** | **中央値 +8.330mm。バネをどう振っても合格域が無い。既知の平行移動を29%しか追随できない** |
| **案N2（バネを役割で分ける・片側だけの壁）** | **改善したが不合格（中央6.93 / 深い8.82）。追随を上げると立体比が0.805まで落ちる** |

**案N・案N2 の失敗は「部品の役割を捨てて全体を1つの殻として扱った」ことに由来する。**
バネの調整・拡縮率の調整で解こうとしないこと（どちらも 2026-08-29 に実測で否定済み）。

## 7. 絶対にやってはいけないこと

1. **合格線と成果を別の測り方で測らない。** 2026-08-29 に実際に起き、合格を1度撤回した。
2. **合格させるための調整値を入れない。** `bias+0.8mm` と `目標0.5倍` を入れて2度合格を作り、
   2度とも撤回した。後者は答えの分かっている試験に落ちた（原作を中央値3.64mm・最大14.41mm 壊す）。
3. **距離だけで判定しない。** 形（G7・G8・G9）を同時に見ないと、上衣を引き裂く方法が合格する。
4. **LLM がレンダー画像を見て判断しない。**（`wiki/builds/llm-vision-review-suspension-policy.md`）
5. **原本を書き換えない。** `intermediate/` と原本 Blend は読み取り専用。
6. **層A（コード由来の事実）と層B（適合）を混ぜない。** 各面に来歴タグを付ける（G6）。
7. **却下済みの方向を再提出しない。** 提示前に
   `python3 tools/rejected_approaches_check.py <計画ファイル>` を通す。
8. **検出力を確かめていない試験を「合格した」の根拠にしない。**（G10 の失敗の教訓）
9. **位相（部品数・辺・開いた辺）を生の頂点番号で数えない。必ず座標で溶接してから数える。**
   （2026-08-29 の失敗。生21 / 溶接6 と結論が変わる）
10. **提示前に `python3 tools/plan_audit.py` を通す。** 設計は
    `wiki/analyses/gf2-helen-plan-audit-design-20260829.md`。
