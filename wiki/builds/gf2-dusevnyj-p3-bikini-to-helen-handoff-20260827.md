## このページの役割

このページは、Dusevnyj SSR0101のP3衣装から**ビキニ上衣だけ**を一次データで確定し、Helen本人の
既存ビキニ状下衣を残した作画資料へ適合する、新規・高リスク案件の再開入口である。

ヘレン完全原作再現とは完成条件が異なる。目的は、絵を描くときに多方向から形状を読める資料を作ること。
照明・ポスト処理・ゲーム完全再現は主目的ではない。ただし透過処理が輪郭や布面積を変える場合は
形状問題として検査する。

### 0.1 武田さんの発言と意図（別のLLMが読んでも分かるように）

以下は武田さん本人の発言と、そこから読み取るべき意図。**言い換えて薄めないこと。**

1. **「オブジェクト生成パイプラインは証明済みで、問題は成果物へ到達できるか」**
   → ゲームデータからの抽出・再構築は既に成立している。もう一度証明する案件ではない。

2. **「プライオリティは形状であり、質感などは現状優先してません。トークンが有限なので」**
   → 材質・透過・照明・色・質感を測る設計は却下される。形状に集中する。
   トークン消費そのものが制約条件であり、大きな計画は それだけで減点になる。

3. **「全モーション適用は考えてません。あくまでも現段階です。まずは、立ち絵に近い状態でいい」**
   → 姿勢の選定を大きな工程にしてはならない。立ち絵に近い1状態で足りる。
   代表姿勢の走査・選定を計画の柱に据えた案は却下済み。

4. **「懸念点は、そのまま移植は成立しないということです。LLMの憶測が介入してきます」**
   → 本件の中心的な危険は技術的困難ではなく、**LLMが穴を憶測で埋めること**。

5. **分離せよ、という指示（最重要）**
   - **「コードからの再現自体は、可能だということが helen原作再現プロジェクトの方で実証済み。
     ここは事実のみでタスクを進めなければいけません。憶測での推論は禁止です」**
   - **「しかし、Helenの体型にドゥルシーヌヴイの水着を着せることを成立させるコードは存在しない
     と思います」**
   - **「なので、ドゥルシーヌヴイの水着をhelenの体型にレンダリングするときに生じる、LLM特有の
     懸念点を洗い出して、監査スクリプトで成果物の品質を安定化させます」**
   → **層A（コード由来・事実・憶測禁止）と 層B（コードが存在しない適合作業）を分ける。**
   ハーネスの存在理由は層Bの品質安定化。

   → 成果物は Helen 全身1体。下半身は Helen 自身の既存下衣。編集は上半身のみ。
   胸だけ・トルソーだけの成果物は禁止。

7. **「（見え方を一度だけ聞いて凍結する案は）聞こえがいいけど、現実的じゃない。
   俺の認知負荷のリソースは無限じゃない」**
   → **武田さんの目視判断に依存する設計を作ってはならない。**
   「最後はユーザーが決める」という逃げは却下される。判断材料は実在データから取る。

8. **「オブジェクトは塊に小物が張り付いてる感じではないかもしれません。オブジェクトを非表示に

   → 肌と布は同じメッシュ内の submesh として同居している。「服のオブジェクトを消せば下に体がある」

9. **「どうせ失敗するのよ何もないと。だから、基準をガチガチに固める必要あるよな。
   どうするか考えろって言ってる」**
   → 求められているのは「私の失敗モードの一覧」ではなく、**合否の物差し（基準）そのもの**。

10. **「ここまでのllmの自律的なタスク処理でどうやってクリエイティブな作業をさせれるかってこと。

### 0.4 表面在庫の実測結果（このセッションの最大の成果）

測り方（再現可能）: 各 mesh の npz を読み、頂点位置を小数5桁で丸めて溶接し、
**1つの三角形にしか使われていない辺＝開いた縁**を数える。submesh 内で開いていても
メッシュ全体では閉じている辺は「隠すと開く縁（seam）」、全体でも開いている辺は「元から開いた縁」。

**確定した構造:**

- **肌と布は別オブジェクトではなく、同じメッシュ内の submesh として同居している。**
  例: `c_HelenSSR0101_slg_cloth2_lod0_Flat` は4 submesh を持ち、#0 が肌、#1以降が布。
  武田さんの指摘（0.1-8）は実データで裏付けられた。

- **上半身の肌は実在し、閉じている。**
  `cloth2_lod0_Flat#0`（3468面 / 1907頂点）の開いた縁は **首の切り口・両肩・両腕の切り口だけ**。
  胸・鎖骨・脇・背中・みぞおちに穴は無い。
  → **上半身の水着化は「肌の面が無い」という理由では blocked にならない。**

- **現在表示中の P1（礼服）構成では、腰に大穴がある。**
  P1 の肌 submesh を全部溶接して残る開口は16個。うち最大は
  **中心 (0.000, 1.030, -0.035)・幅292mm×高75mm×奥行197mm**、および
  (±0.073, 1.005) の 138×91×197mm。スカートの下は空洞。
  他の開口は 首(Y1.474)・両肩(Y1.284)・両腕(Y1.308)・太腿の切り口(Y0.885/0.852)・足首(Y0.162)。

- **「元から着ているビキニパンツみたいなもの」の候補**:

  腰帯（Y 0.95〜1.10）での X 幅が **190mm / 222mm** で、P1 のスカート submesh（306〜336mm）より
  明確に細くパンツ状。**数字からの候補であり、目で見て確認していない（未確認）。**

  `c_DusevnyjSSR0101_slg_P3_cloth1_lod0` は **submesh 1つ・4006面・seam 0 の完全に独立した殻**。

## 5. 懸念とハーネスの対応

| 懸念 | 防止・検出 | 不合格時の動作 |
|---|---|---|
| 白いブラウスを誤採用 | P3全候補を位置・材質・UV・表示状態で台帳化し、除外成分SHAを固定 | `source-audit`へ戻る |
| ビキニ以外のP3部品混入 | 採用連結成分の許可リスト方式 | 未登録成分が候補にあればFAIL |
| Helen下衣との二重表示 | 同一領域の表面層数、近接面、z-fighting候補を測る | 上衣fitへ進まず構成を修正 |

| LLMによる身体創作 | 新規面は別オブジェクト・別材質・来歴・可逆削除を必須化 | 原作身体とは呼ばず別承認 |
| 骨対応の誤り | 骨名、rest変換、親子、影響頂点、ウェイト分布を比較 | 自動対応を拒否し局所対応へ |
| 静止時だけ合う | 中立後に肩・曲げ・ひねりを姿勢ごとに再計算 | 失敗群だけfitを修正 |
| 固定値の使い回し | JSONへ`measurement_scope=per_pose/static`を必須化 | per-pose項目の不自然な全一致はFAIL |
| 接触を貫通と誤認 | 正例にも同じ検査を行い、交差・距離・断面を組み合わせる | 画像単独では停止しない |
| 貫通の見逃し | 表面距離、三角形交差、法線向き、断面を併用 | 最悪位置を自動抽出 |
| 透過で布面積が変わる | 実材質・alpha接続・しきい値と不透明診断を比較 | alpha未接続や輪郭不一致はFAIL |
| 形状が水着に見えない | 正面・側面・斜めの形、接続、被覆を外観ゲートとして分離 | 機械PASSでもユーザー許容前は未完成 |
| 制作器と検査器の共通誤り | 既知負例、別実装監査、別プロセス再計算 | 同じ関数の再利用だけで独立監査としない |
| 古い結果流用 | 入力・候補・スクリプト・出力SHAを1 run manifestへ拘束 | 1つでも不一致なら結果無効 |
| 検査の肥大化 | neutral→代表姿勢→任意の全モーションの順に限定 | 代表合格前に全stateへ進まない |
| 前回ログで偽成功 | 開始時刻より新しい出力と正常終了状態を必須化 | 古いログしか無ければFAIL |
