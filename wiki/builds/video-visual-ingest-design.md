# video-visual-ingest 設計 v2.3

講座動画の画面を、raw に残る動画を根拠として wiki source ページへ取り込む仕組みの正本仕様。
通常の `llm-wiki ingest` に動画検出と映像価値判定を統合し、動画が知識を持つ場合は映像も自動で取り込む。

## 目的と入口

- `raw/` は一次情報の正本として読み取り専用に保つ。
- 音声・文字起こし由来の通常 ingest と、画面上の映像観測を同じ source ページに積み上げる。
- ユーザーは「この raw ページを ingest して」とだけ依頼すればよい。動画の有無と映像を読む価値は LLM が判断する。
- 講座、実演、画面操作、スライド、作例比較など、映像が文字起こしにない知識を持つ場合は自動で映像 ingest まで進める。
- ユーザーが「文章だけ」「映像不要」と指定した場合は映像を読まない。
- 同じ動画ハッシュで映像 ingest 済みの場合は再読取しない。複数候補で対象が決められない場合だけ確認する。

## 実行段階

1. raw ページ、文字起こし、補助資料を読む。
2. 通常の source / entity / concept / index / log 処理を行う。既存 source の映像追加パイロットでは entity / concept は更新しない。
3. raw ページ内の動画リンクを検出し、動画を一意に解決する。
4. `tools/video_frames.py --dry-run` で動画の同一性、再生時間、抽出範囲、予定枚数を確認する。
5. 開始・中間・終了付近を少数サンプルし、文字起こしにない画面情報があるかを判定する。講座実演や画面操作が明らかな場合はサンプル判定を省略してよい。
6. 映像価値があり、vision 実行環境、文字起こし、source ページ、動画解決、抽出範囲が揃っていれば自動でフレームを読む。
7. 画面上の事実を source ページへ反映し、機械検証を通過した場合だけ `visual_ingested` を付ける。

動画が解決できない、候補が複数、vision が使えない、または同一性確認に失敗した場合は、文章 ingest を壊さず映像部分だけ保留する。動画を推測して処理しない。

## 動画解決と同一性

- 検索範囲は vault 内の `raw/` に限定する。外部動画庫は検索しない。
- raw ページの Obsidian リンク、Markdown リンク、ページ隣接の `_attachments/` / `attachments/` / `assets/` を使う。
- 候補が複数ある場合は `--video` で明示されるまで停止する。
- 初回は動画の相対パス、SHA-256、容量、再生時間を `manifest.json` に記録する。
- raw 側に期待ハッシュがない初回は、識別情報の記録だけを行う。
- 再実行時は保存済みの識別情報と比較し、動画が変わっていれば停止する。

## 抽出

- 既定間隔は 20 秒。短時間の画面変化は文字起こしの時刻を `--at` で追加指定する。
- `--start` と `--end` で対象範囲を限定する。範囲外の `--at` はエラーにする。
- 抽出フレームは **vault 内の永続 staging**(`wiki/builds/coloso-visual-ingest-batch2/staging/<章スラッグ>/`)に作る。
  システム一時ディレクトリは PC 再起動で揮発し、ch11/ch12 で抽出済みフレームの再抽出が発生したため廃止(2026-08-26)。
- 観測と結び付いたものだけ `wiki/assets/frames/<source-slug>/` に保存する。
- 未使用フレームは保存せず、処理後に削除する。保存分確定後、staging も削除してよい。
- 盲検読取の結果はバッチごとに `staging/<章>/observations_pN_batchX.txt` へ即時書き込みし、
  会話の中だけに持たない。進捗は `staging/<章>/STATE.md` に記録し、中断後の再開点を機械的に残す。
- PNG は動画解像度のまま保存する。

## 分割動画(1 章に複数の動画)の扱い(v2.3)

2026-08-23 の実調査で、ひづるめ講座は 25 章中 14 章が分割動画(02/09/10/12/13/15×4本/17/18/19×4本/20×3本/21/22/23/25)。
**1 章 = 1 source ページ = 1 frames ディレクトリ = 1 manifest は維持し**、次の拡張で扱う。

- **snapshot**: `--video` を繰り返し指定できる。複数指定時は `videos[]`(link / path / sha256 / size_bytes / duration_seconds の配列)として記録する。単一指定時は従来どおり `video_link` + `video`。
- **manifest**: 複数動画ページでは `videos[]` 配列と、動画ごとの `extraction[]`(part 付き)を記録する。observations の各要素は `video`(動画ファイル名)を持つ。
- **観測表**: 複数動画ページでは `| evidence_id | 動画 | 時刻 | frame | 確信度 | 画面の観測(事実のみ) |` の 6 列。動画列は videos[].path のベース名(`12_01.mp4` 等)と一致させる。単一動画ページは従来 5 列のまま。
- **フレーム名**: パート番号を短縮キーに含める(`<short>-<part>-MMmSSs.png`,例: `hizurume-ch12-01-04m07s.png`)。抽出は動画ごとに行い、保存時に改名してよい。
- **再確認(recheck)**: 最低枚数は全パート合算の saved から算出する(max(3, 10%))。可能なら全パートをカバーしてサンプルする。
- **`visual_ingested`**: ページ内の全動画の処理が完了したときだけ付与する。部分的な完了では付けない。

## 品質ゲート(v2.2 機械化)

映像 ingest の全実行は `tools/video_ingest_gate.py` の 2 コマンドを常時通す(2026-08-22 ユーザー決定)。
ルール本文はスクリプトが検査するため、この節には機械が判定できない部分だけを書く。

### 機械検査(PASS しないと先へ進めない)

- `snapshot`(抽出前): raw ページ・動画・source ページの SHA-256 と、映像観測節の前後ハッシュを記録する。
- `check --phase complete`(完成報告前): 来歴(raw・動画非変更)/ 本文非破壊(映像観測節以外の一致)/
  成果物整合(全パス埋め込み・孤児ゼロ・表行数=manifest・時刻範囲)/ 再確認手続き(独立読取
  max(3, 10%) 枚以上、verdict 記録)/ 台帳(index・log・`visual_ingested` 一致)を検査する。
- 既存完了ページへの遡及では `snapshot --retrofit` を使う。本文非破壊は当時の基準がないため
  節の存在確認のみに降格し、警告として明示される。
- 本文非破壊のハッシュは frontmatter の `visual_ingested:` 行を除外して計算する
  (完成手続きの付与行は本文ではない・2026-08-26)。既存 snapshot には行込みで記録された
  ものがあるため、検査は strip 済み/生のどちらかが一致すれば PASS とする。

### 不一致の扱い(2026-08-22 ユーザー決定: 両方許容・記録必須)

第2読者との不一致は、原寸クロップ等で確定して `corrected` とするか、確定できないまま該当行に
「要確認 / uncertain」表記を残して `marked-uncertain` とする。どちらも manifest `recheck.entries`
の note 必須。再確認読取は wiki を参照しない新規コンテキストで行う。

### 機械が判定できないもの

- 観測内容が画面と一致しているかの最終判断は機械ではない。視覚的な正しさを「機械検証済み」と報告しない。
- 実行モデル名を記録する。Fable 5 に固定しない。
- vision 非対応の実行環境ではフレーム読取を開始しない。
- source ページには画面上で確認できた事実だけを書く。文字起こしは抽出時刻の手掛かりに限定する。
- 画面文字が判読できない場合は「判読不能」と書き、音声から補完しない。
- 画面に表示されていない数値や意味を推測しない。
- 各観測に時刻、証拠 ID、フレーム参照、確信度を付ける。低確信度は `uncertain` として強い根拠に使わない。
- 等間隔抽出で見つからなかったものを「動画に存在しない」と断定しない。

## 保存形式

保存先は `wiki/assets/frames/<source-slug>/` とする。

- `manifest.json`: 動画同一性、抽出範囲、抽出方式、設計版、観測とフレームの対応を記録する。抽出直後は `status: extracted`、観測と検証完了後は `status: complete` とする。
- 観測フレーム: `短縮キー-MMmSSs.png`。source ページから全パスで参照する。
- source ページ: `## 映像観測(フレーム由来)` 節を置換更新する。既存の文字起こし本文は変更しない。
- 実行履歴を細かく比較する `runs/` は、複数モデルでの再解析が必要になった段階で追加する。初回パイロットでは必須にしない。

```md
## 映像観測(フレーム由来)

- 抽出日: YYYY-MM-DD / 元動画: [[02.mov]] / 元動画 SHA-256: <hash>
- 方式: 20秒間隔 + 文字起こし誘導 / 抽出X枚・読取X枚・保存N枚
- 設計版: video-visual-ingest-design v2.1 / 読取モデル: <runtime-model>
- 凡例: 画面上で確認できた事実のみ。判読できない文字は「判読不能」と記載。

| evidence_id | 時刻 | frame | 確信度 | 画面の観測(事実のみ) |
|---|---|---|---|---|
| ev-001 | 04:07 | ![[wiki/assets/frames/<source-slug>/<short>-04m07s.png]] | high | … |
```

`visual_ingested: YYYY-MM-DD` は、source 節、manifest、index、log、孤児フレーム確認、raw 非変更確認の全工程成功後だけ付与する。

## 実装

- `tools/video_frames.py`: 動画リンク自動検出、ページ隣接解決、SHA-256 / 容量 / 再生時間取得、dry-run、範囲指定、フレーム抽出、前回 manifest との同一性比較、manifest 出力。
- `tools/video_ingest_gate.py`: 機械品質ゲート。`snapshot`(抽出前の同一性記録)と `check`(完成報告前の来歴・本文非破壊・成果物整合・再確認手続き・台帳検査)。
- `.claude/skills/video-visual-ingest/SKILL.md`: 通常 ingest からの呼び出し、品質ゲート、保存・報告手順。
- `AGENTS.md` / `CLAUDE.md`: 通常 ingest の映像サブ処理として同じ規則を記載する。
