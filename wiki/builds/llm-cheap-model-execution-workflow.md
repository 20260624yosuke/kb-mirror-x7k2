# 廉価LLM実行ワークフロー

## 要点

- 最初に読む欄は、この「要点」だけで足りる。
- 廉価LLMに投げる前に、ハイエンド推論モデルで `目的` / `完成条件` / `今回やらないこと` /
  `編集対象` / `検証コマンド` / `停止条件` を1ページへ固定する。
- 廉価LLMは、その正本に書かれた**機械作業だけ**を実行する。新しい完成条件、構造変更、
  外部アプリ連携の追加は自分で足さない。
- 完了報告は `実装済み` / `自動試験済み` / `配布済み` / `実機反映済み` / `運用開始可能` を必ず分ける。
  この5つを混ぜたら失敗扱いにする。
- ブラウザ拡張、常駐helper、外部アプリ、Google Tasks のように正本が複数ある作業では、
  廉価LLM単独で「完了」まで言わせない。最後はハイエンド推論モデルか武田さんがゲート判定する。
- この環境での推奨配分は、計画と最終レビューを `GPT-5.4 high`、機械実行を廉価モデル、
  旧断言掃除や状態分離の見直しを必要に応じて `GPT-5.5 medium/high`。

## 目的

雑に投げても、廉価LLMが

- 正本を取り違えない
- 実装と配布と実機反映を混同しない
- 動いていない外部状態を「完了」と誤報しない

状態を作る。

## 今回見えたボトルネック

- **正本が分散していた**: 会話、wiki、配布物、実機、helper が別々で、どれを根拠に完了判定するかが固定されていなかった。
- **完了定義が粗かった**: `署名済みXPIあり` と `Firefox実機で新版が動いた` が分離されていなかった。
- **廉価LLMに判断まで任せた**: 機械実行だけでなく、状態解釈と終端判定まで同じモデルに背負わせた。

## 役割分担

- **ハイエンド推論モデル**: 計画を固定する。完了条件と停止条件を決める。最後のレビューも担当する。
- **廉価LLM**: 既存runbookや正本に沿った機械実行だけを担当する。
- **武田さん**: 実機確認が必要なときだけ、結果の共有か共同確認を行う。

## 廉価LLMに渡す前に固定する項目

1. 目的
2. 完成条件
3. 今回やらないこと
4. 触ってよいファイル
5. 実行コマンド
6. 検証コマンド
7. 停止条件
8. 最終報告の書式

この8点が欠けた状態では、廉価LLMへ渡さない。

## 必須ゲート

### 1. 計画ゲート

正本ページに、少なくとも `目的` / `完成条件` / `今回やらないこと` / `検証方法` を書く。

### 2. 根拠ゲート

実行前に、今の実状態をコマンドで読む。例:

- `manifest.json` の version
- 署名済み配布物の有無
- 公開 `updates.json`
- helper `/health`
- Google Tasks の件数やリスト名

### 3. 実行ゲート

廉価LLMには、既に決まったコマンドと既存ファイルの更新だけをさせる。
新ディレクトリ、新しい保存先、新しい分類体系は勝手に増やさせない。

### 4. 検証ゲート

編集後は、正本に書いた検証コマンドをそのまま流す。
検索やテストで確認できない項目は、未確認のまま残す。

### 5. 終端ゲート

`運用開始可能` は、末端の実ワークフローが通った時だけ使う。
`配布済み` や `自動試験済み` の時点では使わない。

## 状態ラベル

- `実装済み`: ファイル変更そのものは入った
- `自動試験済み`: テストや検索コマンドが通った
- `配布済み`: 配布物や公開URLが更新された
- `実機反映済み`: ユーザー環境へ新版が実際に反映された
- `運用開始可能`: 実機の末端ワークフローが完成条件どおり通った

## 廉価LLMを止める条件

- 実行前に固定していない完成条件が途中で必要になった
- 正本が複数あり、どれが現行かコマンドで確定できない
- 実機確認が無いと成否を判定できない
- 新しい構造変更や保存先変更が必要になった

## モデル選定

- **実行本体**: `GPT-5.4 high`
  - 今回のような「根拠の分離」「状態ラベルの分離」「wiki修正」には十分
- **廉価モデル**: 使ってよいのは、正本・停止条件・検証コマンドが既に固定された後だけ
  - 単独での終端判定はさせない
- **`GPT-5.4-mini`**: 今回系の作業では避ける
  - 外部状態が多く、配布済みと実機反映済みを取り違えやすい
- **`GPT-5.5 medium/high`**: 任意の最終レビュー用
  - 旧断言の残骸、根拠と推測の混在、状態ラベルの崩れを短く点検する用途

  ハイエンド級へ戻す形で回っている。
