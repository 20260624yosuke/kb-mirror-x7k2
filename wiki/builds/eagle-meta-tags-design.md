## A. 出自軸の規則エンジン(作品・キャラ・絵柄の棚)

**核: 辞書は手書きせず、武田さんの手作業フォルダから自動学習する。**
例: `07_作品_ブルアカ` 既存メンバーのauthor_id分布を集計 →「この作者IDならブルアカ」の
規則が自動で採れる。絵柄フォルダも同様に作者IDが特定できる。LLMは辞書の監修だけ行う。
作品・キャラ名のキーワード(ファイル名・annotation内の「ブルアカ」「アスナ」等)は
補助ルールとして辞書に追記する。

**新規スクリプト `tools/eagle_meta_tags.py`**(torch不要・facts.dbのみ読む軽量品):

- `dict-build`: フォルダ既存メンバーのauthor_id分布から辞書下書き
  `tools/eagle_sort_data/meta_dict.json` を生成。キーワード補助ルールは空枠で出力
  (充填は上位級の監修工程)
- `calibrate`: フォルダ既存メンバーの2割を隠して辞書で当てる自動答え合わせ(的中率測定)
- `meta-review`: 辞書を全画像に適用し、該当フォルダ未所属の画像を100枚連番チャンクの
  HTML/JSON(tag-reviewと同一書式・画像コピー方式も同じ)で出力
- 書き戻し・ログ・検証は現行runbookの④〜⑥を流用

**展開順**: 絵柄(author_id完全一致=最も安全)→ 作品 → キャラ。

**ゲート**: ①辞書の的中率(calibrateで自動測定。低い棚は除外)
②キャラ名キーワードの同名誤爆(例: アスナ問題)— パイロットでAI視認により誤爆率を測り、
危ないキャラ名は作者ID条件との併用に落とす。誤爆率が出るまでキャラ軸の一括展開はしない。

## B. 弱カテゴリ補強(ローアングル・シュシュ等)

**方式**: CLIPで上位300枚に粗絞り込み → 判定AIが**1枚ずつ** yes/no/unsure を付ける →
yesだけの確認ページ → 武田さん承認 → 書き戻し。現行のチャンク一括判定との違いは
「1枚単位で選別する」こと。

- 新規スクリプト `tools/eagle_pool_judge.py`: チャンクJSON+判定JSON
  (item_id→yes/no/unsure)を突き合わせ、yes分だけの書き戻しリストと確認HTMLを生成
- 判定AIはカテゴリごとの**判定基準書**(下記)だけ読んで判定する=ミドル級で回る
- **ゲート**: ローアングルでパイロット。300枚から yes 50枚以上、かつ上位級の抜き取り
  20枚で9割妥当なら方式確定→横展開。不合格なら方式ごと再相談

### 判定基準書: ローアングル(初版)

- **yes**: カメラ(視点)が被写体の腰より下にあり、明確に見上げている構図。
  あおり顔・下から覗くスカート・床/地面越しの見上げを含む
- **no**: 通常のアイレベル全身絵、俯瞰(見下ろし)、バストアップで角度不明のもの、
  実写・スクショ・無関係
- **unsure**: わずかにあおっているが判断しづらいもの → タグを付けず unsure リストへ
  (ログJSONの `unsure_item_ids`。上位級が再判定)
- **追補(2026-07-06 W1監査より)**: 「キャラが上を見ている」と「カメラが下から見上げている」を
  混同しない。**カメラが上から見下ろしている画像は、キャラの視線が上向きでも no(俯瞰)**。
  W1抜き取りの外れ2枚は両方この型だった

## C. Canvas還元(実戦_使用済み)

設計は [[canvas-ingest-eagle-feedback-guide]] で完成済み・Codexキュー済み。
追加は1点: sidecar から confirmed の item_id を抜き出す具体例を指南書付録に置く。

```bash
python3 -c "
import json
d = json.load(open('wiki/sources/<slug>.usage.json'))
ids = sorted({m['item_id'] for a in d.get('assets', [])
              for m in a.get('eagle_matches', []) if m.get('level') == 'confirmed'})
print(json.dumps(ids, ensure_ascii=False))
"
```

(キー名が実ファイルと異なる場合は実ファイルの構造を読んで合わせる。candidateは対象外)
