# MMD ライブラリ 忠実版

## これは何 / 目的

[[mmd-library-blender-import]] で作った Blend は、**作画資料として形が読みやすいこと**を優先し、
原作の質感を作る情報を意図的に落としてある。その落とした分を戻し、
**配布パッケージに入っているデータを余さず使った版**を、別ファイルとして作る仕組み。

2026-08-01、武田さんが bilibili の MMD 動画と手元の Blend を見比べて
「質感が明らかに違う」と気づいたことが発端。

## きっかけ(動画 2 本の比較でわかったこと)

武田さんが見比べた 2 本は、クレジットを突き合わせると**同じモデル**
(`少女前线2：追放/DesmondChan`)・**同じ MME 一式**(先頭 10 名が完全一致)で、
違いは Stage / Camera / Motion / PV だけだった。つまり動画 2 本の質感差はモデル由来ではない。

さらに配布物の `Readme.txt` に `rigged and fixed by DesmondChan` とあり、
**武田さんの手元のモデルは動画で使われているものと同一**であることが確定した。

## 現行版が落としていたもの(実測)

`13-inspect-model-fidelity.py` で現行 Blend を開いて数えた値。推測ではない。

| 落としていたもの | 実測の根拠 | 画面でどう見えるか |
|---|---|---|
| 編集済み法線(顔の陰の付き方を決めている設定) | `has_custom_normals: false` | 頬・鼻・顎の陰の形が原作の設計と変わる |
| 生地の凹凸 8 枚(`normalmap/*_n`) | PMX が参照せず、Blender も読んでいない | 布も革も金具ものっぺりする |
| 粗さ・金属・遮蔽 6 枚(`*_rmo`) | 同上 | どこも同じ光り方になる |
| 髪の光沢 1 枚(`*_hair_spc`) | 同上 | 髪のツヤの強弱が出ない |
| 陰の濃淡 | 平坦なエリアライト 1 灯のみ | 陰の切れ目が消える |

> [!note] トゥーンとツヤは現行版でも効いていた
> 当初「spa(トゥーン・ツヤ)も落ちている」と見立てたが、**実測すると効いていた**。
> `mmd_shader` の `Toon Tex` / `Sphere Tex` に接続済みで、`SToon01.png` `skintoon.bmp`
> `hair-a.bmp` `skin.png` `Eff_MatCap_007.png` `SSShine1.png` の 6 枚が使われている。
> 落ちていたのは `normalmap/` 一式と編集済み法線と照明の 3 つだけ。

## 作りかた

### 材質: MMDShaderDev の後ろに Principled BSDF を足す

mmd_tools のシェーダー群 `MMDShaderDev` の入力を実測したところ、
**法線・粗さ・金属の入り口が存在しない**(Base/Toon/Sphere Tex と色・アルファのみ)。
そのため群を置き換えず、**`Color` / `Alpha` 出力を Principled BSDF へ渡し、
その先に `normalmap/` を足す**構成にした。

- 色の作り方(ベース × トゥーン × ツヤ)は**変更していない**。
- `*_n.png` → Normal Map ノード → Principled の Normal
- `*_rmo*.png` → Separate Color → 赤=粗さ / 緑=金属(**この並びは仮定**、青=遮蔽は未使用)
- `*_spc.png`(髪。rmo が無い場合のみ) → 反転して粗さへ

補助画像は**ベース画像のファイル名から機械的に引く**(`..._cloth1_d` → `..._cloth1_n`)。
末尾 `_d` / `_da` / `_da1` を落として照合し、`_rmo` は日付が付くので前方一致で探す。
対応が付かないものは当てずに、使わなかったものとして記録する。

### 照明: 背景の明るさと回り込みを分ける

陰の切れ目を出すため環境光を下げたら、**背景まで暗くなって画面全体が沈んだ**(1 回目の試行)。
World に Light Path を入れ、**カメラが直接見ている面(背景)だけ明るく、
モデルへの回り込みは暗く**した。そのうえでキー・フィル・リムの 3 灯を置いている。

### カメラ: 現行版と完全に同じ計算

比較が成立するよう、レンズ 70mm・余白 1.03・外接箱からの距離算出を
`03-build-model.py` からそのまま流用。顔アップは MMD 標準の `頭` ボーンを狙う
(無ければ外接箱の上部 93% で代用)。

## スクリプト

| ファイル | 役割 |
|---|---|
| `13-inspect-model-fidelity.py` | Blend を開いて材質・法線・照明・配布物の使用状況を JSON に出す。**書き換えない** |
| `14-build-fidelity.py` | PMX から取り込み直して忠実版を作る。`--mode current` で現行版と同条件の比較用も描ける |
| `15-make-compare-sheet.py` | 現行版と忠実版を左右に並べた比較 PNG を作る(PIL 使用、Blender 不要) |

`14` は既存 blend を改造せず**元 PMX から取り込み直す**。
既存 blend では捨てた法線が戻せないため。

## 成果(2026-08-01、Mityl で実施)

- 出力: `01_blend/ドールズフロントライン2/Mityl_デフォルト_網タイツ修正_忠実版.blend`
- 使用画像 **18 枚 → 33 枚**。増えた 15 枚はすべて `normalmap/`
- 更新した材質 **21 / 34**(残り 13 は顔・目など補助画像が同梱されていない部位)
- 使わなかった画像 **5 枚**。全件、理由を記録
  (`cloth4_da` は網タイツ修正前の旧版、`spa/` の 4 枚はモデル側が指定していない予備)
- **顔の斑点は発生しなかった**(下記)
- 元ファイルは SHA-256 `605cd050...` が作業前後で一致、`.blend1` も出ていない

### 顔の斑点について — Mityl では出なかった

**Mityl では再現しなかった**(私のレンダー上)。フローラ固有の可能性がある。
ただし**武田さんの環境(ビューポート)での確認は未実施**。

## 武田さんの実機確認(2026-08-01)

`Mityl_デフォルト_網タイツ修正_忠実版.blend` を実際に Blender で開いて確認。
**「まだ違う気がする」との反応**。原因を切り分けた。

- **顔まわりに凹凸データがそもそも同梱されていない**ことが判明。配布物の `normalmap/` は
  体・服1〜5・髪・爪の分のみで、**顔と目の分は存在しない**。忠実版でも顔の質感はほぼ
  変わっておらず、武田さんが感じた違和感の主な出どころはここだと考えられる。配布物に
  無いデータなので、これ以上は戻しようがない。
- 遮蔽(`*_rmo` の青チャンネル)は未接続のまま(上記のとおり)。
- 照明の手動調整手順(World の Strength、キーライトの Size、Exposure)を武田さんへ案内した。
  ただしこれは試していない・効果未検証。

**結論(暫定)**: データを戻す作業はほぼ天井に到達した。残る差は「配布データの有無」では
説明しきれず、**原作(ゲーム)や動画側が使っているアニメ塗り・輪郭線という描き方そのものの
違い**である可能性が高い。ここは Blender の物理計算では自動的に再現されない。
