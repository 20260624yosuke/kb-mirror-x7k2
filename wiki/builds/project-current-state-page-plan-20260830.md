## 4. 共通欄ファイル `run-state.common.json`（rev.2 で方式変更・要再承認）

### 4.1 なぜ別ファイルにするか

rev.1 は既存 `run-state.json` に `common` を足す方式だった（武田さん承認済みの「案1」）。
レビューで次が判明したため、**同じ内容を隣の別ファイルに置く方式へ変更する**ことを提案する。

| rev.1 の方式の問題 | 別ファイル方式での解消 |
| --- | --- |
| `json.load` → `json.dump` でファイル全体を書き直すため、キー順・インデント・非 ASCII エスケープ・改行が変わる。helen は日本語が大量にあり、既存の grep 前提スクリプトが壊れうる | **既存ファイルを1バイトも触らない** |
| 複数セッション並行で読み込み→全体書き戻しすると後勝ちで消える | 同上。書き込み対象が別ファイルになる |
| helen には既にトップレベル `blocked` があり、語彙が違う2本が同居する | 別ファイルなので同居しない。既存 `blocked` は履歴として扱うと 4.3 に明記 |
| バックアップ `.bak` の置き場が判定⑤の対象に入る | バックアップ自体が不要になる |

**この変更は承認済み「案1」の内容変更にあたる。承認A-0 で武田さんの再承認を取る（12節）。**
再承認が得られない場合は rev.1 の方式に戻し、C-1〜C-2 のリスクを10節へ明記したうえで進める。

## 5. 6つの機械判定

実装先: `<KBルート>/tools/project_state_sync.py`（新規）。

| # | 判定 | 発火点 | 落ちたときの動作 |

### 5.1 判定⑤の詳細（B-6 への対処）

rev.1 は自己ロックした。rev.2 では次を加える。

1. **除外**: `run-state.json`・`run-state.common.json`・`*.bak*`・`__pycache__` への書き込みは
   判定⑤の対象外。共通欄ファイルを更新する行為自体がロックの原因にならない。
2. **適用範囲の限定**: `wiki/builds/` に `current_state_page: true` のページが存在し、その
   `work_roots` に含まれるパスだけを対象にする。該当しなければ**即座に通す**。
   （`~/.claude/settings.json` はグローバルなので、無関係のセッションを巻き込まない。）
3. **脱出口**: `python3 tools/project_state_sync.py resync --force <slug>` で、生成に失敗しても
   `synced_from` だけを現在の mtime へ更新できる。使ったことは `sync.log` に残す。
4. **エラーで詰まない**: 3.4 のとおり 400行超は警告に留め、sync は成功する。
5. **外付け未マウント時**: `stat` が失敗したら**止める**（安全側）。メッセージにマウント案内を出す。
   通して形骸化させない。
