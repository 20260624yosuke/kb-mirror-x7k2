# ミティール 敬礼Actionの左右反転（資料用派生Blend）

元の**左手**敬礼を**右手**敬礼へ入れ替えた、スクショ資料用の派生 Blend を1本作った。
[[gf2-mityl-game-motion-transfer]]（52動作案件・2026-08-05 中断）とは**独立した案件**で、
あちらの再開・修復・再監査は一切していない。

> [!important] 成果物
> `01_イラスト/07_3D資料/gf2-mityl-motion/02_blend/Mityl_グローザ_敬礼_動作左右反転.blend`
> 開くと反転Actionが選択済み、範囲60〜250、現在フレーム60。元カメラ `FID_CAM`・
> 元ライト3灯・`FID_WORLD` はそのまま。元Actionも内部に残してある。

## 目的

元Blend `02_blend/Mityl_グローザ_敬礼.blend` の敬礼（60〜250コマ）を左右だけ入れ替え、
反対側で敬礼する資料を得る。**メッシュ・髪型・衣装・装飾・材質・UV・形状キー・初期骨格・
カメラ・ライトは鏡像化しない。** 画像としての厳密な鏡像ではなく「同じキャラが反対側で
敬礼する資料」を作る。

## やったこと

### 反転の方式

- 対象は **左右24組（48骨）＋中央6骨＝54キー骨**。元Actionのキー骨と完全に一致することを
  実行時に照合し、違えば止まる。`bpy.utils.flip_name` は使わない。
- 初期骨格から軸対応 `C = O_s⁻¹ · S · O_d`（`S = diag(-1,1,1)`、反射面は実測した X=0）を作り、
  `Q_先(f) = C⁻¹ · Q_元(f) · C` で**差分回転だけ**を交換する。
  絶対ポーズの鏡像化は採らない（初期骨格が厳密対称でないため。下記）。
- `センター` の位置キーは、初期軸へ変換した移動ベクトルだけを反射する。
- 初期骨の位置・親子関係には触らない。Quaternion は前コマと同符号にそろえる。
- 60〜250 の191整数コマ・215 FCurve・各191キー・LINEAR を維持。

### 初期骨格は厳密な鏡像ではない（元Blendが元から持つ性質）

腕捩・手捩系8骨で左右差がある（最大 `右手捩1`/`左手捩1` の 0.313 mm）。
初期骨行列自体も単精度保存で厳密な正規直交行列ではない（440骨での最大ずれ 2.05e-05）。
そのため絶対ポーズを鏡像化すると腕のねじれが左右で食い違う。差分回転の交換ならこの影響を
受けない。残る誤差の上限はこの実測値から骨ごとに算出している。

### 物理

元Blendは剛体250個・キャッシュ焼成済みだったが、**剛体の動きをボーンへ返す拘束が0本**で、
メッシュには一切効いていなかった（[[gf2-mityl-game-motion-transfer]] で発見済みの状態）。
今回 `build_rig` で `mmd_tools_rigid_track` を **224本ちょうど**追加し、0〜250を焼き直した。
既存58拘束は骨名・型・対象・subtarget・mute・設定値まで無変更。

その上で、**224本のうち209本を止めてある**（生きているのは15本＝イヤリング・胸元・裾の一部）。
止めた理由は次の2つ。

## 使わなかったもの・落とした情報

### 1. 上着・裾の物理（180+10本を停止）

- **何を捨てたか**: `Jacket_*` 180本と `Cloth_*` 10本の物理追従。
- **手元でどう変わるか**: 上着と裾は元Blend同様、体に貼り付いたまま揺れない。
  代わりに、生かした版（candidate-r1）では**上着が体の前へずり落ちて巻きつき、
  中の衣装が隠れて資料にならなかった**。上着は右肩に掛かる非対称デザインで、
  反転すると上げるのがその右腕になり、上着を支えるものが無くなるため。
  **反転していない対照版では同じ物理で正常に垂れる**ので、原因は
  「反転した動き × 反転していない衣装」であり物理の設定ミスではない。
- **戻せるか**: 戻せる。`tools/mirror_salute_action.py --freeze-tracks` を外して作り直せば
  224本すべて生きた版になる。崩れた版 `mirror-salute/work/candidate-r1.blend` も残っている。

### 2. 髪・前髪の物理（19本を停止）

- **何を捨てたか**: `Hair_*` 12本と `Bangs_*` 7本の物理追従。
- **手元でどう変わるか**: 髪は揺れない。代わりに髪の形が
  `mmd-library/01_blend/ドールズフロントライン2/Mityl_デフォルト_網タイツ修正.blend` と
  **一致する**（頭を基準にした髪の骨28本の位置で最大 0.00035 mm / 0.00001度）。
  生かした版（candidate-r2）では髪が重力と慣性で広がり、同ライブラリ版と
  **最大 61.887 mm / 32.019度**ずれていた（武田さんが2026-08-06に指摘）。
  なお**この広がりは左右反転とは無関係**で、反転していない対照版でも同じように出る。
  髪のメッシュデータ自体は3ファイルとも完全一致（頂点座標ハッシュ `78bcffcb…`・
  形状キー `4a5c4264…`）。
- **戻せるか**: 戻せる。揺れる版 `mirror-salute/work/candidate-r2.blend` が残っている。
  r2 と r3 の差は**髪だけ**で、上着・スカート・イヤリングは 0.000 mm で同一。

### 3. 元カメラ `FID_CAM` を鏡像化しなかった

- **何を捨てたか**: カメラの位置合わせ。計画どおり元カメラを動かしていない。
- **手元でどう変わるか**: **開いた直後、`FID_CAM` には顔が写らず後頭部が写る。**
  `FID_CAM` は元の首の向きに合わせて置かれており、反転で首の向きも逆になるため。
  スクショに使うには自分で視点を回す必要がある。
  2026-08-06 に武田さんが「元カメラのまま触らない」と判断した。
- **戻せるか**: カメラを X=0 で鏡像にすれば元と同等の顔アップになる
  （`reports/比較シート-カメラ問題.png` の3段目に描画済み）。

### 4. 物理を組んだ副産物

隠しオブジェクト（`ncc*`）が **2,923個増える**（655→3,578）。mmd_tools が剛体どうしを
ぶつけないために作るもので、描画には出ない（`hide_render`）が、アウトライナーの一覧は長くなる。
ファイルは 67.8MB → 76.6MB。

## 検証

`tools/verify_mirror_salute.py` が、生成側を **import せず**、元Blend・候補Blend・
無反転対照を別プロセスで直接読み、反転の式も初期骨格から作り直して照合する。
固定の合格値（0.1mm 等）は置かず、物差しは4つとも実測値にした。

1. 無反転対照（保存・再読込・焼成を同じだけ通した版）の誤差 … 0.000 mm / 0.000度
2. 初期骨格が厳密な鏡像でないぶん（骨ごとに算出）
3. Blenderのポーズ評価が単精度であるぶん（元Blendでも同じだけ出ることを実測）
4. 成果物カメラ `FID_CAM`（1400×1400）で**画面1画素＝実物 0.236 mm**

| 層 | 結果 |
|---|---|
| Action保存層 | キー値を独立に再計算して照合し最大差 0.0000257度／センター位置 9.3e-10 m。Quaternionの不連続ゼロ |
| 反転そのもの | 拘束抜きFK鎖を倍精度で解き、最大差 0.0000272 mm（27ナノメートル） |
| 評価済みリグ層 | 54キー骨＋D骨・ねじり骨・肩補助・目・付与親を全191コマ、親からの相対で照合。最大 0.382 mm（初期骨格が元から非対称な捩り骨）／角度 0.0000071度 |
| 保存形状層 | 頂点・面・ループ・UV・材質と面割当・形状キー60・初期骨格440骨・元58拘束・ドライバー・材質・カメラ・ライト**すべてハッシュ一致** |
| 物理層 | 追加は224本ちょうど、キャッシュ0〜250焼成済み、NaNなし、外接箱の異常なし、1コマだけの飛びなし |

品質ゲート `mirror-salute/quality-gate.json` は plan / batch / complete の3段とも合格。
**元Blendの SHA-256 は着手前後で一致**（`c3e2f95a…`）。

## 事故（発生・復旧済み）

2026-08-06 14:06:38 に元Blendが一度上書き保存され、SHA-256 が変化した（撤退ライン該当）。
中身は独立検証ツールで全項目を比較して**差分ゼロ**と確認し、Blenderが同時に作った `.blend1`
（開始前SHAと一致）から**バイト単位で復元済み**。更新日時も元に戻っている。
再保存版は `mirror-salute/work/元Blend_14時06分に再保存された版.blend` に残した。
**原因は特定できていない。** 今回の3スクリプトで保存を呼ぶのは
`mirror_salute_action.py` の1箇所だけで、保存先は常に `--out` で渡した作業用ファイルだった。

## 未確認・残った不確実性

- **反転後の髪・服の揺れ方には外部の正解が無い。** 原作に左右反転版の敬礼は存在しないため、
  忠実な鏡像ではなく、左右非対称のモデル上で計算し直した**近似**である。
- 元Blendが再保存された原因。
- 目の骨で、親からの相対差が丸め見積もりを 0.0009 mm 超える（成果物カメラで 0.004画素）。
- 差し戻し経路（候補の削除・Wikiの差し戻し）は構造上確認しただけで実行していない。
