## 腕・脚のめり込みを妥協した理由(2026-07-26 決定)

武田さんが17件統合Blendを実見し、H0159の左腕が右足に、H0167の左腕が胸にめり込む破綻を指摘した。
調査の結果、これは変換の不具合ではなく**再現の忠実さと引き換えに出ている**ものと判明したため、
武田さんが構造を理解したうえで妥協を選んだ。

- ゲームから抽出した回転角そのものは正しく、それを忠実に適用した結果として接触が起きている。
- 接触の有無は骨の角度だけでなく**体型**で決まる。ゲーム内モデルと公式MMDモデルは腕の長さ・
  胴の太さ・胸の張り出しが違うため、同じ角度を与えても当たり方が変わる。
- したがって、めり込みを消すには**原作の角度からわざと外す**しかない。身体に関しては
  「1次情報の再現」と「破綻の解消」が両立しない。
- 武田さんの目的は作画資料としての1次情報の再現であるため、破綻側を許容する判断をした。
- 一方**外套・裾はゲームに曲線データが存在せず100%こちらの創作**なので、この制約は掛からない。
  布の破綻は直す対象として残る。この線引きが 2026-07-26 の作業範囲を決めている。

## 2026-07-26 レビューで判明した計画側の誤り

`/plan-gate` で作った計画（`plans/md-users-takedayousuke-llm-uploads-2026-foamy-beaver.md`）の
根拠に事実誤認があった。同じ誤解を繰り返さないために残す。

- **「外套が6.87倍に振れた」は外套の数値ではない。** `reports/h0167__ssr0101__SRC__run1-shape.json`
  の 6.87 は `Skirt_8_17`（スカート末端、元の長さ 0.00127＝メッシュ中央値 0.0042 の約1/3）の
  比であり、細い辺を割り算したときに出る既知の落とし穴と同種。外套(Pifeng)の実害は絶対量の
  `0.0461`（frame 664、`Pifeng_R022`、元 0.0320）に出ており、**このフレーム 664 は武田さんが
  目視で指摘した「650〜680フレーム付近」と一致する**。数値より目視の方が正しかった。
- **「動く本数を増やす」は外套には逆方向。** `reports/h0167__ssr0101__SRC__run1-bake.json` の
  ボーン名を分類すると、スカートは18列×9本で末端2本のみ動的（約22%）、外套は4〜5本の房が8本で
  末端2本が動的（40〜50%）。「全長でしなれない」が当てはまるのはスカートだけ。
  `bake_secondary.py` の冒頭には「チェーン全体を動的にしたら膨らむ現象が出たので末端だけにした」
  と明記されており、外套で本数を増やすとそれを呼び戻す。**外套は下げる、裾は上げる**が正しい向き。
- **設定を変える配線が通っていなかった。** `run_representative_batch.py` は `bake_secondary.py` を
  `--armature / --output / --report` の3引数だけで呼んでおり、布の設定を渡す経路が無かった。
- **試行は build をやり直す必要がない。** `runs/*-raw.blend` が88ファイル残っており、
  raw はリターゲット結果で布設定に依存しないため、bake からやり直せる。
- **「移動ゲイン 0.0 が腿貫通の直接原因」は誤り。移動ゲインは動かせない。** 2026-07-26 に
  `translation_gain` を 0.0→0.1 にして再ベイクしたところ、測定値も貫通量も**1ビットも変わらなかった**。
  調べると、スカートの移動キーは36本すべて作られているのに値が**全フレームちょうど 0.0**。
  公式MMDモデル側で布ボーンが移動禁止に設定されているため（`lock_location` 全軸 true、
  `mmd_bone.is_movable` false）、ポーズボーンの位置が動かず、シミュレーション由来の局所移動が
  常に0として採取される。さらにスカートの剛体追従constraintは **`COPY_ROTATION`（回転のみ）**で、
  Pifeng の `COPY_TRANSFORMS` とも違う。移動を有効にするには197本の布ボーンのロック解除と
  constraint 差し替え、つまり**公式モデルのリグ改造**が要る。計画が挙げた3つのてこのうち1本は
  実在しない。

## 「動きとしてありえるか」を測る基準(2026-07-26 新設)

既存ゲートは「メッシュが破れているか」しか見ておらず、動きの妥当性を測る仕組みが1つも無かった。
原作映像が無いため合格ラインを原理から決められないので、**武田さんが 2026-07-25 に実見して
承認した3件（H0157 / H0176 / H0705）と、2026-07-26 に指摘した1件（H0167/ssr0101）の間に線を引く**
方法で導出した。正本は `inputs/plausibility-gates.json`、測定は `tools/motion_plausibility.py`。

- 採用した6基準はいずれも承認済みと却下の差が2倍以上あるものだけ。差が数%のものは
  標本4件では偶然と区別できないため `rejected_metrics` に理由付きで落とした
  （例: `Pifeng.max_angular_speed` は 158.6 対 171.3 で 1.08倍）。
- **最も効いたのは「外套全体が 5度/フレームを超え続けた最長フレーム数」**。承認済み最大4に対し
  H0167 は34。その34フレームは **frame 655 から始まる**ため、武田さんの「650〜680フレーム付近」と
  測定値が同じ場所を指している。
- 現行34ランに適用すると、**落ちるのは H0167/ssr0101 の1件だけ**で、6基準すべてに引っかかる。
  結果は `reports/plausibility-gate-check.json`。
- **「減衰」は検証できなかった。** 身体が30フレーム以上止まる区間があるのは34ラン中16件だけで、
  基準の較正に使う参照4件にはいずれも存在しない。診断値としては出力するがゲートにしない。
- **貫通は合否基準にできない。** `tools/validate_penetration.py`（`retarget-fix-pilot` から複製し
  引数化。元は骨格名 ssr0101 固定・身体剛体33個ちょうどの前提で ssr0102 では動かなかった）で
  測ると、**承認済みの H0705 の方が却下の H0167 より悪い**（超過フレーム率 99.7% 対 34.8%、
  スカート対脚の最大めり込み 100.7mm 対 0.0mm）。武田さんは貫通を承認したのではなく後から
  「毎回貫通する」と指摘したので、これは合否ではなく**減らすべき目標値**として扱う。
  なおこの監査は剛体カプセルを測るもので、画面に見えるメッシュの貫通とは別物。

| ssr0101 | **49.9mm** | `P1-Cloth2-Metal`（金属）。次いで `P1-Cloth2-TopCloth-Bras` 39.6mm、`BodySkin` 39.1mm |
| ssr0102 | **41.0mm** | `TopBras`。次いで `BodySkin` 35.0mm、`SleeveLeisure` 9.2mm |

**両衣装とも歪んでおり、ssr0101 の方が大きい。** 原因は同じで、ブラ・紐・金具が胸ボーンと
`上半身2` にまたがってウェイトが乗っているところへ、公式MMDの胸物理を切ったまま
ゲーム由来の胸角度（`04_寝室04_動作` は左14.6度/右24.77度、最大は `06_寝室06_動作` の37.3度）を
直接与えているため。ssr0102 では `TopBras` / `Jewels` / `Chained` に布シミュレーションは
1本も掛かっておらず（物理が効くのは袖と尻尾だけ）、**布設定の調整では原理的に届かない**。

### 決定

武田さんが ssr0102 の A/B を実見し「やっぱ歪んでいた。デフォルトの方が資料価値が高いので
今後はこちらで行く」と判断した。**`Chest_L` / `Chest_R` のゲーム由来カーブを全17件から除去する**
（1アクションあたり8カーブ、17件で136カーブ・59,464キー）。胸以外のカーブ7,191本はハッシュ一致で不変。

- `tools/reset_chest_to_rest.py`（新規）がカーブ除去とポーズのrest復帰を行う。
- 成果物（各モデルで BEFORE/AFTER の対）:
  - `blends/helen-ssr0101-1-BEFORE-胸に原作の角度あり.blend` / `helen-ssr0101-2-AFTER-胸をデフォルトに戻した.blend`
  - `blends/helen-ssr0102-1-BEFORE-胸に原作の角度あり.blend` / `helen-ssr0102-2-AFTER-胸をデフォルトに戻した.blend`
- これは**胸に関して原作再現を捨てる**決定である。2026-07-23 に `blocked` とした
  「原作の胸変形機構の再現」は、再現しようとしていた対象そのものを今後の成果物から外すことで決着する。
  身体の他の部位（腕・脚のめり込み）は引き続き原作忠実のまま妥協する。

## 目に見える貫通を測る手段(2026-07-26 新設)

`tools/validate_penetration.py`（剛体カプセル）はスカートの貫通に対して 0.0mm を返す。
静止姿勢での重なりを引き算する作りで、スカートは静止時点で既に脚を包んでいるため。
つまり**武田さんが見ている貫通に対応する数値が存在しなかった**。

`tools/validate_mesh_penetration.py`（新規）は、フレームごとに `BodySkin` の面と各衣装材質の面で
BVH の交差判定を行い、**実際に面が交差している組数**を数える。61フレーム抽出で約20秒。

初回測定（`04_寝室04_動作`）:

| ssr0101 | 組数 | | ssr0102 | 組数 |
| --- | ---: | --- | --- | ---: |
| `P1-Cloth-Skirt` | 537 | | `Sleeve` | 1290 |
| `P1-Cloth2-TopCloth-Bras` | 283 | | `TopBras` | 224 |
| `P1-Cloth-Underwear` | 217 | | `Veil` | 204 |

初版は全材質で出現率100%になった。手袋や靴下のような**密着が設計どおりの部位**も交差として
数えていたため。**静止姿勢での交差数を引き算する**ように直し、「動きによって新たに生じた交差」
（`max_added_pairs`）を主指標にした。これで手袋等は相殺され、実際の破綻だけが残る。

## 貫通への対処と、到達した限界(2026-07-26)

### 原因はスカートが移動できないこと

`bake_secondary.py` に、布グループごとに移動を有効化する処理を入れた。スカートの
`mmd_tools_rigid_track` は **`COPY_ROTATION`（回転しか返さない）**で、`translation_gain` を
上げても局所移動が常に0のまま届かなかった。移動を要求されたグループについて
`COPY_TRANSFORMS` へ差し替え、`lock_location` を解除する（ssr0101 のスカート155本が対象）。

### 効果（成果物どうしの比較・動きで増えた交差組数）

| クリップ | 部位 | 前 | 後 |
| --- | --- | ---: | ---: |
| `04_寝室04_動作` | スカート | 33 | **20** |
| `06_寝室06_動作` | スカート | 521 | **468** |
| `06_寝室06_動作` | 外套 | 496 | **460** |

**減ったが解決ではない。** 脚の動きが大きい `06` では約1割。

### 動く本数を増やす方向は3回とも失敗した

スカートは1列9本のうち動くのが末端2本のみで、全長で曲がって脚をよけられない。回転を抑えた
状態なら増やせるかを試したが、結果は逆だった。

| 設定 | スカートの交差 | 外套の交差 | 揺れの基準 |
| --- | ---: | ---: | --- |
| 移動なし（従来） | 521 | 496 | 通過 |
| **移動あり・末端2本（採用）** | **468** | **460** | 通過 |
| 移動あり・末端4本 | 758 | 400 | 不合格（裾の連続6・ピーク70.9・入力超過104.8） |
| 移動あり・末端6本 | 635 | 500 | 不合格（裾の連続27・ピーク86.0・入力超過121.6） |

2026-07-26 の t3（末端4本・移動なし）を含めて**3回とも悪化**しており、
`bake_secondary.py` 冒頭の「チェーン全体を動的にすると膨らむ」という記述と一致する。
**末端2本が上限**と結論する。

### ssr0102 の布は動かせない

ssr0102 の `Cloth`（袖・尻尾）に移動を許すと、肘まわりでメッシュが裂けて機械ゲートが停止した
（移動1.0で辺の伸び4.35倍・絶対伸び0.0456、移動0.25でも9.93倍）。**ssr0102 は布を変更しない。**
成果物の差はファイル名に出してある（ssr0101 は「胸デフォルト-布調整」、ssr0102 は「胸デフォルト」）。

### 残る限界

この作りは、スカートを「9本の骨の鎖＋末端2本だけ剛体シミュレーション」で表現している。
公式MMDモデルの想定はMMD自身のソルバと限られた動きであり、ゲームから持ってきた任意の動きに
対して布が脚をよけきれない。**骨の鎖ではなくスカートのメッシュ自体に布シミュレーションを掛け、
身体と衝突させる**方式へ替えない限り、この残りは消えない見込み。これは別のパイプラインになる。

## ssr0102 には外套も裾も無い(2026-07-26 判明)

ssr0102 の布ボーンは `Cloth` 27本のみで、`Skirt` / `Pifeng` は1本も無い。
「H0167 の布の伸び率が SSR0102 では 1.14 で突出しない」のはこのため。
外套・裾の調整は ssr0101 にしか掛からない。
