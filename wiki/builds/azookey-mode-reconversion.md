# azooKey 打ち間違いモード復元機能(かな連打/英数連打)— 中止・元に戻し済み

## 現在の統合見解

日本語/英語モードを間違えて打った文字列を、かなキー2回押し/英数キー2回押しで機械的に直す機能を
azooKey-Desktop の自前ビルドに実装しようとしたプロジェクト。

**2026-07-10、実機で機能しないまま中止し、プロジェクト開始前の状態(元の azooKey v1.0)へ復元済み。**
コードの実装自体は完了・単体テストも通過したが、実機の macOS 入力メソッド機構(IMKit・入力ソース登録)の
段階で複数回つまずき、最終的に「実機で動く成果物」には至らなかった。

このページは今後の再挑戦のための記録として残す(status: superseded — 今回の実装方針そのものでは進めない)。

## 技術的な原因まとめ(再挑戦時に必読)

- **確定した実装バグ**: `azooKeyMacInputController.swift` の `eventGeneration` は、かな/英数キー自体の
  押下でも増分されていた。ダブルタップは2回のキーイベントにまたがるため、
  「直前の1イベントで確定した内容のみ復元」という判定が2回目の押下時点で必ず不成立になる。
  修正版(102/104キーでは世代を進めない)はビルド・単体テストは通過したが、**実機での再検証は未達**
  (修正直後にアプリ配置移動で入力自体が壊れたため)。
- **`.insertText` 経路の裏取り**: 英語(Roman)モードの1文字ずつの入力も `.insertWithoutMarkedText` →
  `.insertText` を経由することをコードで確認済み。「英語モード打鍵が記録されない」という当初の疑いは誤りだった。
- **macOS 側の制約(未解決)**:
  - `imklaunchagent` はアプリの配置パスに敏感で、`/Library/Input Methods/` 以外へ移すと
    既存の登録が解決できなくなることがある(再起動でも治らないケースがあった)。
  - 入力メソッド本体(親)の有効化は `TISEnableInputSource` の呼び出しだけでは定着しないことがあり、
    「システム設定」の GUI 操作が必要な場合がある(原因未特定)。
