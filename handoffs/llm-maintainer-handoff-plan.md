## フェーズ構成(各フェーズ末 = 明示的な承認待ち停止点。承認前に次フェーズへ進まない)

### Phase 1 — 正本移管 + 統合候補マップ

- **正本移管(承認後の最初の作業)**: 承認済みのこの計画を
  `wiki/builds/llm-maintainer-handoff-plan.md`(type: build)へ保存し、log へ記録
  (op: `ingest`)。**以後はそのファイルだけを計画の正本**とし、`~/.claude/plans/` の
  作業版と `llm-uploads/` の写しは揮発物として扱う(後継 AI は wiki 内の正本だけ読めばよい)。
- **冒頭で再計測**: 全 md 数 / source / concept / analyses / status なしページ数 /
  index.md 行数。結果と計測日をマップに記録し、以後の判断はこの値だけを使う。
  あわせて**対象 7 講座(Ye Jji / Nekojira / chan / ひづるめ / hide / マーセ / 佐々)と
  各講座の代表 source ページを記録し、Phase 2 の調査対象として固定**する。
- **調査の段階化(範囲爆発の防止)**:
  - 全候補: index.md + frontmatter + slug の機械走査で「関連がありそうな講座」を特定する
    まで(この段階で講座本文の調査はしない)。
  - 高優先度候補・パイロット推奨候補のみ: 関連する実ページ本文を重点確認してから順位を
    確定し、根拠リンク(`[[slug]]`)をマップに記録。本文未確認の候補は「要調査」と明記し、
    高優先度として断定しない(仮説と本文確認済みを区別)。
  - 全 7 講座の正式調査(講座調査表)は **Phase 2 の選定テーマに対してのみ**行う。
- 各テーマに書く内容: 関連ページ列挙 / 関連がありそうな講座 / 矛盾候補 /
  統合形態の提案(既存 concept 拡張 or 新規ページ)/ 優先度とその根拠。
- Fable は**パイロット推奨テーマ 1 件と推奨理由を明示**する。
- 出力: `wiki/analyses/synthesis-backlog-2026-06.md`
  (type: analysis、**evidence_level: ai-hypothesis 固定** — AI の優先順位判断を含むため)
- **停止点 — 武田さんの判断項目(この 3 つだけ)**:
  1. 優先順位が「今後知りたいこと・使いたいこと」に合っているか
  2. 模範解答として作るテーマをどれにするか
  3. ページ形式(既存 concept 拡張 / 新規ページ)の推奨を採用するか

### Phase 2 — 模範統合ページ(模範解答)

- 選ばれた 1 テーマで、推奨構造(現在の統合見解 / 根拠 / 矛盾・未確定 / 変遷)の統合ページを
  1 件、**新規作成または既存 concept の更新**(Phase 1 の決定に従う)。固定した全 7 講座を
  調査した上で、根拠には関係がある講座の発言だけを使う(無関係な講座を無理に結び付けない)。
  帰属は「講師が該当講座でそう述べた」形式。frontmatter 完備。
- **講座調査表を必須で含める**(今後の統合作業の標準形式として指南書にも載せる):
  - 列: 講座 / 確認したページ(`[[リンク]]`)/ 関連性(`直接関連`・`間接関連`・`関連なし`・
    `判断保留`)/ 根拠への採用 / 理由
  - 固定した 7 講座すべてを 1 行ずつ記録。`関連なし` も調査済みの結果として残す。
    `判断保留` は不足資料・判断できない理由を明記。自己申告だけで調査済み扱いしない。
- 触った関連ページにのみ backlink・frontmatter 追補(一括変換しない)。
- 出典リンク・帰属・調査表・必須 frontmatter の正しさは **Fable 側で検証してから**
  レビュー依頼を出す。
- **停止点 — 武田さんの判断項目(この 3 つだけ)**:
  1. 統合見解が実際の質問・制作判断に役立つか
  2. 講師間の共通点・違い・未確定事項の分け方が妥当か
  3. このページを今後の模範解答として採用してよいか
