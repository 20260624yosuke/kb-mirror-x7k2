# 引き継ぎ資料：LLM の書き方ルールを直す

> [!note] 役目終了(2026-08-02)
> この引き継ぎで求めたルールは `CLAUDE.md` / `AGENTS.md` の
> 「3. 説明の質 — 意味と「どう変わるか」を省略しない」へ取り込まれた。
> **以後の正本はそちら。** このページは経緯の記録として残す。
> 下の枠内のコピペ用プロンプトは実行済みなので、もう使わない。

この下の枠の中を**まるごとコピペ**すれば、別プロジェクトで `plan-gate` の計画が始まります。
枠の外（この段落）は読まなくて構いません。

/plan-gate

LLM Wiki の運用ルールを直したい。特定のプロジェクトの話ではなく、Wiki 全体の話。

## 何が起きたか（実例）

2026-08-01、ドルフロ2の MMD モデルを Blender に取り込んだライブラリ
（正本: wiki/builds/mmd-library-blender-import.md）で問題が出た。

私（武田）が Blender でモデルを開いたら、参考にしていた動画と質感が明らかに違った。
調べたら、LLM がライブラリを作ったときに「見やすさを優先する」判断をして、
原作の質感を作っている情報を意図的に落としていた。

- 顔の陰の付き方を決めている設定を捨てていた
- 服の生地の凹凸の情報（8枚）を一度も使っていなかった
- 材質ごとの光り方の情報（6枚）を一度も使っていなかった
- 陰の濃淡が出ないよう照明を平坦にしていた

判断そのものは wiki に記録してあった。技術的な理由も書いてあった。
**でも「それによって画面でどう見えるか」が一言も書いていなかった。**
だから私は、自分が何を手放したのか分からないまま「見やすさ優先でいい」と答えていた。

さらに、そのとき出された二択は「試行回数を減らす」対「資料に使えればいい」だった。
後者を選ぶと原作の見た目を失う、とはどこにも書いていなかった。

## 何がボトルネックか（私の見立て）

1. LLM の報告は「自分が何をしたか」で止まっている。
   「その結果、画面や成果物でどう見えるか」に翻訳されていない。
   CLAUDE.md には専門用語を日本語に訳す規則はあるが、
   結果を見え方に訳す規則が無い。

2. 二択を出すとき、選ばなかった側で何を失うかが書かれていない。
   代償が見えない二択は、選ばせたことにならない。

3. 外から取り込んだ素材のうち「使わなかったもの」がどこにも残らない。
   配布物に入っているのに未使用のデータがあっても、私には気づきようがない。

4. 加えて、専門用語が多いと、説明されているのに成果物のイメージが湧かない。
   結果として、書いてあっても私が理解できず、判断できない。

## やりたいこと

上の 1〜4 が、私が毎回プロンプトで注意しなくても自動で効くようにしたい。
毎回ケアする方式は負荷が高いので採らない。

## 候補（これで確定ではない。検討してほしい）

- CLAUDE.md の「3. 説明の質」に追記する
  - 何かを捨てる／使わないと決めたら、必ず「そのせいでどう見えるか」を書く
  - 捨てる判断は3点セット（何を捨てたか／どう見えるか／戻せるか）
  - 二択を出すときは、選ばなかった側で失うものを各選択肢に書く
- build ページに「使わなかったもの一覧」の節を必須化する
- Codex 用の AGENTS.md にも同じものを入れる
- 記憶（メモリ）にも保存する

## 制約・希望

- ルールは増やしすぎない。CLAUDE.md は既に長い。
  新しい規則を足すより、既存の規則の順番や書き方を直して済むならそちらがいい。
- 私は非エンジニア。専門用語で説明されても判断できない。
- 既存ページの一括書き換えはしない（CLAUDE.md の既存方針）。

## 別途ある宿題（この計画に含めるかは判断してほしい）

その画像は実際にディスク上に存在していた。記録が誤っている可能性がある。数え直して訂正したい。
