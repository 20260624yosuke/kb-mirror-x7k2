# Claude 引き継ぎ: アクティブなディスプレイの解像度を擬似的に上げたい件

## 依頼の背景

ユーザーは「今アクティブになっているディスプレイの解像度を、擬似的に上げたい」という話を、過去に LLM とこのフォルダで話した記憶がある。

ただし Codex でこのフォルダ内を確認した限り、`BetterDisplay`、`HiDPI`、`SwitchResX`、`RDM`、`仮想解像度`、`擬似解像度`、`疑似解像度`、`アクティブなディスプレイ` などの直接記録は見つからなかった。

## このフォルダで確認できた近い正本

関連しそうな正本は以下。

- `wiki/analyses/desk-display-setup-2026-06.md`
- `index.md` の `[[desk-display-setup-2026-06]]`
- `log.md` の `2026-06-05 query | デスク環境（液タブ + サブモニター上下スタック）アップデートの設計詰め（grill-build）`

この正本に残っている内容は、「現在のモニターをソフトウェア的に擬似高解像度化する」話ではなく、液タブ + サブモニター環境そのものの改善相談。

## 記録されている環境

- 液タブ: Huion Kamvas Pro 24
- サブモニター: HP M27f と推定。27型 FHD。VESA 非対応をアダプタで無理やりアーム化している可能性あり。
- PC: M1 Mac mini
- 現在の表示枚数: Kamvas + M27f の 2枚
- M1 Mac mini は標準では外部表示が最大2枚なので、3枚化は DisplayLink または Mac 買い替えが必要、という整理だった。

## 前回の結論として残っていること

`desk-display-setup-2026-06.md` では、問題は以下のように整理されていた。

- 問題A: サブモニターの位置・角度・水平が決まらず見にくい。
- 問題B: 3枚ディスプレイ運用。これは問題Aとは別物。

推奨は、HP M27f を VESA ネイティブの 27型 1440p IPS モニターへ買い替え、既存アームを流用すること。

理由は、現 M27f が 27型 FHD で粗く、アーム取り付けも非 VESA アダプタ依存で角度の基準面が怪しいため。物理解像度も設置安定性も、1440p VESA ネイティブ機への買い替えでまとめて改善できる、という判断だった。

## 今回 Claude に相談したいこと

今回の焦点は、過去正本に残っている「買い替え」ではなく、ユーザーが言っている以下の話を再調査・再設計すること。

> 今アクティブになっているディスプレイの解像度を、擬似的に上げたい。

ここでいう「擬似的に上げる」は、おそらく以下のどれかを意味する可能性がある。

1. macOS の表示スケーリングで、見かけ上の作業領域を広くする。
2. BetterDisplay などで HiDPI（高密度表示モード。内部的に高解像度で描いて縮小表示するモード）や仮想解像度を追加する。
3. 今マウスやキーボード操作の対象になっているディスプレイだけを検出し、そのディスプレイの解像度設定をショートカットで切り替える。
4. 単に「サブモニターの表示をもっと細かくしたい」だけで、アクティブ判定や自動切替までは不要。

## Claude 側で最初に確認してほしいこと

ユーザーに抽象的な目的整理をさせず、まず実環境から確認すること。

1. macOS が現在認識しているディスプレイ一覧を確認する。
   - 例: `system_profiler SPDisplaysDataType`
   - 可能なら `displayplacer list`、`BetterDisplay`、`SwitchResX` など既存インストールの有無も確認。
2. 現在アクティブなディスプレイを、CLI（コマンドライン操作）で安定して特定できるか確認する。
   - マウス位置ベースなのか、前面ウィンドウ位置ベースなのかで挙動が変わる。
   - ここは設計判断になるので、実装前にユーザーへ違いを説明して確認すること。
3. 目的が「手動で一度だけ設定を増やしたい」のか、「ショートカットで現在の画面だけ切り替えたい」のかを分ける。

## 重要な注意

- まだこのフォルダ内には、BetterDisplay / HiDPI / SwitchResX で実際に成功した記録はない。
- したがって「前に決まっていた」として進めないこと。
- GUI（画面を直接操作する作業）が必要な場合は、AGENTS.md の規則に従い、手動確認・LLM 自動操作・短い共同確認の選択肢を先に出すこと。
- 実機の画面設定変更は、表示が見えなくなる、文字が小さくなりすぎる、戻し方が分からなくなる可能性があるため、変更前に復旧手段を決めること。
- Wiki の構造変更、ページ新設、正式な build 化は、方針としてユーザー承認が必要。
